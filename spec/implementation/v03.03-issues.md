# v03.03 — GitHub Issues

Issues for phase **v03.03 — Chat & the Observer role** (version **v03 — Web UI (Player &
Observer)**), derived from the per-phase Tasks in [roadmap.md](../roadmap.md) (§v03.03) and the
contracts in [architecture.md](../architecture.md) (§6.2 WebSocket protocol, §8 Web UI
Architecture) plus [web_ui_specification.md](../web_ui_specification.md) (§4.4, §5, §11). This
file is scoped to a single phase; IDs continue from the previous phase (ARENA-102 →
**ARENA-103…104**). **This is the v03 release gate.**

Chat becomes live (post + render, sender-labelled) and the Observer role is hardened: a seat-less
viewer sees the board and chat update live but can never post or claim a seat.

**Reconciliation note (Step 0.5):** v03.02's own reconciliation flagged that
`web_ui_specification.md` §4.4 claims `chat_message.sender` is the seat symbol (`"X"`/`"O"`), but
the real, tested server behavior (`server/main.py:159`, pinned by
`tests/test_ws_chat.py::test_chat_broadcasts_to_every_connection_including_sender`, unchanged
since v01.04) sends `participant.player_name` — e.g. `"Alice"`. That gap is *in scope here*
(chat is this phase's own work), so ARENA-103 implements self/other styling by comparing `sender`
against the client's own **`state.myPlayerName`**, not `mySymbol`, and corrects
`web_ui_specification.md` §4.4 to describe the real contract rather than carrying the drift
forward. `architecture.md` §6.2 itself only ever said `sender, message` with no symbol/name claim,
so nothing there needs to change — this is a correction to the UI spec, not a seam change.

## v03.03 — Chat & the Observer role

### ARENA-103 — Chat panel: post, render, self/other styling, auto-scroll

**Description:**
Wires the chat form to send `chat` actions and renders every `chat_message` the server broadcasts
(including the sender's own, echoed back — never posted optimistically, matching the board's
non-optimistic pattern from v03.02). Touches: `web/app.js`, `spec/web_ui_specification.md`
(correcting §4.4's sender claim per this file's reconciliation note).

**What needs to be done:**
- Chat form submit → `{"action":"chat","payload":{"message":<text>}}`; guard against an empty
  message and a socket that isn't `OPEN` (same discipline as `handleCellClick`'s guards,
  web_ui_specification.md §6.3). Clear the input on send; never render the sent message directly —
  wait for the server's own broadcast, same non-optimistic principle as the board.
- `renderChat({sender, message})`: appends a message bubble to `#messages`, auto-scrolling so the
  newest is always visible. **Self vs other is derived by comparing `sender` to
  `state.myPlayerName`** (the reconciled contract -- see this file's note above), not `mySymbol`:
  a match renders left/blue (`self`/`agent-x`-style per §4.4's class table), anything else renders
  right/pink (`other`/`agent-o`-style).
- System notices (e.g. "Match started", a `game_over` line) render centered/dashed per §4.4's
  `system` row — at minimum, post one on `joined` ("Match started") and one on `game_over`
  ("Game over — `<result>`"), reusing the same `renderChat`-adjacent rendering path rather than a
  parallel one.
- Update the chat header's participant count (`#chat-count`) — a simple presentational count is
  enough for v03.03 (exact live participant tracking isn't pushed by any event; don't invent a
  server round-trip to get it exactly right).
- Correct `web_ui_specification.md` §4.4: replace the "sender is the seat symbol" claim with the
  real contract (`sender` is the participant's `player_name`; self/other is derived from
  `myPlayerName`).

**Dependencies:** None

**Expected result:**
Typing a message and pressing Send delivers it to every connection in the match, including your
own, rendered as a labelled bubble; a match started/ended posts a system notice.

**Acceptance criteria:**
- [ ] Chat form sends a `chat` action with the typed message and clears the input.
- [ ] Empty messages and a non-`OPEN` socket are guarded (no send).
- [ ] `chat_message` renders for every recipient, including the sender (no optimistic render).
- [ ] Self vs other styling is derived from `state.myPlayerName`, not `mySymbol`.
- [ ] `#messages` auto-scrolls to the newest message on append.
- [ ] System notices post on `joined` and `game_over`.
- [ ] `web_ui_specification.md` §4.4 is corrected to describe the real `sender` contract.
- [ ] **Integration test:** static assertions on the served `app.js` for the guard clauses, the
      `myPlayerName`-based self/other derivation, and the system-notice call sites.
- [ ] Ties to phase DoD: "players exchange chat live."

### ARENA-104 — Observer role hardening: chat suppression + release-gate tests

**Description:**
Closes the v03 release gate: an Observer's chat input is suppressed regardless of connection
state (not just disabled-until-connected, like a Player's), and the DoD's server-side refusal of a
spectator's move is explicitly covered by a test at this level (not just inherited from v01
coverage). Touches: `web/app.js`, `tests/`.

**What needs to be done:**
- Gate chat input/send by role, not just connection state: `setConnected(true)` currently enables
  chat unconditionally for anyone connected — an Observer (`state.mySymbol === null`) must stay
  disabled even once `OPEN`. Re-check role wherever connection state toggles chat enablement.
- Confirm (already true from v03.02, verify with a test at this phase's level rather than assuming
  it silently holds) that an Observer's board is never interactive regardless of `current_turn`,
  and `initPlayerCards(null)` doesn't crash — these are v03.02 behaviors this phase's DoD restates
  as release-gate requirements, so they get their own explicit coverage here rather than trusting
  a different phase's tests to keep covering a DoD line that's now this phase's own.
- **Release-gate check:** a spectator's `submit_move`, if one were ever sent, is refused
  server-side (`symbol is None` in `server/main.py`'s WS handler) — this is pre-existing v01
  behavior; add an integration test at the real-server level confirming it explicitly, since the
  DoD names it directly as a v03.03 acceptance line.
- Confirm `spectateMatch`/`observe()` sends a genuinely distinct action from Host/Join: `spectator`
  is `true` only for Observe, `false` for both Host and Join (already implemented in ARENA-099;
  add the explicit regression test this phase's DoD calls for rather than relying on it being
  implied by other coverage).

**Dependencies:** ARENA-103

**Expected result:**
An Observer sees the board and chat update live for the whole match, can never type a message or
click a cell, and never holds a seat — verified end to end, not just by inspection.

**Acceptance criteria:**
- [ ] Chat input/send stay disabled for an Observer even while the socket is `OPEN`.
- [ ] Observer board interactivity and `initPlayerCards(null)` safety have explicit test coverage
      at this phase's level.
- [ ] **Integration test (real server):** a spectator's `submit_move` is refused, confirming the
      DoD's explicit release-gate line.
- [ ] **Integration test:** the served `app.js` sends `spectator:true` only from the Observe path,
      `false` from Host and Join.
- [ ] Ties to phase DoD (v03 release gate): "clicking Observe on an agent-vs-agent match shows the
      board + chat updating live without claiming a seat; a spectator's submit_move (if forced) is
      refused server-side."
