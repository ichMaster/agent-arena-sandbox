## Finding 1 — a blanket except hid our own bugs

A `TypeError` or `AttributeError` raised inside the agent was swallowed by the retry loop and
counted as a failed model attempt. The agent would then play a random legal move, look merely
unlucky with the model, and the real defect would never surface — in a long agent-vs-agent run
that is indistinguishable from a flaky model.

**Fixed:** the net is now the four failures a model call genuinely produces — `LLMResponseError`,
`ValidationError`, `httpx.HTTPError`, `APIError`. A regression test asserts an `AttributeError`
from our own code propagates rather than being retried away. Two existing tests that raised a bare
`RuntimeError` now raise realistic model failures; **the implementation was not widened to keep
them passing** — their premise was wrong.

**Verification:** 391 passed, mypy strict clean, ruff clean.

## What's solid
- **The random-legal fallback**, which is what stops a hallucinating model stalling a match forever.
- **The turn is derived from state**, so the same check that decides "is it my turn" also stops the
  agent acting on the terminal update carrying `current_turn: null`.
- **Line-buffered stdout**, tested — a redirected log flushes as the game plays.
- **Every test mocks the LLMClient.** Zero paid calls.
