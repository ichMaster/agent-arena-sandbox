## Findings

### #1 🟡 No reconnect/backoff (LOW) — deferred
If the WS connection drops mid-match, `run_agent` simply exits (`except websockets.ConnectionClosed:
pass`) — there's no retry. Real, but this is precisely v05.01's stated purpose (resilience &
reconnection), and this version's own scope notes already say so explicitly. Not new scope creep to
defer; confirming the deferral rather than silently dropping it.

### #2 🟡 `.env` path is CWD-relative (LOW) — deferred
`load_environment()` calls `load_dotenv()` with no explicit path by default, so `python
agent/agent.py …` only picks up `./.env` relative to wherever the command was launched from — running
it from a different directory silently misses the file (then fails clearly via `load_api_key`, at
least, so it's not a silent wrong-key bug — just a discoverability nuisance). Homed to v05.03 (README/
run-mode docs should say "run from the repo root").

## What's solid
`choose_move`'s broad `except Exception` around the model call is a deliberate design choice, not an
oversight — any model failure must count as a failed attempt rather than crashing the match, exactly
matching the roadmap's "an illegal model move is retried then falls back to a legal one" DoD wording
extended to *any* model failure, not just illegal moves. `AgentSession.on_event` is fully
order-tolerant (a pre-`joined` event simply finds `self.symbol is None` and does nothing — no crash),
which is what made the integration test's cross-task ordering safe without extra synchronization.
`join_match`'s injectable `httpx.AsyncClient` keeps tests off the real network entirely. Zero paid
calls anywhere in the suite.

## Architecture impact
None — the agent *consumes* the §6.2 protocol and §4.2 seam as already documented; no contract changed.
