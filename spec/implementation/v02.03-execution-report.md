### ARENA-095: chat + submit_move, memory recording, game_over
**Status:** completed · **Commit:** 976ebb6
**Validation:** [x] tests (134 full suite) · [x] mypy --strict
**Found and fixed during validation:** a genuine production race in `server/main.py`'s `websocket_endpoint` -- the newly-connected socket was registered with `ConnectionManager` (broadcast-eligible) *before* its own `joined` event was sent, so a concurrent broadcast (e.g. the opponent's opening move) could arrive first and violate architecture.md §6.2 ("joined is always the first message a client receives"). Fixed by sending `joined` first, then registering. Also hardened the `live_server` fixture: disposes the shared SQLAlchemy engine per use (an abrupt teardown was corrupting the pool for a later, unrelated test with `MissingGreenlet`), and polls a real `/api/v1/health` request before yielding the URL (`server.started` only means the TCP listener is bound, not that the ASGI lifespan/`init_models()` finished). This exposed a test-design race in the new live-game integration test itself (the agent reacting to `joined` and completing its entire first turn before the opponent's socket was even registered) -- fixed by deferring when the agent starts draining its event queue until after the opponent is connected and listening.
