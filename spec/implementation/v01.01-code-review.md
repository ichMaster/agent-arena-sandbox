## Findings

### #1 🟡 No player-value validation (LOW) — accepted
`TicTacToe.apply_move("garbage", 0)` marks the board with `"garbage"` rather than rejecting it.
**Failure scenario in isolation:** calling the engine directly with an arbitrary player string lets a
"garbage" 3-in-a-row be reported as a win for `"garbage"`. **Why it's not a real risk:** the engine is
transport-opaque by design (architecture.md §4.1) — legality of the *move* is its job; legality of the
*player* is enforced upstream (later phases: `Repository.assign_symbol` only ever returns `"X"`/`"O"`,
and the server only calls `apply_move` with that value). No later phase's design routes an unchecked
player string into this call. Kept as-is; would be revisited only if a future game module needed
per-player validation the caller couldn't guarantee.

## What's solid
