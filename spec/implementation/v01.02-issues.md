This phase adds the durable substrate: an async SQLAlchemy engine over `sqlite+aiosqlite`, the four
ORM tables (`matches`, `participants`, `moves`, `chat_messages`) with `UNIQUE(match_id, symbol)`,
and the **`Repository`** — the single access seam for all durable state. Live game state is
**reconstructed by replaying the move log** through a fresh `TicTacToe`, so `GameInterface` gains no
serialize step. It builds directly on the v01.01 engine and is the store the REST/WS layers (v01.03–04)
will drive. No model is involved.

## v01.02 — Persistence layer (SQLite)

### ARENA-OPUS-SONNET-004 — SQLite engine, ORM models & schema init

**Description:**
The persistence gate — `server/database.py` (async SQLAlchemy engine, session maker, FK PRAGMA,
`init_models()`) and `server/models.py` (the four ORM tables per §5.1 with FKs and the seat
uniqueness constraint). Touches: `server/database.py`, `server/models.py`, `tests/`.

**What needs to be done:**
- `server/database.py`: an async engine over a **config-driven URL** (default `sqlite+aiosqlite:///./arena.db`), `async_sessionmaker(expire_on_commit=False)`, a connect-time **`PRAGMA foreign_keys=ON`** listener (on the engine's sync connection), a declarative `Base`, and `async def init_models()` running `create_all`.
- Provide a way to build the engine/sessionmaker against a **throwaway DB** (temp file, or `:memory:` with a shared/static pool) so tests never touch `./arena.db`.
- `server/models.py`: SQLAlchemy 2.0 typed ORM (`Mapped`/`mapped_column`) for `Match`, `Participant`, `Move`, `ChatMessage` per §5.1 — PKs, `match_id` FKs, columns/types, `created_at` defaults, and **`UNIQUE(match_id, symbol)`** on `participants`.

**Dependencies:** None (v01.02 depends on v01.01, already released).

**Expected result:**
`init_models()` creates the four correctly-shaped tables in a fresh SQLite DB with FK enforcement on and the seat-uniqueness constraint in place.

**Acceptance criteria:**
- [ ] `server/database.py` builds an async engine + `async_sessionmaker(expire_on_commit=False)`; a fresh connection reports `PRAGMA foreign_keys = 1`; `init_models()` creates the schema against a throwaway DB.
- [ ] `server/models.py` defines the four tables per §5.1 with `match_id` FKs and `UNIQUE(match_id, symbol)`.
- [ ] **Contract test:** the four table shapes — table names, key columns, FKs, and the seat-uniqueness constraint — are pinned (roadmap §v01.02 Tests). *(Schema is documented in §5.1; implemented as-is — no architecture change.)*
- [ ] **Unit test:** against a **throwaway SQLite DB** (`:memory:`/temp, `foreign_keys=ON`) — `init_models` creates all four tables; a duplicate `(match_id, symbol)` insert raises; an FK violation (unknown `match_id`) is rejected. No LLM, no paid call.
- [ ] mypy (strict) clean on `server/database.py` and `server/models.py`.
- [ ] Ties to DoD: a durable schema that survives restart and enforces seat uniqueness at the DB.

### ARENA-OPUS-SONNET-005 — Repository: matches / participants / moves / chat CRUD

**Description:**
`server/repository.py` — the single access seam for durable state (§5.1). Implements the core
create/read/append methods over an async session; no ad-hoc SQL escapes the Repository. Touches:
`server/repository.py`, `tests/`.

**What needs to be done:**
- `Repository` (async, over one `AsyncSession`): `create_match(match_id, game_type="tictactoe")`, `get_match(match_id) -> Match | None`, `add_participant(token, match_id, name, is_spectator)`, `log_move(match_id, symbol, move)`, `log_chat(match_id, sender, message)`.
- Persist the **opaque `move` payload as-is** (the game module owns interpretation; the store never parses it).
- Strict typing; all methods `async`; reads return ORM objects usable after commit (`expire_on_commit=False`).

**Dependencies:** ARENA-OPUS-SONNET-004

**Expected result:**
Matches, participants, moves, and chat round-trip through the Repository and persist to SQLite.

**Acceptance criteria:**
- [ ] The five methods persist and read back correctly via the Repository (no handler-level SQL).
- [ ] **Unit/integration test** (throwaway DB): round-trip each table; `get_match` returns `None` for an unknown id; ordered `moves`/`chat` return in insertion order; an FK violation (participant/move for a missing match) is rejected. No paid call.
- [ ] Persistence **survives a fresh engine/session** pointed at the same DB file (restart simulation) for a temp-file DB.
- [ ] mypy (strict) clean on `server/repository.py`.
- [ ] Ties to DoD: matches/participants/moves/chat persist to SQLite and survive a process restart.

### ARENA-OPUS-SONNET-006 — Seat assignment (`assign_symbol` / `release_seat`, §5.2)

**Description:**
The token-keyed seat rule at the Repository layer (§5.2): `assign_symbol` (write-through) and
`release_seat`. Implements the documented §5.2 algorithm; the REST/token wiring, `auth.py`, and the
exhaustive by-token identity semantics land in v01.03. Touches: `server/repository.py`, `tests/`.

**What needs to be done:**
- `assign_symbol(match_id, token) -> str | None` per §5.2: participant `is_spectator` → `None`; already-seated → return the existing symbol (idempotent reconnect); two seats already taken → `None`; otherwise assign the first free symbol (`X` then `O`) and persist it — `UNIQUE(match_id, symbol)` guards a race.
- `release_seat(match_id, token) -> None`: clear the participant's symbol so a reconnect can reclaim it.
- Keep it a thin **write-through** over the `participants` row — no in-memory seat state.

**Dependencies:** ARENA-OPUS-SONNET-005

**Expected result:**
Two distinct tokens get `X` and `O`, a third gets `None`, a spectator never gets a seat, and a re-call for a seated token is idempotent.

**Acceptance criteria:**
- [ ] `assign_symbol` implements the §5.2 rule (spectator → `None`, idempotent reconnect, third → `None`, first-free otherwise); `release_seat` frees the seat.
- [ ] **Contract/unit test** pinning the §5.2 seat behavior at the Repository level: first two tokens → `X`/`O`, third → `None`, spectator → `None`, re-call for a seated token returns the same symbol; after `release_seat` a new token reclaims the freed symbol; the DB `UNIQUE(match_id, symbol)` blocks a duplicate. Throwaway DB, no paid call. *(§5.2 implemented as documented — no architecture change; v01.03 adds the token/REST identity coverage, incl. name-collision-by-token.)*
- [ ] mypy (strict) clean on the seat methods.
- [ ] Ties to DoD: a second seat for the same symbol is rejected by the DB.

### ARENA-OPUS-SONNET-007 — Game reconstruction by move-log replay + `current_turn`

**Description:**
`reconstruct_game` and `current_turn` on the Repository (§5.1) — rebuild live state by replaying the
ordered move log through a fresh `TicTacToe`, keeping `GameInterface` free of any serialize step.
Touches: `server/repository.py`, `tests/`.

**What needs to be done:**
- `reconstruct_game(match_id) -> GameInterface`: load the match's `moves` in order and replay each through a fresh `TicTacToe` via `apply_move`, returning the live game.
- `current_turn(match_id) -> str | None`: derive from move-count parity (`X` on an even count, `O` on odd) and return **`None` once `is_game_over()` is truthy**.
- Import the game only via `games/` — the server holds no board state of its own.

**Dependencies:** ARENA-OPUS-SONNET-005

**Expected result:**
The board, whose-turn, and result are correctly reconstructed purely by replaying the persisted move log.

**Acceptance criteria:**
- [ ] `reconstruct_game` returns a `TicTacToe` whose `get_state()` matches the applied moves; `current_turn` is `X`/`O` by parity and `None` once the game is over.
- [ ] **Unit/integration test** (throwaway DB): after N logged moves the reconstructed board / `current_turn` / `is_game_over` are correct for an ongoing game, a win, and a draw; `current_turn` is `None` on and after the terminal move. No paid call.
- [ ] mypy (strict) clean on the reconstruction methods.
- [ ] Ties to DoD: the board and whose-turn are correctly reconstructed by replaying the move log.
