## v01.02 — Persistence layer (SQLite)

### ARENA-040 — Async SQLite engine, session maker & init_models

**Description:**
`server/database.py`: the async SQLAlchemy engine over `sqlite+aiosqlite:///./arena.db`, an
`async_sessionmaker(expire_on_commit=False)`, a connect-time `PRAGMA foreign_keys=ON` listener, and
`init_models()` to create tables from the ORM metadata. The `.db` path is config-driven (env var with
a default) so tests can point at a throwaway file/`:memory:`. Touches: `server/`.

**What needs to be done:**
- `create_async_engine("sqlite+aiosqlite:///./arena.db")` (path overridable via an env var, e.g.
  `ARENA_DB_PATH`, defaulting to `./arena.db`).
- `async_sessionmaker(engine, expire_on_commit=False)`.
- An `event.listens_for(engine.sync_engine, "connect")` listener that runs `PRAGMA foreign_keys=ON`
  on every new DBAPI connection (SQLite enforces FKs per-connection, off by default).
- `async def init_models() -> None`: `run_sync(Base.metadata.create_all)`.

**Dependencies:** ARENA-036

**Expected result:**
Importing `server.database` and calling `init_models()` against a throwaway SQLite file creates an
empty schema with foreign keys enforced.

**Acceptance criteria:**
- [ ] **Unit test:** `init_models()` against a temp-file/`:memory:` DB creates all tables (verified via reflection).
- [ ] **Unit test:** a raw FK violation (insert a `participants` row with a non-existent `match_id`) is rejected once `PRAGMA foreign_keys=ON` is confirmed active on the connection.
- [ ] `mypy server` strict-clean.

### ARENA-041 — The four ORM tables & the seat uniqueness constraint

**Description:**
`server/models.py`: SQLAlchemy ORM models for `matches`, `participants`, `moves`, `chat_messages`
exactly per architecture.md §5.1's column list, including `UNIQUE(match_id, symbol)` on
`participants` (the DB-level guard against a race assigning the same symbol twice). Touches:
`server/`.

**What needs to be done:**
- `Match`: `match_id` (PK, str), `game_type`, `status` (`active`/`finished`), `result`
  (`X`/`O`/`draw`/null), `created_at`.
- `Participant`: `token` (PK, str), `match_id` (FK → matches), `player_name`, `symbol`
  (`X`/`O`/null), `is_spectator` (bool), `created_at`; `UniqueConstraint("match_id", "symbol")`.
- `Move`: `id` (PK, autoincrement), `match_id` (FK), `player_symbol`, `move` (JSON-serializable
  opaque payload — stored as a string/JSON column, never interpreted by this layer), `created_at`.
- `ChatMessage`: `id` (PK, autoincrement), `match_id` (FK), `sender`, `message`, `created_at`.
- All FKs reference `matches.match_id`; `created_at` defaults to `func.now()`.

**Dependencies:** ARENA-040

**Expected result:**
The four tables exist with correct columns/types/constraints; a second `participants` row for the
same `(match_id, symbol)` pair raises an integrity error.

**Acceptance criteria:**
- [ ] **Contract test:** the four table shapes (columns + types) pinned per architecture.md §5.1.
- [ ] **Unit test:** `UNIQUE(match_id, symbol)` rejects a duplicate seat via `IntegrityError`.
- [ ] **Unit test:** a `moves`/`participants`/`chat_messages` row referencing an unknown `match_id` is rejected by the FK constraint.
- [ ] `mypy server` strict-clean.

### ARENA-042 — Repository — CRUD, the §5.2 seat rule & chat/move logging

**Description:**
`server/repository.py`: the single seam everything else uses to touch the database —
`create_match`, `get_match`, `add_participant`, `assign_symbol` (the full §5.2 seat-assignment
algorithm), `release_seat`, `log_move`, `log_chat`. No ad-hoc SQL anywhere else. Touches: `server/`.

**What needs to be done:**
- `create_match(match_id, game_type="tictactoe") -> None`: inserts a `matches` row, `status="active"`.
- `get_match(match_id) -> Match | None`: `None` when not found (the 404 signal for v01.03's join
  endpoint).
- `add_participant(token, match_id, name, is_spectator) -> None`: inserts a `participants` row with
  `symbol=None`.
- `assign_symbol(match_id, token) -> str | None` — the §5.2 algorithm, in order: (1) spectator →
  `None`; (2) already has a `symbol` → return it (idempotent reconnect); (3) both `X` and `O` already
  taken → `None`; (4) otherwise assign the first free symbol and persist it.
- `release_seat(match_id, token) -> None`: clears the `symbol` back to `None` (frees it for a future
  reassignment; the participant row itself isn't deleted).
- `log_move(match_id, symbol, move) -> None` / `log_chat(match_id, sender, message) -> None`: append-only inserts.
- All methods async, over one `AsyncSession` per call (or an injected session — caller's choice), and
  commit before returning.

**Dependencies:** ARENA-041

**Expected result:**
A caller can create a match, add participants, assign/release seats per the §5.2 rule, and log
moves/chat — entirely through `Repository`, with no direct table access anywhere else.

**Acceptance criteria:**
- [ ] **Unit test:** `create_match` + `get_match` round-trip; `get_match` on an unknown id returns `None`.
- [ ] **Unit test:** `assign_symbol` — spectator → `None`; idempotent reconnect (same token, same symbol back); third distinct token → `None`; two tokens sharing the same `player_name` still get distinct symbols (keyed by token, not name).
- [ ] **Unit test:** `release_seat` frees the symbol so a later `assign_symbol` call can reassign it.
- [ ] **Unit test:** `log_move`/`log_chat` persist rows retrievable in insertion order.
- [ ] `mypy server` strict-clean.

### ARENA-043 — reconstruct_game & current_turn — replay-derived live state

**Description:**
Complete the Repository with `reconstruct_game(match_id) -> GameInterface` and
`current_turn(match_id) -> str | None`: load a match's `moves` in insertion order and replay them
through a fresh `TicTacToe()` (from the released v01.01.00 `games/` package) via `apply_move`. No
board snapshot is stored — replay is the only path to live state, keeping `GameInterface` free of any
serialize seam. `current_turn` is derived from move-count parity (`X` on even count) and forced to
`None` once `is_game_over()` is truthy. This is the phase's DoD-closing issue. Touches: `server/`.

**What needs to be done:**
- `reconstruct_game(match_id) -> GameInterface`: `SELECT moves WHERE match_id=... ORDER BY id`, then
  `TicTacToe()` + `apply_move(symbol, move)` per row, in order.
- `current_turn(match_id) -> str | None`: reconstruct, then `None` if `is_game_over()` else `"X"` if
  `len(moves) % 2 == 0` else `"O"`.
- A **process-restart** integration test: write matches/participants/moves/chat to a real (temp-file,
  not `:memory:`) SQLite DB, close all connections/engine, open a **fresh** engine against the same
  file, and confirm `reconstruct_game` yields the same board and `current_turn` — proving durability
  isn't an artifact of one in-memory connection staying open.

**Dependencies:** ARENA-042, ARENA-039 (released `games/tictactoe.py`)

**Expected result:**
`reconstruct_game` and `current_turn` correctly reflect a match's true state purely from its
persisted move log, across a full match and across a simulated server restart.

**Acceptance criteria:**
- [ ] **Integration test:** N moves logged → `reconstruct_game` board matches an equivalent in-memory `TicTacToe` playthrough.
- [ ] **Integration test:** `current_turn` alternates correctly by move-count parity and is `None` once the game is over (win or draw).
- [ ] **Integration test:** the process-restart scenario (fresh engine, same DB file) reconstructs identically.
- [ ] `pytest` green and `mypy server` strict-clean for the whole phase.
- [ ] Ties to v01.02 DoD (release gate): matches/participants/moves/chat persist and survive a
  process restart; board and turn are correctly reconstructed by replay; a duplicate seat is rejected
  by the DB.
