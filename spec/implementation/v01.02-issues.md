## v01.02 — Persistence layer (SQLite)

### ARENA-075 — `server/database.py` — async engine, session maker, FK pragma, `init_models()`

**Description:**
Stand up the async SQLAlchemy engine over `sqlite+aiosqlite:///./arena.db` per
architecture.md §3: an `async_sessionmaker(expire_on_commit=False)`, a connect-time
`PRAGMA foreign_keys=ON` (via an SQLAlchemy `event.listens_for(engine.sync_engine, "connect")`
listener), and `init_models()` to create tables from the ORM metadata. Touches: `server/database.py`,
`pyproject.toml` (new runtime deps).

**What needs to be done:**
- Add runtime deps: `sqlalchemy>=2.0`, `aiosqlite`. Add dev dep: `pytest-asyncio`, with
  `[tool.pytest.ini_options] asyncio_mode = "auto"`.
- `[tool.setuptools] packages` gains `"server"`.
- `server/__init__.py` (empty).
- `server/database.py`: `DB_URL` (config-driven, default `sqlite+aiosqlite:///./arena.db`),
  `engine = create_async_engine(DB_URL)`, `async_session_maker = async_sessionmaker(engine,
  expire_on_commit=False)`, an FK-pragma connect listener, `async def init_models() -> None` that
  creates all tables via `Base.metadata.create_all` run through the async engine
  (`run_sync`).
- `Base` (the declarative base) lives here so `models.py` can import it without a cycle.

**Dependencies:** ARENA-071

**Expected result:**
`init_models()` against a throwaway SQLite file creates a schema with foreign keys enforced.

**Acceptance criteria:**
- [ ] `init_models()` creates all tables idempotently (safe to call twice).
- [ ] A connection has `PRAGMA foreign_keys` reporting `1` (on) — verified directly in a test.
- [ ] `mypy --strict server` passes.
- [ ] `pip install -e ".[dev]"` still succeeds with the new deps declared.

### ARENA-076 — `server/models.py` — ORM models for the four tables, with seat uniqueness

**Description:**
Define the four SQLAlchemy ORM models per architecture.md §5.1: `Match`, `Participant`, `Move`,
`ChatMessage`, with `UNIQUE(match_id, symbol)` on `Participant` so at most one `X` and one `O` can
ever exist per match. Touches: `server/models.py`, `tests/`.

**What needs to be done:**
- `server/models.py`: `Match(match_id: str PK, game_type: str, status: str, result: str | None,
  created_at)`; `Participant(token: str PK, match_id: str FK, player_name: str, symbol: str | None,
  is_spectator: bool, created_at)` with a `UniqueConstraint("match_id", "symbol")`; `Move(id: int PK
  autoincrement, match_id: str FK, player_symbol: str, move: JSON-serializable, created_at)`;
  `ChatMessage(id: int PK autoincrement, match_id: str FK, sender: str, message: str, created_at)`.
- All FKs reference `matches.match_id`; typed via SQLAlchemy 2.0 `Mapped`/`mapped_column`.
- Contract test pinning the four table shapes (columns + the seat-uniqueness constraint).

**Dependencies:** ARENA-075

**Expected result:**
`init_models()` (from ARENA-075) creates exactly these four tables with the documented columns and
constraints.

**Acceptance criteria:**
- [ ] All four tables created by `init_models()`, matching architecture.md §5.1's key columns.
- [ ] **Contract test:** the four table shapes (columns, PK/FK, the `UNIQUE(match_id, symbol)`
      constraint on `participants`) are pinned here — must change in the same commit as any future
      schema change.
- [ ] `mypy --strict server` passes.

### ARENA-077 — `server/repository.py` — `Repository` CRUD: matches, participants, moves, chat

**Description:**
Build the `Repository` — the **only** way handlers touch the database per architecture.md §3/§5.1 —
covering match/participant/move/chat CRUD (seat *assignment* logic and game reconstruction land in
ARENA-078, which builds on this). Touches: `server/repository.py`.

**What needs to be done:**
- `class Repository`: constructed with an `AsyncSession`; all methods `async`.
- `create_match(match_id, game_type="tictactoe") -> None`.
- `get_match(match_id) -> Match | None` — `None` when unknown (the 404 case for lobby join, wired
  in v01.03).
- `add_participant(token, match_id, name, is_spectator) -> None`.
- `release_seat(match_id, token) -> None` — clears `symbol` back to `None` on that participant's row.
- `log_move(match_id, symbol, move) -> None`, `log_chat(match_id, sender, message) -> None` — append
  ordered rows.
- Session lifecycle: methods commit their own writes; no long-lived transaction held across calls.

**Dependencies:** ARENA-076

**Expected result:**
Each CRUD method round-trips correctly against a throwaway SQLite DB.

**Acceptance criteria:**
- [ ] `create_match` + `get_match` round-trip; `get_match` on an unknown id returns `None` (no
      exception).
- [ ] `add_participant` persists a row; `release_seat` clears `symbol` without deleting the row.
- [ ] `log_move` / `log_chat` append rows in insertion order.
- [ ] `mypy --strict server` passes.

### ARENA-078 — `reconstruct_game` + `current_turn`, and the persistence/integration test suite

**Description:**
Close out the phase DoD: `reconstruct_game` replays a match's ordered `moves` through a fresh
`TicTacToe` instance to derive live state (architecture.md §5.1 — no serialize/deserialize is added
to `GameInterface`), and `current_turn` derives whose turn it is from move-count parity, `None` once
the game is over. Plus the full persistence/integration suite the phase DoD requires. Touches:
`server/repository.py`, `tests/`.

**What needs to be done:**
- `Repository.reconstruct_game(match_id) -> GameInterface`: load `moves` ordered by insertion,
  replay each through a new `TicTacToe()` via `apply_move`, return the resulting game object.
- `Repository.current_turn(match_id) -> str | None`: `"X"` on even move count, `"O"` on odd,
  `None` once `reconstruct_game(...).is_game_over()` is truthy.
- `tests/test_database.py`: `init_models()` creates the schema; `PRAGMA foreign_keys` is on.
- `tests/test_models.py` (from ARENA-076, extended here if needed): FK violation is rejected by
  the DB (inserting a `Move` for a nonexistent `match_id` raises an integrity error).
- `tests/test_repository.py`: round-trip every table through `Repository`; `UNIQUE(match_id,
  symbol)` blocks a second participant claiming the same symbol (integrity error).
- `tests/test_reconstruct_game.py`: after N moves, `reconstruct_game` yields the correct board and
  `current_turn`; a finished game (win or draw) yields `current_turn is None` and the correct
  `is_game_over()` result.
- All DB tests run against a **throwaway SQLite DB** (temp file or a fresh `:memory:` engine per
  test) — never the dev `arena.db`.

**Dependencies:** ARENA-077, ARENA-073

**Expected result:**
Matches/participants/moves/chat persist and survive a process restart (a fresh `Repository` against
the same DB file sees prior data); board and turn are correctly reconstructed by replay; a duplicate
seat for the same symbol is rejected by the DB, not just application logic.

**Acceptance criteria:**
- [ ] Data survives a simulated "restart" (new engine/session against the same DB file still reads
      prior rows).
- [ ] `reconstruct_game` yields the correct board/`current_turn`/result after N moves, including a
      completed game.
- [ ] `UNIQUE(match_id, symbol)` rejects a second seat for an already-taken symbol.
- [ ] A `Move`/`ChatMessage`/`Participant` FK violation (unknown `match_id`) is rejected.
- [ ] `mypy --strict server` passes; full suite green.
