## Findings

### 1. 🟠 MEDIUM — submitting a move can *grant* a seat

**Anchor:** [server/handlers.py](../../server/handlers.py) — `handle_submit_move`, step 1

```python
symbol = await repository.assign_symbol(match_id, token)   # a WRITE
if symbol is None:
    ...error "you have no seat in this match"
```

§5.4 names `assign_symbol` as step 1, and for a seated player it is idempotent, so the flow is
correct as written. The problem is what it does for a client that is *not* seated.

**Failure scenario.** Alice (X) and Bob (O) are playing. Carol joins the same match as a player,
finds it full, and connects — her `joined` carries `symbol: null, seat_available: true`, and she sits
there. Bob's connection drops for a moment; the seat is released (finding #2). Carol now sends
`submit_move`. Step 1 does not merely *check* her seat, it **assigns** her one — she becomes O and
plays on into a game whose O moves were made by Bob. Bob reconnects to find himself seated as nobody,
or seated as X's opponent in a game he is no longer playing.

The move flow is supposed to be the place where authority is *checked*. Making it also the place
where identity is *granted* means the act of asking changes the answer, which is exactly what an
authority check must not do. Seats are already claimed at connect (ARENA-015 calls `claim_seat` and
reports the result in `joined`), so nothing needs assigning here.

Secondary cost: `assign_symbol` is a write path — `SELECT` participant, `SELECT` taken symbols,
possibly a savepoint — executed on **every move** by every player, to re-derive something that was
settled at connect.

**Proposed fix.** Step 1 reads the seat the token already holds instead of assigning one. A client
with no seat is refused exactly as before, and the refusal no longer depends on whether a seat
happens to be free at that instant. This changes documented behaviour, so `architecture.md` §5.4 gets
the correction in the same commit.

### 2. 🟠 MEDIUM — a momentary drop gives the game away

**Anchor:** [server/main.py](../../server/main.py) — the `finally` block; `release_seat`

Cleanup releases the seat the instant a socket goes away. That is right for a player who leaves, and
wrong for a player whose wifi hiccups: their seat is immediately available, and with finding #1 fixed
a *newly connecting* client can still take it and continue their game.

The whole point of keying seats by token (§5.2) is that identity survives the connection, and
`assign_symbol`'s idempotent-reconnect branch exists to hand a returning player their seat back — but
only if it was not released in the meantime.

Deferred rather than fixed because the correct behaviour is a **grace period** (hold the seat for N
seconds, release on expiry), which needs timers, a policy decision about N, and a way for `joined` to
say "your seat is being held". That is a design, not a patch — and it is precisely what roadmap
**v05.01 — Resilience & reconnection** exists for.

**Home:** v05.01.

### 3. 🟡 LOW — rooms outlive the application

**Anchor:** [server/main.py](../../server/main.py) — `manager = ConnectionManager()`, module-level

`lifespan` disposes the engine on shutdown but never clears `manager`, so a second `lifespan` in the
same process starts with the previous run's socket lists. In production a restart is a new process,
so this is only reachable in tests and embedded use — the suite avoids it by using a fresh `match_id`
per test rather than by the code being safe.

**Home:** v05.02 (the integration suite is where in-process restarts get exercised).

### 4. 🟡 LOW — nothing bounds chat volume or audience size

**Anchor:** [server/handlers.py](../../server/handlers.py) — `handle_chat`

Message length is bounded, message *rate* is not: a client may chat as fast as it can write, and each
one is persisted and fanned out to the whole room. Likewise nothing caps observers per match, so the
broadcast fan-out is unbounded.

Both are denial-of-service shapes rather than correctness bugs, and §12 is explicitly local-first.

**Home:** v05.01.

### 5. 🟡 LOW — a long-lived session can hold a stale `Match`

**Anchor:** [server/main.py](../../server/main.py) — one session per WS connection (§10)

§10 specifies a session per connection, and `expire_on_commit=False` keeps objects usable after
commit — together that means `get_match` can return an instance from the identity map that another
connection has since updated. Harmless today because no decision reads `matches.status`: the flow
derives everything from the move log. It would stop being harmless the moment one does.

**Home:** v05.01.

## What's solid

- **The authority rule holds against a lying client.** A player sending `{"move": 0, "symbol": "X"}`
  from the O seat is refused — the symbol comes from the token, and there is a test that would fail
  if the payload were ever trusted, because it really *was* X's turn.
- **The §5.4 order is followed and its reasoning is recorded**: legality before turn would let a
  player probe free cells on the opponent's turn; turn before seat would leak whose turn it is to
  someone with no seat.
- **`broadcast` serialises once and prunes**, verified by counting, with the test ordering
  deliberately alive-dead-alive — a naive loop stops at the raise and everyone after it goes silent.
- **The transaction change is guarded structurally**: an AST test fails on any `.commit` in the
  Repository, and the seat race moved to a savepoint so losing a race cannot discard a caller's
  unrelated work.
- **Cleanup genuinely survives cancellation**, and the fix was driven by a real failure rather than
  by reading §10 — the inline version leaked the seat and the next client received `O`.
- **The gate test walks the DoD verbatim**, with three clients including an observer, every refusal,
  chat, and the closed room.
- **A test that passed against broken code was thrown away** rather than kept for its green tick.

## Fixes applied

Both in `52e3531`. **Files:** `server/handlers.py`, `server/repository.py`, `server/websockets.py`,
`server/main.py`, `tests/test_ws_connect.py`, `tests/test_ws_moves.py`.

### Finding 1 — the move flow reads the seat, never grants it

`Repository.seat_of(match_id, token)` is the read-only counterpart of `assign_symbol`, and §5.4 step
1 now uses it. A client with no seat is refused exactly as before, but the refusal no longer depends
on whether a seat happens to be free at that instant.

`seat_of` queries the **columns** rather than loading the entity. A WS connection holds one session
for its whole life (§10), and an entity already in its identity map is answered with the attributes it
was loaded with — so a seat changed by another connection would be read stale. This was not
theoretical: it produced a wrong answer during the fix pass.

### Finding 6 — a deferred release must not outrun a reconnect

**Raised during the fix pass, and new in this phase** — introduced by ARENA-015's own fix.

The release runs detached so that cancellation cannot kill it. That left it **unordered** with respect
to a quick reconnect: landing after the reconnect's claim, it wiped the seat just taken. The symptom
was a direct self-contradiction — `joined` reported `symbol: "X"` and the very next move was refused
with "you have no seat in this match".

A first attempt guarded the release with "skip if this token has a live socket". That narrowed the
window without closing it, because the two operations were still merely racing. The connection now
**waits for its own pending release before claiming**, making the ordering explicit.

> **Why it had been invisible.** The pre-fix `submit_move` called `assign_symbol` on every move, which
> silently re-granted the very seat the stale release had taken away. Fixing finding #1 removed that
> accidental repair and the bug surfaced immediately. A bug masked by a second bug is the argument for
> fixing the authority check even though nothing was visibly broken.

**Regression test:** `test_reconnecting_immediately_keeps_the_seat` — connect, drop, reconnect, move.
It fails without the ordering (`error: you have no seat`).

**Verification:** 310 passed (309 → 310) · `mypy games server agent` clean · tracker suite 293.

**Architecture impact.** §5.4 step 1 no longer reads *"`symbol = repo.assign_symbol(match_id, token)`"*:

> **The move flow reads the seat (`seat_of`); it does not assign one.** Seats are claimed once, at WS
> connect (§6.2 `joined`). `None` still means no seat — observer, unseated, or unknown token — and the
> refusal is unchanged from the client's point of view.

`spec/architecture.md` is updated in the same commit as this record.
