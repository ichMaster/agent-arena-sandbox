## Findings

### #1 🟡 Empty `player_name` accepted (LOW) — deferred
**Failure scenario:** `POST /lobby/join {"match_id": "...", "player_name": ""}` succeeds and stores a
blank display name — later rendered as an empty label in chat/UI. Not a security or correctness issue
(identity is by token, per §5.2 — a blank name can't collide a seat), purely a UX nuisance. Homed to
v05.03 polish alongside the rest of the input-hygiene sweep.

## What's solid
`create_app`'s DI pattern means every integration test binds its own throwaway engine — the dev
`./arena.db` is never at risk of being touched by a test run; the join→404 path is a real HTTP
round-trip, not a mocked assertion; `test_match_identity.py` drives the seat rule through real,
lobby-issued tokens (the coverage the v01.02 Repository tests structurally couldn't provide); zero
model calls anywhere.

## Architecture impact
None — §5.2/§6.1/§6.3 implemented exactly as already documented; no seam changed.
