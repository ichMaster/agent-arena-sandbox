## v05.01 — Resilience & reconnection

### ARENA-OPUS-034 — Resilience verification + malformed-JSON fix: same-token reconnect, no-leak, graceful bad input

> **⟳ Reconciled (2026-07-21):** re-scoped from test-only to test **+ one small production fix** — see
> the file intro's correction. The malformed-JSON DoD line was never actually implemented; closing it
> is small and self-contained enough to belong in this same verification-checkpoint issue rather than
> spinning up a separate one.

**Description:** most of the resilience code is already in place (see the reconciliation table); this
issue **closes two gaps**: (1) test coverage — a participant that drops and **reconnects with the same
token reclaims a seat** — and (2) a real gap — `_ws_connection` currently lets malformed (non-JSON)
input crash the connection instead of sending an `error` event and continuing, contradicting this
version's own DoD. Touches: `server/main.py`, `tests/`.

**What needs to be done:**
- **Fix (`server/main.py::_ws_connection`):** wrap the receive-loop's JSON parse in a `try/except` —
  on invalid JSON, send the existing `error_event("malformed message")` over the same socket and
  `continue` the loop (never crash it, never drop the connection). Reuses the shipped `error_event`
  shape — no new wire contract.
- `tests/test_reconnect.py`:
  - `test_same_token_reconnect_reclaims_seat`: player A joins → WS connect → gets `X`; A drops (WS
    context exit) → the shielded cleanup frees `X`; A **reconnects with the same token** → gets a seat
    again (poll briefly for the shielded release, mirroring the existing resilience test).
  - `test_drop_then_reconnect_leaves_both_seats_usable`: after an A drop + A reconnect, a second
    player B can still take the remaining seat — i.e. exactly two seats exist, none leaked.
  - `test_malformed_json_keeps_connection`: send non-JSON text over an open WS; assert an `error`
    event comes back (not a raised exception / dropped connection) and the socket still accepts a
    normal action afterward.
- The LLM is not involved (pure server/WS + DB paths). Confirm the full resilience set (existing +
  new) is green and deterministic.

**Dependencies:** None (verifies the shipped v01.04 resilience; the malformed-JSON fix is
self-contained).

**Expected result:** a dropped player reconnecting on the same token reclaims a seat; the two-seat
invariant holds across drop/reconnect — no leak; malformed input no longer crashes a connection.

**Acceptance criteria:**
- [ ] `test_same_token_reconnect_reclaims_seat` passes (same-token reconnect gets a seat after a drop).
- [ ] `test_drop_then_reconnect_leaves_both_seats_usable` passes (no seat leaked; both seats usable).
- [ ] `test_malformed_json_keeps_connection` passes: invalid JSON yields an `error` event, connection stays open and usable.
- [ ] The whole resilience suite is green and **deterministic** (stable across repeated runs); no LLM, no paid call.
- [ ] mypy (strict) clean. Ties to DoD: a disconnecting player frees their seat for a reconnect; a malformed message is rejected without killing the socket; the server never leaks a seat on a disconnect path.
