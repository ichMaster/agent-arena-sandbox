## Findings

### #1 🟡 Generic opponent label (LOW) — deferred
`renderPlayers` labels the non-me card "Player X/O" + "Haiku · Agent". **Scenario:** in a
human-vs-human match the opponent is mislabelled "Agent"; and a Haiku agent's actual persona name
(e.g. "Ironclaw") isn't shown either way. The wire `joined`/`state_update` payloads carry no
participant display names, so a faithful label needs a protocol addition — out of MVP scope
(web_ui_spec §10). Homed to v05 polish.

## What's solid

presentation-only and reads the DOM only after the terminal `state_update` has already rendered it
(events arrive in order, so this is safe) — the server remains the sole authority on the actual
result; `resetPlayState` closes the §7 second-match regression. Zero model calls.
