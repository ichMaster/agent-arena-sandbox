### ARENA-OPUS-SONNET-002 — `GameInterface` abstract seam + contract test

**Description:**
Define the abstract **`GameInterface`** — the only way a game plugs into the system ([architecture.md](../architecture.md) §4.1) —
as four typed abstract methods, importing nothing from `server/`. This is a **stable seam**: it ships
with a contract test that pins the exact method signatures, and any future change to it must update
[architecture.md](../architecture.md) §4.1 + this test in the same commit. Touches: `games/interface.py`, `tests/`.

**What needs to be done:**
- `games/interface.py`: `GameInterface(ABC)` with the four `@abstractmethod`s, strictly typed exactly per §4.1:
  - `get_state(self) -> dict[str, Any]`
  - `get_valid_moves(self) -> list[Any]`
  - `apply_move(self, player: str, move: Any) -> bool`
  - `is_game_over(self) -> str | None`
- Document the seam rules in the module: the move payload is **opaque** to transport; `apply_move` is the **sole legality authority** and returns `False` (never raises) on illegal input; new games are new modules.
- Keep the module free of any `server/` import (pure logic seam).

**Dependencies:** ARENA-OPUS-SONNET-001

**Expected result:**
An importable, strictly-typed `GameInterface` abstraction whose signatures are pinned by a contract test.

**Acceptance criteria:**
- [ ] `games/interface.py` defines `GameInterface(ABC)` with the four abstract methods, strict-typed per §4.1; imports nothing from `server/`.
- [ ] **Contract test:** `tests/test_game_interface_contract.py` pins the seam — the four method **names + signatures** (params and annotations) are asserted (e.g. via `inspect.signature`), and a bare/partial subclass cannot be instantiated (abstractness enforced). *(Seam pinned — architecture §4.1 is its source of truth; changing the seam updates §4.1 + this test together.)*
- [ ] **Unit test:** the abstractness/signature assertions run under `pytest` with **no LLM and no paid call**.
- [ ] `mypy` (strict) is clean on `games/interface.py`.
- [ ] Ties to DoD: establishes the abstract game seam the TicTacToe engine implements.

### ARENA-OPUS-SONNET-003 — TicTacToe engine + exhaustive unit tests

**Description:**
Implement the concrete **TicTacToe** game as pure logic behind `GameInterface` ([architecture.md](../architecture.md) §4.1),
plus the exhaustive unit suite that verifies it in isolation (roadmap §v01.01 Tests). No server,
transport, or persistence is involved. Per "tests ship with the feature," the engine and its full
test matrix land in the one commit. Touches: `games/tictactoe.py`, `tests/`.

**What needs to be done:**
- `games/tictactoe.py`: `TicTacToe(GameInterface)` — a 9-cell board (`list`), `X` moves first, the 8 winning lines, `"draw"` when the board is full with no line.
- `get_state()` returns the structured board (e.g. `{"board": [...]}`); `get_valid_moves()` returns the list of empty cells (shrinks as the board fills); `is_game_over()` returns `"X" | "O" | "draw" | None`.
- `apply_move(player, move)`: the **sole legality authority** — returns `False` for out-of-range, occupied, and wrong-type (non-`int`) moves and **never raises**; on a legal move, marks the cell with `player`'s symbol and returns `True`.
- Exhaustive tests (`tests/test_tictactoe.py`): a **win on every one of the 8 lines**; **draw** detection on a full no-line board; **illegal-move rejection** for each category (out-of-range, occupied, wrong-type) returning `False` without raising; `get_valid_moves` **shrinks correctly** as moves are applied; `get_state`/`is_game_over` report correctly through a full game.

**Dependencies:** ARENA-OPUS-SONNET-002

**Expected result:**
A fully-tested TicTacToe engine that reports valid moves, applies legal moves, rejects illegal ones without raising, and detects win/loss/draw — all verified with no server involved.

**Acceptance criteria:**
- [ ] `games/tictactoe.py` implements `GameInterface`; `X` first, 8 winning lines, `"draw"` on a full board; `apply_move` returns `False` (never raises) for out-of-range/occupied/wrong-type and `True` on a legal move.
- [ ] **Unit test:** the exhaustive matrix passes — win on **each** of the 8 lines, draw detection, illegal rejection per category, `get_valid_moves` shrink invariant — with the **LLM absent entirely** (pure logic, no paid call).
- [ ] `mypy` (strict) is clean on `games/tictactoe.py` and its tests.
- [ ] Ties to DoD: the engine correctly reports valid moves, applies legal moves, rejects illegal ones without raising, and detects win/loss/draw — verified in isolation, no server involved.
