## v01.01 — Project skeleton & the game engine

### ARENA-071 — Repo skeleton — pyproject.toml, package layout, pytest + mypy config

**Description:**
Stand up the project skeleton so every later phase has somewhere to land code: `pyproject.toml`
with pytest and `mypy --strict` configuration, and the top-level package layout from
[architecture.md](../architecture.md) §2 (`games/`, `server/`, `agent/`, `web/`, `profiles/`,
`scripts/`, `tests/` — created as needed by later phases, but `games/` and `tests/` must exist now).
Touches: repo root, `games/`.

**What needs to be done:**
- `pyproject.toml`: project metadata, `pytest` config (`tests/` as the test root), `[tool.mypy]
  strict = true` (no separate `mypy.ini`).
- `[tool.setuptools] packages = ["games", "server", "agent"]` set explicitly — without it,
  setuptools auto-discovers `web/`, `profiles/`, `spec/`, etc. as false top-level package candidates
  and `pip install -e ".[dev]"` fails with *"Multiple top-level packages discovered in a
  flat-layout"*.
- Runtime deps declared for what exists so far (none yet beyond stdlib); dev deps: `pytest`, `mypy`.
- `games/__init__.py`, empty `tests/` package ready for ARENA-074.
- `.gitignore` already present — confirm it covers `*.db`, `__pycache__/`, `.mypy_cache/`,
  `.pytest_cache/`, `.venv/` (add any missing).

**Dependencies:** None

**Expected result:**
`python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"` succeeds from a clean checkout, and
`.venv/bin/pytest` / `.venv/bin/mypy games` run cleanly (0 collected is fine at this point).

**Acceptance criteria:**
- [ ] `pip install -e ".[dev]"` succeeds from a clean checkout (no flat-layout package-discovery error).
- [ ] `mypy --strict` config is active via `[tool.mypy]` in `pyproject.toml` (confirm with a
      deliberately mistyped scratch file, then remove it).
- [ ] `pytest` collects (even zero tests) without error.

### ARENA-072 — `GameInterface` — the abstract game seam

**Description:**
Define the abstract `GameInterface` in `games/interface.py` per [architecture.md](../architecture.md)
§4.1 — the **only** way a game plugs into the system. Pure `abc.ABC`, no server or transport imports.
Touches: `games/interface.py`, `tests/`.

**What needs to be done:**
- `games/interface.py`: `class GameInterface(ABC)` with the four abstract methods, typed exactly as
  pinned — `get_state() -> dict[str, Any]`, `get_valid_moves() -> list[Any]`,
  `apply_move(player: str, move: Any) -> bool`, `is_game_over() -> str | None`.
- Docstring notes: the move payload is opaque to transport (only the game module interprets it);
  `apply_move` is the sole legality authority and must never raise on bad input — it returns `False`.
- No concrete logic here — this issue is the seam only; `TicTacToe` lands in ARENA-073.

**Dependencies:** ARENA-071

**Expected result:**
`games.interface.GameInterface` exists as an abstract base class matching the pinned signatures,
importable with zero dependencies beyond stdlib.

**Acceptance criteria:**
- [ ] `GameInterface` cannot be instantiated directly (all four methods abstract).
- [ ] **Contract test:** a test module asserts the exact method names and signatures pinned in
      [architecture.md](../architecture.md) §4.1 — this test must change in the same commit as any
      future seam change.
- [ ] `mypy --strict games` passes on the new module.

### ARENA-073 — `TicTacToe` engine — board, moves, win/draw detection

**Description:**
Implement `games/tictactoe.py`, the concrete `GameInterface` for Tic-Tac-Toe per
[roadmap.md](../roadmap.md) §v01.01 and [architecture.md](../architecture.md) §4.1: a 9-cell board,
`X` moves first, 8 winning lines, `"draw"` when the board is full with no line. Touches:
`games/tictactoe.py`.

**What needs to be done:**
- `class TicTacToe(GameInterface)`: 9-cell list state (`get_state()` returns `{"board": [...]}`),
  `X` first.
- `get_valid_moves()`: indices `0–8` of empty cells only; shrinks as moves are played.
- `apply_move(player, move)`: opaque `int` cell payload; returns `False` — never raises — for
  out-of-range (`< 0` or `> 8`), occupied, or wrong-type (non-`int`) moves; otherwise places the
  mark and advances turn.
- `is_game_over()`: checks all 8 lines (3 rows, 3 cols, 2 diagonals) for a winner; returns `"X"` /
  `"O"` / `"draw"` (full, no line) / `None` (ongoing).

**Dependencies:** ARENA-072

**Expected result:**
`TicTacToe` fully implements `GameInterface`; illegal input never raises, always returns `False`
from `apply_move` and leaves state unchanged.

**Acceptance criteria:**
- [ ] Legal moves are applied and reflected in `get_state()`.
- [ ] `apply_move` returns `False` (no exception) for out-of-range, occupied, and wrong-type moves,
      and state is unchanged after a rejected move.
- [ ] `is_game_over()` correctly reports each of the 8 winning lines, `"draw"`, and `None` mid-game.
- [ ] `mypy --strict games` passes.

### ARENA-074 — Exhaustive unit tests for the TicTacToe engine

**Description:**
Close out the phase DoD with an exhaustive, isolated unit suite directly against the engine — no
server, no transport. Touches: `tests/`.

**What needs to be done:**
- `tests/test_tictactoe.py`: a parametrized test hitting all 8 winning lines (3 rows, 3 columns, 2
  diagonals) for both `X` and `O`.
- Draw detection: a full board with no winning line resolves `is_game_over() == "draw"`.
- Illegal-move rejection: out-of-range (negative, `> 8`), already-occupied, and wrong-type (e.g. a
  `str`) moves each return `False` without raising and without mutating state.
- `get_valid_moves()` shrinks by exactly one index per legal move and never includes an occupied
  cell.
- `tests/test_game_interface_contract.py` (from ARENA-072) runs alongside as the seam's contract
  test.

**Dependencies:** ARENA-073

**Expected result:**
`pytest` is green with the full TicTacToe suite passing, run in isolation from any server code.

**Acceptance criteria:**
- [ ] Unit test: win asserted on every one of the 8 lines.
- [ ] Unit test: draw detection on a full, lineless board.
- [ ] Unit test: illegal-move rejection (out-of-range, occupied, wrong-type) — no exception raised.
- [ ] Unit test: `get_valid_moves()` shrinks correctly across a played-out game.
- [ ] Ties to the phase DoD: the engine is verified fully in isolation, no server involved.
