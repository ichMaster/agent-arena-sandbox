## Findings

### 1. 🟠 MEDIUM — Wrong Haiku model id: `"claude-haiku-4-5"` instead of `"claude-haiku-4-5-20251001"`

**File:** `agent/llm.py:19`

**Failure scenario:** ARENA-089's own acceptance criteria explicitly flagged this risk —
"confirm against the live model list rather than hardcoding a guess" — because the default test
suite **mocks the SDK entirely** and can never catch a wrong model id; it only surfaces the first
time a live agent actually calls the API, as an authentication/model-not-found error, mid-match.
`HAIKU_MODEL_ID` was set to `"claude-haiku-4-5"`, copied verbatim from the illustrative example in
`roadmap.md` §v02.01 ("e.g. `claude-haiku-4-5`") without the verification step the roadmap itself
calls for. The correct, current id (per this environment's own up-to-date model listing) is
**`claude-haiku-4-5-20251001`** — Anthropic model ids for dated releases include the date suffix;
the undated short form is not a real model id.

**Proposed fix:** update the constant to the verified id.

## What's solid

- **Structured output is genuinely forced, not just requested.** `tool_choice` is pinned to the
  single tool built from `schema.model_json_schema()`, so the model cannot fall back to a plain-text
  reply the caller would have to parse.
- **One failure path for malformed output.** A missing tool-use block and a malformed one both
  fall through to `schema.model_validate(...)`, raising the same `ValidationError` either way —
  no separate ad-hoc "block not found" exception type to handle downstream.
- **Fail-fast on the API key is genuinely fail-fast** — checked in `__init__`, before any client
  construction touches the network, not deferred to the first call.
- **Contract test correctly pins the abstract method's signature** (`generate_structured_response`)
  rather than just checking the class exists.
- **No paid API calls anywhere in the suite** — verified structurally (every test mocks
  `messages.create`), not just claimed.

## Fixes applied

### Fix for Finding 1

**Change:** `HAIKU_MODEL_ID` corrected to `"claude-haiku-4-5-20251001"`.

**Regression test:** none added — this is a config-constant correction with no branching logic to
regress; the existing mocked test suite already exercises every code path around it, and the
value itself isn't something a unit test can validate without a real API call (which the suite
deliberately never makes). Noted here instead so a future live run's model-not-found error, if it
ever recurs, has this history to check first.

**Verification:** full suite green after the change (no behavior depends on the exact string);
`mypy --strict` clean.

**Architecture impact:** none — `HAIKU_MODEL_ID` is an internal constant, not part of the
`LLMClient` seam's contract. No `spec/architecture.md` update needed.
