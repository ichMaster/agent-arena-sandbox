  (self = `sender === mySymbol` → left/blue; everyone else → right/pink), auto-scrolling. The chat
  form sends `{action:"chat", payload:{message}}` on submit and never renders optimistically — only
  the server's `chat_message` echo renders a bubble. `error` now surfaces as a system line (closes
  v03.01 review #2); `game_over` also posts a result system line. Chat input is enabled only when
  `mySymbol !== null`.

  Human/Haiku labels) whenever `mySymbol === null`, without ever calling `null.toLowerCase()`. Board
  cells and chat input were already non-interactive for an Observer (v03.01–v03.02, ARENA-OPUS-030).
  A new end-to-end test against the real server confirms an Observer join yields `symbol:null` and no
  seat, and a forced `submit_move` is refused ("no seat"); Host/Join still default to the Player role.
- **Reconciliation carried forward:** the pre-generated issues file's "observers cannot chat" server
  citation was found stale during reconcile (no such v01.04 fix exists) — the real server currently
  *accepts* an observer's chat (labeled `sender="observer"`), which diverges from web_ui_spec §5's
