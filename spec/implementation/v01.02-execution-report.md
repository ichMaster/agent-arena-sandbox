## Detailed Results

### ARENA-005 — Async SQLite engine, session maker & `init_models`
**Status:** completed · **Commit:** `300ae20` · **Attempts:** 1
**Validation:** [x] install · [x] pytest (108) · [x] mypy · [x] acceptance

Config-driven URL (`ARENA_DATABASE_URL`), `expire_on_commit=False`, `session_scope()`, and the
connect-time `PRAGMA foreign_keys=ON`. The PRAGMA is asserted to read back as `1`, and to stay on
across repeated connections — it is a *per-connection* setting, so a pooled connection opened later
would otherwise stop enforcing anything.

`tests/conftest.py` gives every database test a throwaway temp **file**, chosen over `:memory:`
specifically so ARENA-008's restart test is expressible.

### ARENA-006 — The four ORM tables & the seat uniqueness constraint
**Status:** completed · **Commit:** `765210b` · **Attempts:** 1
**Validation:** [x] pytest (119) · [x] mypy · [x] contract test · [x] acceptance

The seat constraint is tested from three sides, because only the first is obvious: a duplicate symbol
*within* a match is rejected; the same symbol in *another* match is allowed; and many `NULL` symbols
coexist in one match. Had the third been wrong, a second spectator could never have been inserted.

The three FK-rejection tests double as a live check that ARENA-005's PRAGMA is still in force —
without it they would pass as successful inserts.

### ARENA-007 — `Repository` — matches, participants & the seat rule
**Status:** completed · **Commit:** `749d857` · **Attempts:** 1
**Validation:** [x] pytest (138) · [x] mypy · [x] contract test · [x] acceptance

Every branch of §5.2 in order. The contract test pins the identity rule through the *signature*:
`assign_symbol(match_id, token)` takes no name, so keying a seat by display name cannot be
reintroduced without changing the seam and its test together.

Two guards beyond the acceptance list: a token belonging to another match is refused a seat, and
seats are scoped per match.

### ARENA-008 — Move/chat log, `reconstruct_game` & derived `current_turn`
**Status:** completed · **Commit:** `d6bea1a` · **Attempts:** 1
**Validation:** [x] pytest (155) · [x] mypy · [x] acceptance

Reconstruct-by-replay, with `current_turn` reading `TicTacToe.current_player` straight through.
Durability is proven with a **second engine over the same file**, standing in for a restarted
process, for both an in-progress and a finished match.

**Where the reconciliation paid off.** v01.01's review fix (`f5a9ee4`) had already made
`current_player` return `None` once the game is over. So `current_turn` needed no parity arithmetic
and no special case for the terminal move: §6.2's "`current_turn` is `null` on the game-ending move"
is satisfied by construction, in one place. That is exactly the outcome the fix was intended to buy,
one version later.
