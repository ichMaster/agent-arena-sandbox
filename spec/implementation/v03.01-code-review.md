# Code Review & Fix Recommendations — v03.01 (static UI shell & connection)

**Date:** 2026-07-21 · **Reviewer:** Claude Sonnet 5, via `/ship-solution`
**Scope:** the `/ui` mount + `no-store` middleware (`server/main.py`), the arena shell
(`web/index.html`, `web/styles.css`), and the connection wiring (`web/app.js`).
**Method:** manual adversarial read; each finding carries a concrete failure scenario.

## Recommendation summary

*No findings.* The mount is CWD-independent and exact-match (not a loose prefix); the shell exposes
every JS-targeted id; `app.js` opens exactly one socket, shows the **full** match id (no truncation
anywhere), and resets `isGameActive` on every new connection (the §7 regression guard).

## Notes considered and set aside (not findings)

- **REST/WS `error` failures aren't surfaced visually to the user yet** (`postJSON` throws a generic
  message; `routeEvent`'s `error` case only `console.warn`s). Not flagged: there is nowhere to surface
  them *to* — the chat panel (where system/error lines belong per web_ui_spec §6.1) is wired in
  v03.03, not this version. Genuinely out of scope, not an oversight.
- **`openSocket` doesn't explicitly detach the old socket's listeners** before replacing `ws`. Not a
  real leak: listeners are scoped to their own (now-closed, unreferenced) socket object and become
  irrelevant once nothing points to it.

## What's solid
The `no-store` middleware matches the mount exactly (`"/ui"` or `"/ui/…"`), not a loose prefix — a
correctness detail fixed proactively rather than shipped as a known gap; the shell is fully
self-contained (system fonts, no CDN, verified by a served-asset test); the match id is rendered with
`textContent` (no injection risk) and never sliced/substringed; `window.arena` keeps the no-build UI
testable without a real DOM. Zero model calls anywhere.

## Architecture impact
None — §3/§6.2/§8 implemented exactly as documented.
