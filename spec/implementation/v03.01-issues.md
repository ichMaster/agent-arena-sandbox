## v03.01 — Static UI shell & connection

### ARENA-062 — Static mount at /ui with Cache-Control: no-store

**Description:**
`server/main.py`: mount `web/` at `/ui` via `StaticFiles(directory="web", html=True)`, plus
middleware that sets `Cache-Control: no-store` on every `/ui/*` response (architecture.md §3) — so a
UI edit is never masked by browser caching, matching web_ui_specification.md §1's "served fresh"
principle. Non-`/ui` routes are untouched. Touches: `server/`.

**What needs to be done:**
- `app.mount("/ui", StaticFiles(directory="web", html=True), name="ui")`.
- A `@app.middleware("http")` (or equivalent ASGI middleware) that adds `Cache-Control: no-store` to
  the response only when `request.url.path` starts with `/ui`.
- `web/` directory created (even if `index.html`/`styles.css`/`app.js` are stubs at this point —
  ARENA-063/064 fill them in; this issue's own tests only need *some* file present to serve).

**Dependencies:** None

**Expected result:**
`GET /ui/` (and any `/ui/*` asset) responds with `Cache-Control: no-store`; `GET /api/v1/health`
does not gain that header.

**Acceptance criteria:**
- [ ] **Integration test (`TestClient`):** `GET /ui/` returns 200 with `Cache-Control: no-store`.
- [ ] **Integration test:** a non-`/ui` route (`/api/v1/health`) does **not** carry `Cache-Control:
  no-store` (normal caching behavior is untouched).
- [ ] `mypy server` strict-clean.

### ARENA-063 — index.html + styles.css — the arena shell

**Description:**
`web/index.html` + `web/styles.css`: the full static layout per web_ui_specification.md §3–§4 and
[ui_prototype.html](../ui_prototype.html)'s exact design tokens (§2) — app bar (brand, connection
status, lobby buttons), the two-column stage/chat grid (collapsing to one column at `≤860px`), the
3×3 board as real `<button id="cell-0">`…`<button id="cell-8">` elements (inert/disabled — no
interactivity until v03.02), player card placeholders, and the chat panel structure (messages list +
input row, disabled until v03.02/v03.03 wire it up). Dark glassmorphism aesthetic, self-contained
(no CDN fonts/scripts), `system-ui` font stack. Touches: `web/`.

**What needs to be done:**
- `web/styles.css`: the CSS custom properties from web_ui_specification.md §2.1–§2.2 (`--bg-0`,
  `--x`/`--o` colors, glass recipe, radii, motion — incl. `prefers-reduced-motion` handling) and the
  layout rules (§3) mirroring `ui_prototype.html`'s `<style>` block structurally (selectors/classes
  may be copied near-verbatim — it's the committed design source).
- `web/index.html`: the app bar (brand "Agent·Arena" + "tic-tac-toe" tag, a connection-status dot +
  label + match-id span with `word-break: break-all` and a `title` attribute, three lobby buttons:
  Host New Match / Join Match / Observe), the stage section (turn banner, `<div class="board"
  id="board">` containing 9 `<button id="cell-N" class="cell empty" disabled>`, two player-card
  placeholders), and the chat aside (header with a participant count span, `<div id="messages">`,
  a chat form with a text input and Send button, both disabled by default).
- No inline `<script>` logic beyond loading `app.js` (`<script src="app.js" defer></script>`) — all
  behavior lands in ARENA-064.

**Dependencies:** None

**Expected result:**
Opening `/ui/` in a browser shows the full dark-arena layout — app bar, empty board, chat panel —
matching `ui_prototype.html`'s visual design, with every interactive element present but inert
(cells `disabled`, chat input `disabled`) since no WebSocket is open yet.

**Acceptance criteria:**
- [ ] **Integration test:** the served HTML contains the app-bar elements (brand text, a
  connection-status element, three lobby buttons with the documented labels).
- [ ] **Integration test:** the served HTML contains 9 board-cell elements with ids `cell-0`…`cell-8`,
  each `disabled`.
- [ ] **Integration test:** the served HTML contains the chat panel structure (a messages container,
  an input, a submit control).
- [ ] **Integration test:** `styles.css` is served and defines the documented CSS custom properties
  (`--x`, `--o`, `--ok`, `--accent` at minimum — a text-content check, not a rendering check).

### ARENA-064 — app.js — lobby actions, one socket, routeEvent skeleton

**Description:**
`web/app.js`: **Host**/**Join**/**Observe** call the REST lobby then open **one** WebSocket
(web_ui_specification.md §6, §8); a connection-status indicator flips to "Connected" once the socket
opens; `setMatchIdDisplay` shows the **full, untruncated** match id (never shortened — it's the
exact string copied into `agent/agent.py --match-id`); `routeEvent({event, payload})` is stubbed —
one `case` per server event, only storing `mySymbol` from `joined` for now (rendering lands in
v03.02/v03.03). This closes the v03.01 DoD. Touches: `web/`.

**What needs to be done:**
- Module-level state (web_ui_specification.md §7): `ws`, `currentMatchId`, `myToken`,
  `myPlayerName`, `mySymbol`, `isGameActive`.
- `async function hostMatch()`: `POST /api/v1/lobby/match` → `POST /api/v1/lobby/join
  {match_id, player_name, spectator:false}` → `connectWebSocket(matchId, token)`.
- `async function joinMatch(spectator)`: prompt for a Match ID → `POST /api/v1/lobby/join
  {match_id, player_name, spectator}` → `connectWebSocket(matchId, token)`. `Observe` calls this with
  `spectator:true`.
- `function connectWebSocket(matchId, token)`: `new WebSocket(...)`; `onopen` → `setConnectionStatus(true)`
  + `setMatchIdDisplay(matchId)`; `onclose` → `setConnectionStatus(false)`; `onmessage` → `routeEvent(JSON.parse(event.data))`.
- `function setMatchIdDisplay(matchId)`: sets the match-id element's **full** text content (no
  `.slice()`/`.substring()`/truncation of any kind) and its `title` attribute to the same string.
- `function setConnectionStatus(connected)`: toggles the dot/label between the documented states
  (`Connected` / `Disconnected`).
- `function routeEvent({event, payload})`: a `switch`/`if-else` with one case per event
  (`joined`, `state_update`, `chat_message`, `game_over`, `error`); only `joined` does anything this
  issue (`mySymbol = payload.symbol`) — the rest are no-op stubs, explicitly commented as landing in
  v03.02/v03.03.
- Wire the three lobby buttons' click handlers to `hostMatch`/`joinMatch(false)`/`joinMatch(true)`.

**Dependencies:** ARENA-062, ARENA-063

**Expected result:**
Clicking **Host New Match** creates a match, joins as a player, opens a WebSocket, and the status
area shows "Connected" plus the full match id — matching the v03.01 DoD exactly.

**Acceptance criteria:**
- [ ] **Integration test:** the served `app.js` text defines `routeEvent`, `hostMatch`, `joinMatch`,
  `connectWebSocket`, `setMatchIdDisplay`, `setConnectionStatus` (structural presence — no headless
  browser is part of this repo's toolchain, matching the "no build step" constraint; behavior is
  verified by inspecting the served source, consistent with how v01.03 tested served-JS structure).
- [ ] **Integration test:** `setMatchIdDisplay`'s source contains no truncation call (`slice`,
  `substring`, `substr`) applied anywhere near the match-id assignment — the full-id guarantee is a
  static, checkable property of the function body.
- [ ] **Integration test:** `hostMatch`'s source calls `/api/v1/lobby/match` then
  `/api/v1/lobby/join` with `spectator` set to a falsy value (`false`); `joinMatch`'s source threads
  its `spectator` parameter through to the join call.
- [ ] `pytest` green for the whole phase; no `mypy` target (`web/` is JS, not Python).
- [ ] Ties to v03.01 DoD (release gate): opening `/ui`, hosting a match, connecting shows "Connected"
  and the full match id; `/ui/*` responses carry `Cache-Control: no-store`.
