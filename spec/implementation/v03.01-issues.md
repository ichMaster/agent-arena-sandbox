The browser renderer begins: vanilla HTML/CSS/JS, **no build step**, served at `/ui`, holding no
authoritative state. This version ships the page shell + the lobby→REST→one-WebSocket connection +
a stubbed `routeEvent` dispatcher; board/gameplay is v03.02, chat/observer is v03.03. It renders the
same events the agent consumes, so **no server changes beyond the static mount + `no-store`**.

**Reconciliation (generate Step 0.5, against the real implementation):**
- **Wire contract as shipped** (server/websockets.py, verified): envelope `{"event": name,
  "payload": {...}}`; `joined{symbol, board, current_turn, valid_moves}`,
  `state_update{board, current_turn, valid_moves, last_move}`, `chat_message{sender, message}`,
  `game_over{result}`, `error{detail}`; client→server `{action, payload}` — `submit_move{move}`,
  `chat{message}`. The UI's `routeEvent` cases and action senders must use these exact names.
- **REST as shipped** (server/main.py, server/schemas.py): `POST /api/v1/lobby/match → {match_id}`;
  `POST /api/v1/lobby/join {match_id, player_name, spectator} → {token}`. WS at
  `GET /ws/match/{match_id}?token=`.
- **No seam changes.** The static mount + `no-store` middleware are additive server config, not a
  protocol/contract change — `architecture.md` §8/§3 already prescribe them, so no doc edit is
  triggered (the WS event/action shapes §6.2 are untouched).
- **Design tokens** are fixed by `ui_prototype.html` / web_ui_spec §2 (colors, glass recipe, radii,
  motion) — mirror them verbatim as `:root` custom properties.

## v03.01 — Static UI shell & connection

### ARENA-OPUS-SONNET-025 — Serve `/ui` static mount + `no-store` middleware

**Description:** make the server host the Web UI (architecture §3, §8). Mount `web/` at `/ui`
(`html=True` so `/ui/` serves `index.html`) and add middleware that stamps `Cache-Control: no-store`
on `/ui/*` responses so edits are never masked by browser caching. Touches: `server/main.py`,
`web/index.html` (a minimal placeholder so the mount has something to serve), `tests/`.

**What needs to be done:**
- `server/main.py`: `from fastapi.staticfiles import StaticFiles`; in `create_app`, mount
  `application.mount("/ui", StaticFiles(directory="web", html=True), name="ui")` (path resolved from
  the repo root, robust to CWD). Add an `@application.middleware("http")` that, for request paths
  starting `/ui`, sets `response.headers["Cache-Control"] = "no-store"`; other paths untouched.
- `web/index.html`: a minimal valid page (replaced fully in ARENA-OPUS-SONNET-026) so `/ui/` returns 200
  now. Remove `web/.gitkeep`.

**Dependencies:** None (v03 depends on v01's protocol, already shipped).

**Expected result:** `GET /ui/` → 200 HTML with `Cache-Control: no-store`; `/api/v1/health` keeps
normal caching.

**Acceptance criteria:**
- [ ] `/ui/` and `/ui/<asset>` serve from `web/` with `Cache-Control: no-store`.
- [ ] Non-`/ui` routes (e.g. `/api/v1/health`) do **not** get `no-store`.
- [ ] **Integration test** (`TestClient`): `/ui/` is 200 + `no-store`; a served asset carries `no-store`; `/api/v1/health` lacks it. No LLM.
- [ ] mypy (strict) clean; no WS event/action shape changed (no architecture.md edit).
- [ ] Ties to DoD: `/ui/*` responses carry `Cache-Control: no-store`.

### ARENA-OPUS-SONNET-027 — `web/app.js` — lobby → REST → one WebSocket + `routeEvent` skeleton

**Description:** wire the shell to the server (web_ui_spec §6–§8, architecture §8): Host/Join/Observe
call the REST lobby then open **one** WebSocket; a connection-status indicator; `setMatchIdDisplay`
shows the **full** id (never truncated — it's copied into `agent/agent.py --match-id`); a stubbed
`routeEvent({event, payload})` dispatcher. Board/chat rendering are stubs here (filled in v03.02/03).
Touches: `web/app.js`.

**What needs to be done:**
- Client state (§7): `ws`, `currentMatchId`, `myToken`, `myPlayerName`, `mySymbol`, `isGameActive`.
- `hostMatch()` → `POST /lobby/match` → `joinAndConnect(matchId, {spectator:false})`;
  `joinMatch()`/`spectateMatch()` → prompt for a Match ID → `joinAndConnect(id, {spectator})`.
  `joinAndConnect` → `POST /lobby/join {match_id, player_name, spectator}` → open
  `ws://<host>/ws/match/{id}?token=<token>`; **reset `isGameActive = true`** on each new connection
  (§7 regression guard).
- `setConnectionStatus(state, resultText?)`: toggles the dot + `#status-label`
  (`Connected`/`Disconnected`/`Game Over — …`); `setMatchIdDisplay(id)` writes the **full** id +
  sets the element `title`.
- `routeEvent({event, payload})`: a switch over `joined`/`state_update`/`chat_message`/`game_over`/
  `error` with small stub handlers (store `mySymbol` on `joined`; `game_over` → `isGameActive=false`
  + status; others no-op for now) — expanded in v03.02/03.
- Wire the three lobby buttons; guard sends on socket `OPEN`. Expose the entry points on `window`
  (`window.arena = { hostMatch, joinMatch, spectateMatch, routeEvent, setMatchIdDisplay }`) so the
  served-asset tests can assert them without a DOM.

**Dependencies:** ARENA-OPUS-SONNET-025, ARENA-OPUS-SONNET-026.

**Expected result:** opening `/ui`, clicking **Host** connects, shows "Connected" and the full match id.

**Acceptance criteria:**
- [ ] Host → creates a match, joins non-spectator, opens one WS, shows "Connected" + the **full** (untruncated) match id.
- [ ] `routeEvent` has a case per server event (exact names); `game_over` flips `isGameActive=false`; new-match connect resets `isGameActive=true`.
- [ ] **Integration test** (`TestClient` serving the asset): `app.js` exposes `hostMatch`/`joinMatch`/`spectateMatch`/`routeEvent`/`setMatchIdDisplay`; references the real event names and the `/api/v1/lobby/*` + `/ws/match/` endpoints; contains **no** id-truncation (`slice`/`substring` on the match id). No LLM, no paid call.
- [ ] Ties to DoD: hosting a match connects, shows "Connected" + the full match id; one WebSocket opened.
