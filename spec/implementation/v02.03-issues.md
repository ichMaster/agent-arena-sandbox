The agent becomes runnable: `python agent/agent.py --match-id <id> --profile profiles/aggressive.yml`
joins over REST, opens the WS, and on every `joined`/`state_update` where `current_turn == my symbol`
asks the model for one structured `{move, comment}` — validated against `valid_moves`, retried up to
`MAX_MOVE_ATTEMPTS`, falling back to a random legal move — then sends `chat` + `submit_move`. A pure
external client: imports nothing from `server/`; the LLM is **always mocked** in tests.

**Reconciliation (generate Step 0.5, against the real implementation):**
- Wire contracts as actually shipped (v01.03/v01.04): `POST /api/v1/lobby/join {match_id, player_name,
  spectator?} → {token}`; WS `GET /ws/match/{id}?token=` → events `joined{symbol, board, current_turn,
  valid_moves}`, `state_update{board, current_turn, valid_moves, last_move}`, `chat_message`,
  `game_over`, `error`; actions `{action, payload}`. The **terminal `state_update` carries
  `current_turn: null`** — the agent must never act on it.

- **Code-review v01.04 finding #7 lands here as planned:** `.env` loading at agent startup
  (`python-dotenv`) so `ANTHROPIC_API_KEY` can live in the agent's `.env` (§9). Its review-doc status

### ARENA-OPUS-SONNET-022 — Agent CLI: args, `.env` loading & lobby join

**Description:** the runnable entrypoint scaffolding in `agent/agent.py`: arg parsing, environment
loading (`.env` via `python-dotenv`), the REST join, line-buffered stdout, and
the direct-run shim so `python agent/agent.py …` works. Touches: `agent/agent.py`, `pyproject.toml`,
`tests/`.

**What needs to be done:**
- `parse_args`: `--match-id` (required), `--profile` (required), `--server-url` (default
  `http://127.0.0.1:8000`), optional `--player-name` (defaults to the profile's `name`).
- `load_environment(dotenv_path=None) -> str`: `load_dotenv` then the existing fail-fast
  `load_api_key` — the secret stays in the agent process (§9).
- `async join_match(server_url, match_id, player_name, *, client=None) -> str` over `httpx`
  (injectable client for tests); a 404/unknown match surfaces as a clear error.
- Direct-run shim (repo root onto `sys.path` when run as a script) + line-buffered stdout; `main()`
  assembles profile → LLM client → join (the session loop arrives in ARENA-OPUS-SONNET-024).
- `pyproject.toml`: `httpx`, `websockets`, `python-dotenv` as runtime deps.

**Dependencies:** None. **Expected result:** the CLI parses, loads the key from `.env`, and a join
against the real app returns a token.

**Acceptance criteria:**
- [ ] `parse_args` per the roadmap flags; `--player-name` defaults to the profile name.
- [ ] **Unit/integration tests (no paid call):** args happy/missing paths; `.env` → key loaded, missing key aborts clearly; `join_match` returns a token against the **real app** (in-process ASGI transport) and errors clearly on an unknown match.
- [ ] mypy (strict) clean.
- [ ] Ties to DoD: the command-line invocation shape of the release gate.

### ARENA-OPUS-SONNET-023 — `choose_move` — decide → validate → retry → random-legal fallback

**Description:** the §7.1 decision core in `agent/agent.py`: ask the seam for `AgentResponse`,
validate `move ∈ valid_moves`, re-prompt up to `MAX_MOVE_ATTEMPTS`, then fall back to a **random
legal move** rather than stalling the match. Touches: `agent/agent.py`, `tests/`.

**What needs to be done:**
- `MAX_MOVE_ATTEMPTS = 3`; `async choose_move(llm, memory, board, valid_moves, persona) ->
  (move, comment)` using `build_prompt` + `generate_structured_response(prompt, AgentResponse)`.
- An illegal/unparseable/erroring model reply counts as a failed attempt; on exhaustion pick
  `random.choice(valid_moves)` with a neutral in-character comment. Print decisions/retries to stdout
  (read-only observability).

**Dependencies:** None. **Expected result:** always returns a legal move; model failures never stall.

**Acceptance criteria:**
- [ ] **Unit tests (mock `LLMClient`, no paid call):** legal-first-try; illegal→legal retry; all-illegal → fallback ∈ `valid_moves`; model exception → fallback; the comment passes through.
- [ ] mypy (strict) clean. Ties to DoD: "an illegal model move is retried then falls back to a legal one."

### ARENA-OPUS-SONNET-024 — `AgentSession` WS event loop + full-game integration (v02 gate)

**Description:** the §7.1 session over one WebSocket: act **only** when `current_turn == my symbol`
(never on the terminal `state_update` with `current_turn: null`), record opponent moves + chat into
the memory window, send `chat` + `submit_move` per turn, handle `game_over` cleanly; plus the
production `run` loop (`websockets`) and full `main()` wiring. Touches: `agent/agent.py`, `tests/`.

**What needs to be done:**
- `AgentSession(profile, llm, memory)`: `async on_event(event) -> [actions]` — testable transport-free
  core dispatching `joined`/`state_update`/`chat_message`/`game_over`/`error`; opponent
  `last_move` → `record_move`, others' `chat_message` → `record_chat`; my turn → `choose_move` →
  `[chat, submit_move]`; `finished` on `game_over`.
- `run_agent(...)`: join → `websockets.connect(ws://…?token=…)` → dispatch loop → clean exit when the
  room closes; `main()` wires args → env → profile → `create_llm_client` → session.
- **Integration test against the real server** (`TestClient` WS, throwaway DB): a scripted mock
  `LLMClient` (incl. one illegal reply → retry) plays a **full game to `game_over`** vs a scripted
  opponent connection; the agent acts only on its turn and **never** on the terminal `state_update`;
  opponent chat lands in memory; the session finishes cleanly.

**Dependencies:** ARENA-OPUS-SONNET-022, ARENA-OPUS-SONNET-023. **Expected result:** the v02.03 DoD end to end —
the v02 release gate.

**Acceptance criteria:**
- [ ] `on_event` acts only when `current_turn == my symbol`; terminal update triggers nothing; opponent moves/chat recorded; `game_over` sets `finished`.
- [ ] **Integration (LLM mocked, no paid call):** full game to `game_over` vs a second connection incl. the illegal→retry path; model-call count proves no act on the terminal update.
- [ ] mypy (strict) clean. Ties to DoD: the full release-gate scenario.
