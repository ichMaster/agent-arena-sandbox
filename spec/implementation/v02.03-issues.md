## v02.03 — Agent event loop & decision play

### ARENA-058 — CLI entrypoint, line-buffered output & direct-run shim

**Description:**
`agent/agent.py`: argument parsing (`--match-id`, `--profile`, `--server-url`, optional
`--player-name`), `AgentSession.__init__`, and `join_match()` — the REST half of architecture.md
§7.1's flow (`POST /api/v1/lobby/join`). Line-buffers stdout/stderr so redirected logs flush
promptly, and a `if __name__ == "__main__":` shim so `python agent/agent.py …` works directly. The
WS event loop itself is a stub this issue (ARENA-059). Touches: `agent/`, `pyproject.toml`.

**What needs to be done:**
- `pyproject.toml`: move `httpx` from `[project.optional-dependencies].dev` to
  `[project].dependencies` — it's a runtime dependency once the agent makes real REST calls.
- `argparse` in `main(argv: list[str] | None = None) -> None`: `--match-id` (required), `--profile`
  (required, a YAML path), `--server-url` (default `http://127.0.0.1:8000`), `--player-name`
  (optional, defaults to the loaded profile's `name`).
- `AgentSession(server_url, match_id, profile, llm_client, player_name)`: holds a
  `MemoryWindow(maxlen=profile.memory_limit)` and `self.symbol: str | None = None`.
- `async def join_match(self) -> str`: `httpx.AsyncClient().post(f"{server_url}/api/v1/lobby/join",
  json={"match_id": ..., "player_name": ...})`, `raise_for_status()`, returns the token.
- `sys.stdout.reconfigure(line_buffering=True)` / same for `stderr`, at the top of `main()`.
- `main()` wires: load `AgentProfile.load_from_yaml(args.profile)`, read
  `ANTHROPIC_API_KEY` from the environment (fail-fast is already `create_llm_client`'s job, from
  v02.01 — this issue just passes the key through, doesn't re-implement the check), build the
  `LLMClient` via `create_llm_client`, construct `AgentSession`, and (stub this issue)
  `asyncio.run(session.join_match())` only — the real `run()` loop lands in ARENA-059.

**Dependencies:** ARENA-054 (released `LLMClient`/`create_llm_client`), ARENA-057 (released
`AgentProfile`/`build_prompt`)

**Expected result:**
`python agent/agent.py --match-id <id> --profile profiles/aggressive.yml` (against a running server)
joins the match and obtains a token; malformed/missing required CLI args fail with `argparse`'s
standard usage error.

**Acceptance criteria:**
- [ ] **Unit test:** argument parsing accepts the documented flags; a missing `--match-id`/`--profile` exits non-zero (argparse's own behavior, asserted via `SystemExit`).
- [ ] **Unit test:** `join_match` posts the expected REST body and returns the token, against a
  mocked `httpx` transport (`httpx.MockTransport` — no real network).
- [ ] `mypy agent` strict-clean.

### ARENA-059 — `AgentSession` — join, connect, and the event loop

**Description:**
Completes the WS half of `AgentSession`: opens the WebSocket (`websockets.connect`), dispatches each
incoming envelope (`joined`, `state_update`, `chat_message`, `game_over`), acts **only** when
`current_turn == self.symbol` (architecture.md §7.1 — never on the terminal `state_update`, where
`current_turn` is `null`), and records **opponent** moves/chat into the memory window (never its own
— those are recorded proactively when the agent itself acts, avoiding double-recording when the
server echoes its own broadcast back). `decide_move` is a stub this issue (always accepts the
model's first answer, no retry/fallback yet — ARENA-060 completes it). Touches: `agent/`.

**What needs to be done:**
- `async def run(self) -> None`: `join_match()` → `websockets.connect(ws_url)` → `async for raw in
  ws: await self._handle_event(ws, json.loads(raw))`. Exits cleanly (no exception) when the server
  closes the connection (`close_room`, v01.04) — the `websockets` library's `async for` ends
  naturally on a clean server-initiated close.
- `_handle_event`: `joined` → store `self.symbol`; `chat_message` → record into memory if
  `sender != self.player_name`; `state_update` → record `last_move` into memory if its `player !=
  self.symbol`; `game_over` → print the result and return (no further action).
- Turn gate: after handling `joined`/`state_update`, if `payload["current_turn"] == self.symbol`
  (and `self.symbol is not None`), call `_take_turn`.
- `_take_turn(ws, payload)`: builds the prompt (`build_prompt`), calls the stub `decide_move` for
  `(move, comment)`, records its **own** move into memory, sends `{"action": "chat", "payload":
  {"message": comment}}` then `{"action": "submit_move", "payload": {"move": move}}` — chat before
  move, per the §7.1 sequence diagram.

**Dependencies:** ARENA-058

**Expected result:**
An `AgentSession` correctly tracks its own symbol, only acts on its own turn, never acts on the
terminal `state_update`, and accumulates opponent history (not its own) in its memory window.

**Acceptance criteria:**
- [ ] **Unit test:** `_handle_event` with a `state_update` where `current_turn != self.symbol` does
  not call `_take_turn` (no `chat`/`submit_move` sent).
- [ ] **Unit test:** a `state_update` with `current_turn: null` (the terminal case) does not call
  `_take_turn`, even though `self.symbol` is non-null.
- [ ] **Unit test:** an opponent's move (`last_move.player != self.symbol`) is recorded into memory;
  the agent's own echoed move is not recorded a second time.
- [ ] **Unit test:** an opponent's chat is recorded; the agent's own echoed chat is not.
- [ ] `mypy agent` strict-clean.

### ARENA-060 — `decide_move` — retry then random legal fallback

**Description:**
Completes `_take_turn`'s decision step with the real `decide_move`: ask the `LLMClient` for a
structured response; if `AgentResponse.move` isn't in `valid_moves`, re-prompt (same prompt) up to
`MAX_MOVE_ATTEMPTS` total attempts; on exhaustion, fall back to `random.choice(valid_moves)` rather
than stalling the match (architecture.md §7.1). Prints each attempt's reasoning to stdout. Touches:
`agent/`.

**What needs to be done:**
- `MAX_MOVE_ATTEMPTS = 3` (a module constant).
- `async def decide_move(self, prompt: str, valid_moves: list[int]) -> tuple[int, str]`: loop up to
  `MAX_MOVE_ATTEMPTS` calls to `self.llm_client.generate_structured_response(prompt, AgentResponse)`;
  return `(response.move, response.comment)` the first time `response.move in valid_moves`; print an
  attempt-failed line (`flush=True`) on each miss.
- On exhausting all attempts without a legal move: `return random.choice(valid_moves), "..."` (or a
  similarly neutral fallback comment) — never raises, never stalls.
- `_take_turn` calls `decide_move` instead of ARENA-059's stub.

**Dependencies:** ARENA-059

**Expected result:**
Given a mocked `LLMClient` that returns an illegal move once then a legal one, `decide_move` returns
the legal move on the second attempt without falling back; given a client that never returns a legal
move, it falls back to a genuinely valid one after `MAX_MOVE_ATTEMPTS`.

**Acceptance criteria:**
- [ ] **Unit test:** a mocked `LLMClient` returning an illegal move then a legal one → `decide_move`
  returns the legal move, called exactly twice.
- [ ] **Unit test:** a mocked `LLMClient` returning only illegal moves → `decide_move` falls back to
  a `random.choice(valid_moves)` result (asserted to be `in valid_moves`), called exactly
  `MAX_MOVE_ATTEMPTS` times.
- [ ] `mypy agent` strict-clean.

### ARENA-061 — A full game against a real server (v02 release gate)

**Description:**
The integration test the phase's own DoD requires: a **real running server** (a background-thread
`uvicorn` instance over the released `server.main:app`, a throwaway temp-file DB — not FastAPI's
`TestClient`, since the agent is a genuine external client over real HTTP/WS sockets), one real
`AgentSession` (LLM **mocked**, scripted to return one illegal move before a legal one, exercising
ARENA-060's fallback path for real) playing a full game to `game_over` against a second, test-side
WS client. Confirms the process-level exit is clean. This closes the v02.03 DoD and is **the v02
release gate**. Touches: `tests/`.

**What needs to be done:**
- A pytest fixture: start `uvicorn.Server` (bound to `127.0.0.1:0`, port discovered after start) in
  a background thread over `server.main.app` with `dependency_overrides` pointed at a temp-file DB
  (the same pattern as v01.04's WS tests, adapted to a real server rather than `TestClient`); tear
  down (`server.should_exit = True`, join the thread) after the test.
- Create a match + a second ("opponent") participant via real `httpx` REST calls against the live
  server; open a real `websockets` connection for the opponent side, scripted to alternate legal
  moves.
- Construct one real `AgentSession` with a **mocked** `LLMClient` (`generate_structured_response`
  scripted: one illegal move, then legal moves for the rest of the game) and run it
  (`await session.run()`) concurrently (`asyncio.gather`) with the scripted opponent's moves.
- Assert: the game reaches `game_over`; the agent's session coroutine returns cleanly (no exception,
  no hang) once the room closes; the fallback/retry path was genuinely exercised (not just
  unit-tested in isolation) — e.g. by asserting the mocked LLM was called more times than there were
  moves, or by capturing the retry print line.

**Dependencies:** ARENA-060

**Expected result:**
`AgentSession` plays a complete, real game over real sockets against the real (released) server,
survives an illegal model move via retry-then-fallback, and exits cleanly when the match ends.

**Acceptance criteria:**
- [ ] **Integration test:** a full game (mocked `LLMClient`, one scripted illegal move) reaches
  `game_over` against a real running server.
- [ ] **Integration test:** the agent acts only on its own turn and never on the terminal
  `state_update` (already unit-tested in ARENA-059; re-confirmed here end-to-end against real
  timing/ordering, which unit tests can't fully exercise).
- [ ] **Integration test:** the agent process/session exits cleanly (the `run()` coroutine returns,
  no unhandled exception) once the server closes the room.
- [ ] `pytest` green and `mypy agent` strict-clean for the whole phase; the default suite makes
  **no live model call** (LLM mocked throughout, including this integration test).
- [ ] Ties to v02.03 DoD (v02 release gate): `python agent/agent.py --match-id <id> --profile
  profiles/aggressive.yml` joins a match and plays a full game to `game_over` against a second
  connection; an illegal model move is retried then falls back to a legal one; the process exits
  cleanly when the room closes.
