# v02.03 — GitHub Issues

Issues for phase **v02.03 — Agent event loop & decision play** (version **v02 — Agent Client
(Haiku)**), derived from the per-phase Tasks in [roadmap.md](../roadmap.md) (§v02.03) and the
contracts in [architecture.md](../architecture.md) (§7.1 Decision flow).
This file is scoped to a single phase; IDs continue from the previous phase
(ARENA-092 → **ARENA-093…096**).

This phase is the **v02 release gate**: the CLI entrypoint and `AgentSession` that make the
agent an actual playable client — joining a match, waiting for its turn, deciding via the
`LLMClient` seam, and playing to `game_over`. Depends on v02.02 (profile/memory/prompt) and
v01.04 (the WS protocol it speaks). The agent is a **true external client**: it imports nothing
from `server/`, reaching it only over real HTTP/WS — so its own tests need a real server, not
just `TestClient`'s in-process transport.

## v02.03 — Agent event loop & decision play

### ARENA-093 — `agent/agent.py` — CLI args, `join_match`, `AgentSession`, WS connect

**Description:**
The CLI entrypoint and the shell of `AgentSession` (architecture.md §7.1): parse arguments,
join over REST, open the WebSocket, and hold session state. No decision-making yet — this issue
gets the agent connected and receiving events. Touches: `agent/agent.py`, `pyproject.toml`.

**What needs to be done:**
- Add `httpx` and `websockets` as **explicit runtime dependencies** (the agent is a true
  external client — it needs its own HTTP/WS clients, not a transitive pull from `uvicorn`'s
  server-side extras).
- `agent/agent.py`: arg parsing (`argparse` or equivalent) — `--match-id` (required),
  `--profile` (required, path to a YAML file), `--server-url` (default `http://127.0.0.1:8000`),
  `--player-name` (optional, default derived from the profile's `name`).
- `async def join_match(server_url, match_id, player_name, http_client) -> str` (the token) —
  `POST {server_url}/api/v1/lobby/join`.
- `class AgentSession`: holds the profile, the `LLMClient`, a `MemoryWindow`, the WS connection,
  and `my_symbol`. Opens `ws://.../ws/match/{match_id}?token=...` (derive the `ws://` URL from
  `--server-url`), and on the `joined` event stores `my_symbol` from the payload.
- The event loop reads `{event, payload}` messages and dispatches on `event` (a stub dispatcher
  here; ARENA-094/095 fill in the real handling).

**Dependencies:** ARENA-089, ARENA-092

**Expected result:**
Running the agent against a live server joins the named match and receives the `joined` event
with a correctly stored `my_symbol`.

**Acceptance criteria:**
- [ ] `join_match` returns a valid token from a real `POST /lobby/join`.
- [ ] `AgentSession` connects over WS and correctly stores `my_symbol` from `joined`.
- [ ] `mypy --strict agent` passes.

### ARENA-094 — `agent/agent.py` — decision flow: prompt → `LLMClient` → validate → retry/fallback

**Description:**
On every `joined`/`state_update` where `current_turn == my_symbol`, build the prompt, ask the
configured `LLMClient` for a decision, and validate it — retrying on an illegal move up to
`MAX_MOVE_ATTEMPTS`, falling back to a random *legal* move on exhaustion rather than stalling the
match (architecture.md §7.1). Touches: `agent/agent.py`.

**What needs to be done:**
- `MAX_MOVE_ATTEMPTS` constant (small, e.g. 3).
- `AgentSession.decide(board, valid_moves) -> AgentResponse`: `build_prompt(...)` →
  `llm_client.generate_structured_response(prompt, AgentResponse)`; if `response.move not in
  valid_moves`, retry (re-prompting) up to `MAX_MOVE_ATTEMPTS`; on final exhaustion, return an
  `AgentResponse` with a **random legal move** from `valid_moves` and a neutral fallback comment.
- Act **only** when `current_turn == my_symbol` — `joined`/`state_update` where it isn't my turn
  are recorded (into memory, in ARENA-095) but never trigger a decision.
- The terminal `state_update` (`current_turn: null`) must never trigger a decision either — it's
  not "my turn," it's nobody's.

**Dependencies:** ARENA-093

**Expected result:**
Given a scripted `LLMClient` mock, the agent decides only on its own turn, retries an illegal
move, and falls back to a legal one rather than stalling.

**Acceptance criteria:**
- [ ] **Unit test:** a mocked `LLMClient` returning an illegal move is retried, then falls back
      to a random legal move after `MAX_MOVE_ATTEMPTS`.
- [ ] **Unit test:** `decide` is never invoked when `current_turn != my_symbol`, including on the
      terminal `state_update`.
- [ ] `mypy --strict agent` passes.

### ARENA-095 — `agent/agent.py` — chat + `submit_move`, memory recording, `game_over` handling, line-buffered I/O

**Description:**
Close the loop: send the decided move (+ taunt) back to the server, record opponent activity
into the memory window, exit cleanly on `game_over`, and make CLI output usable when redirected
to a log file. Touches: `agent/agent.py`.

**What needs to be done:**
- After `decide()`: send `{action: "chat", payload: {message: response.comment}}` then `{action:
  "submit_move", payload: {move: response.move}}`.
- Record **every** move and chat event (mine and the opponent's) into the session's
  `MemoryWindow`, from `state_update.last_move` and `chat_message` events — not just what I send.
- On `game_over`: print the result, stop the event loop, exit cleanly (exit code 0).
- `print(..., flush=True)` or `sys.stdout.reconfigure(line_buffering=True)` at startup — read-only
  observability that survives being piped/redirected (architecture.md §7.1).
- A direct-run shim: `if __name__ == "__main__": asyncio.run(main())` so `python agent/agent.py
  --match-id ... --profile ...` works standalone.

**Dependencies:** ARENA-094

**Expected result:**
`python agent/agent.py --match-id <id> --profile profiles/aggressive.yml` runs to completion
against a live match, printing its decisions as it goes, and exits cleanly when the game ends.

**Acceptance criteria:**
- [ ] Chat and `submit_move` are both sent after a decision, in that order.
- [ ] Opponent moves/chat are recorded into memory (verified by inspecting the session's
      `MemoryWindow` after a scripted exchange).
- [ ] The process exits cleanly (no hang, no traceback) on `game_over`.
- [ ] `mypy --strict agent` passes.

### ARENA-096 — Full end-to-end integration suite (real server, mocked `LLMClient`) + retry/fallback unit tests

**Description:**
Close out the v02 release gate: a full game, agent CLI against a **real** running server (the
agent imports nothing from `server/` and talks only over HTTP/WS, so its own integration tests
need a real listening server — an in-process `uvicorn.Server` on a random free port, not
`TestClient`'s ASGI transport). The `LLMClient` stays mocked throughout; the default suite makes
no paid API call. Touches: `tests/`.

**What needs to be done:**
- A pytest fixture that starts a real `uvicorn.Server` (the app's own `server.main:app`) on a
  random free port in a background task/thread, yields the base URL, and tears it down cleanly.
- `tests/test_agent_live_game.py`: drive a full game — the agent (with a **mocked**
  `LLMClient`, scripted moves including one illegal move → fallback) against a second raw WS
  client (playing the opponent), to `game_over`. Assert: the agent only acts on its turn, never
  on the terminal `state_update`; the illegal-move-then-fallback path is exercised at least once
  across the game.
- Confirm (and comment, for future readers) that this suite makes **zero** network calls to
  Anthropic — the `LLMClient` seam is mocked, never the real `AnthropicHaikuClient`.
- A live run remains available and opt-in (not part of this suite) — note this in a docstring,
  don't build it here.

**Dependencies:** ARENA-095

**Expected result:**
`python agent/agent.py --match-id <id> --profile profiles/aggressive.yml` joins a match and
plays a full game to `game_over` against a second connection; an illegal model move is retried
then falls back to a legal one; the process exits cleanly when the room closes — all verified
against a real running server, not simulated.

**Acceptance criteria:**
- [ ] **Integration test:** full game to `game_over` against a real server, agent driven by a
      mocked `LLMClient`.
- [ ] Illegal model move → retried → falls back to a legal move (exercised in the live game, not
      only in isolation).
- [ ] The agent acts only on its own turn and never on the terminal `state_update`.
- [ ] The agent process/session exits cleanly when the room closes.
- [ ] `mypy --strict agent` passes; full suite green; zero paid API calls anywhere in the default
      run. **This is the v02 release gate.**
