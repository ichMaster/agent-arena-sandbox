# v02.02 — GitHub Issues

Issues for phase **v02.02 — Profile, persona, memory & prompt** (version **v02 — Agent Client
(Haiku)**), derived from the per-phase Tasks in [roadmap.md](../roadmap.md) (§v02.02) and the
contracts in [architecture.md](../architecture.md) (§7.2 Prompt, memory, profile).
This file is scoped to a single phase; IDs continue from the previous phase
(ARENA-089 → **ARENA-090…092**).

This phase gives the agent an identity: a YAML-loaded persona, a rolling memory of recent
moves/chat, and the prompt builder that composes both with the board state the server pushes.
Because the server pushes full turn state (v01.04), the agent **never round-trips to read
state** — the prompt builder is handed everything it needs. Depends on v02.01 (`AgentResponse`
only; no `LLMClient` dependency here).

## v02.02 — Profile, persona, memory & prompt

### ARENA-090 — `agent/profile.py` — `AgentProfile.load_from_yaml` + `profiles/aggressive.yml`

**Description:**
The Agent Designer surface for the MVP (architecture.md §7.2): `AgentProfile`, loaded from a
YAML file — `name`, `model_type` (→ `create_llm_client`), `temperature`, `system_prompt`
(persona), `memory_limit`. Touches: `agent/profile.py`, `profiles/aggressive.yml`.

**What needs to be done:**
- `agent/profile.py`: `class AgentProfile(BaseModel): name: str; model_type: str; temperature:
  float; system_prompt: str; memory_limit: int` — strictly typed.
- `AgentProfile.load_from_yaml(path: str | Path) -> AgentProfile`: reads the file, parses YAML,
  validates into the model. A missing/malformed file or field raises a clear error (Pydantic's
  `ValidationError`, or a `FileNotFoundError` for a missing path — not a silent default).
- `profiles/aggressive.yml`: a first sample persona (`name: "Aggressor"`, an in-character
  `system_prompt`, a plausible `temperature`/`memory_limit`).
- Add `pyyaml` as a runtime dependency.

**Dependencies:** ARENA-087

**Expected result:**
`AgentProfile.load_from_yaml("profiles/aggressive.yml")` returns a validated profile; a missing
file or a YAML file missing a required field fails clearly, not silently.

**Acceptance criteria:**
- [ ] Loading `profiles/aggressive.yml` returns an `AgentProfile` with all five fields
      populated.
- [ ] A YAML file missing a required field raises a validation error.
- [ ] A nonexistent path raises a clear error (not a default-constructed profile).
- [ ] `mypy --strict agent` passes.

### ARENA-091 — `agent/memory.py` — `MemoryWindow`

**Description:**
A rolling buffer of the last *N* moves and chat messages (architecture.md §7.2), so the prompt
builder can give the model short-term context without unbounded growth. Touches:
`agent/memory.py`.

**What needs to be done:**
- `agent/memory.py`: `class MemoryWindow`, constructed with `maxlen: int`.
- `record_move(player: str, move: Any) -> None` and `record_chat(sender: str, message: str) ->
  None` — both append to the same rolling window (or two windows sharing one eviction bound; the
  implementer's call, but eviction must be observable as "the last N *events*", matching the
  phase DoD).
- `events() -> list[...]` (or equivalent iteration) exposing what's currently retained, oldest
  first, for the prompt builder to consume.
- Eviction: once `maxlen` is reached, the oldest event is dropped as a new one arrives (`collections.deque(maxlen=...)` is the natural implementation).

**Dependencies:** ARENA-087

**Expected result:**
A `MemoryWindow(maxlen=5)` fed 8 events retains exactly the most recent 5, oldest evicted first.

**Acceptance criteria:**
- [ ] Recording fewer than `maxlen` events retains all of them, in order.
- [ ] Recording more than `maxlen` events keeps exactly the most recent `maxlen`, oldest evicted
      first.
- [ ] Both moves and chat contribute to the same eviction bound (a chat flood can evict old
      moves and vice versa — no separate unbounded list for either).
- [ ] `mypy --strict agent` passes.

### ARENA-092 — `agent/prompt.py` — `build_prompt`

**Description:**
Compose persona + memory window + the **pushed** board/valid-moves into one prompt
(architecture.md §7.2) — the only prompt-assembly point in the agent, and the reason the agent
never round-trips to read state: the server already pushed everything this needs. Touches:
`agent/prompt.py`, `tests/`.

**What needs to be done:**
- `agent/prompt.py`: `def build_prompt(memory: MemoryWindow, board: list, valid_moves: list,
  persona: AgentProfile) -> str`.
- The resulting prompt string embeds: the persona's `system_prompt` (or is clearly composed
  alongside it, if the caller sends persona separately as a system message — the implementer's
  call, documented in a docstring), the current board state, the legal moves, and the recent
  memory-window events (moves + chat) in a readable form.
- No model call here — this is pure string assembly, fully unit-testable.

**Dependencies:** ARENA-090, ARENA-091

**Expected result:**
`build_prompt(...)` returns a string that a human could read and understand the game state and
persona from, containing the board, valid moves, and persona content.

**Acceptance criteria:**
- [ ] The returned prompt contains the persona's `system_prompt` content (or the persona is
      otherwise demonstrably part of the composed output, per the docstring's documented
      design).
- [ ] The returned prompt contains a representation of the current board.
- [ ] The returned prompt contains the valid moves.
- [ ] The returned prompt reflects recent memory-window events when present.
- [ ] `mypy --strict agent` passes; full suite green; no model call made.
