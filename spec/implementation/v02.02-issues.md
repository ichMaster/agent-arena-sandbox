# v02.02 — GitHub Issues

Issues for phase **v02.02 — Profile, persona, memory & prompt** (version **v02 — Agent Client
(Haiku)**), derived from the per-phase Tasks in [roadmap.md](../roadmap.md) (§v02.02) and the
contracts in [architecture.md](../architecture.md) (§7.2 Prompt, memory, profile). IDs continue from
v02.01 (ARENA-054) → **ARENA-055…057**.

**Reconciliation (Step 0.5):** v02.01 (`agent/schemas.py`, `agent/llm.py`) is released (tag
v02.01.00); its one code-review fix (whitespace-key handling) recorded no architecture impact. This
phase adds the Agent Designer surface (`AgentProfile`, `MemoryWindow`, the prompt builder) on top —
none of it touches the `LLMClient` seam, so no reconciliation correction is needed.

Builds an agent's identity: a YAML-loaded persona, a rolling memory of recent moves/chat, and the
prompt builder that composes persona + memory + the server-pushed board/valid-moves into one string.
Because the server pushes full turn state (v01.04's `joined`/`state_update`), the agent never
round-trips to read state — the prompt builder's inputs are always handed to it, never fetched.

## v02.02 — Profile, persona, memory & prompt

### ARENA-055 — `AgentProfile` — the persona YAML loader, + the first sample persona

**Description:**
`agent/profile.py`: `AgentProfile` (architecture.md §7.2) — `name`, `model_type`, `temperature`,
`system_prompt`, `memory_limit` — loaded from a YAML file. Ships `profiles/aggressive.yml`, the
first real persona, both as the sample and as this issue's own loader fixture. Touches: `agent/`,
`profiles/`.

**What needs to be done:**
- `class AgentProfile(BaseModel): name: str; model_type: str; temperature: float = 0.7;
  system_prompt: str; memory_limit: int = 10` — `temperature`/`memory_limit` default to sensible
  MVP values; `name`/`model_type`/`system_prompt` are required (no meaningful default).
- `AgentProfile.load_from_yaml(path: str | Path) -> AgentProfile`: read + parse via `yaml.safe_load`,
  validate into the model; a missing file or malformed YAML/schema raises a clear error (not a bare
  `KeyError`/`yaml.YAMLError` leaking past this function).
- `profiles/aggressive.yml`: `name: Aggressor`, `model_type: haiku`, a `temperature` on the higher
  side (e.g. `0.9`), a `system_prompt` establishing a taunting, aggressive persona, `memory_limit:
  10`.

**Dependencies:** None

**Expected result:**
`AgentProfile.load_from_yaml("profiles/aggressive.yml")` returns a fully-populated, validated
profile; a profile YAML omitting `temperature`/`memory_limit` still loads, using the defaults.

**Acceptance criteria:**
- [ ] **Unit test:** loading `profiles/aggressive.yml` produces the expected field values.
- [ ] **Unit test:** a YAML lacking `temperature`/`memory_limit` loads with the documented defaults (`0.7`, `10`).
- [ ] **Unit test:** a YAML missing a required field (`name`/`model_type`/`system_prompt`) raises a clear validation error.
- [ ] `mypy agent` strict-clean.

### ARENA-056 — `MemoryWindow` — a bounded rolling record

**Description:**
`agent/memory.py`: `MemoryWindow` — a fixed-size rolling buffer of recent moves and chat messages,
per architecture.md §7.2 ("a rolling buffer of the last *N* moves and chat messages"). Touches:
`agent/`.

**What needs to be done:**
- `MemoryWindow(maxlen: int)`: wraps a `collections.deque(maxlen=maxlen)`.
- `record_move(player: str, move: object) -> None` / `record_chat(sender: str, message: str) ->
  None`: append a tagged entry (e.g. `{"type": "move", "player": ..., "move": ...}` /
  `{"type": "chat", "sender": ..., "message": ...}`) to the same deque, preserving relative order
  across both kinds of events.
- `entries() -> list[...]` (or an equivalent read accessor) exposing the current window in
  chronological order, for `build_prompt` (ARENA-057) to consume.
- Eviction: once `maxlen` entries are recorded, the oldest entry (move or chat, whichever is
  oldest) is dropped on the next `record_*` call — `deque(maxlen=...)` provides this for free, but
  the test must prove it against a **mixed** sequence of moves and chat, not just one kind.

**Dependencies:** None

**Expected result:**
A `MemoryWindow(maxlen=3)` after 5 recorded events (mixed moves/chat) retains exactly the 3 most
recent, in order.

**Acceptance criteria:**
- [ ] **Unit test:** recording fewer than `maxlen` events keeps all of them, in order.
- [ ] **Unit test:** recording more than `maxlen` events (a mix of moves and chat) evicts the oldest first, regardless of which kind it was.
- [ ] `mypy agent` strict-clean.

### ARENA-057 — `build_prompt` — persona + memory + pushed state

**Description:**
`agent/prompt.py`: `build_prompt(memory, board, valid_moves, persona) -> str` — composes the
persona's `system_prompt`, the memory window's recent history, and the **pushed** board/valid-moves
into one prompt string ready for `LLMClient.generate_structured_response` (architecture.md §7.2).
This closes the v02.02 DoD. Touches: `agent/`.

**What needs to be done:**
- `build_prompt(memory: MemoryWindow, board: list[str | None], valid_moves: list[int], persona:
  AgentProfile) -> str`: a single string embedding, at minimum, the persona's `system_prompt`
  verbatim, a human-readable rendering of `board`, the list of `valid_moves`, and the memory
  window's recent entries (moves + chat) in order.
- No I/O, no state fetch — every input is a parameter, matching §7.2's "the agent never round-trips
  to read state" (the caller, `agent/agent.py` in v02.03, is the one holding the pushed state).

**Dependencies:** ARENA-055, ARENA-056

**Expected result:**
Given a persona, a memory window with some history, a board, and valid moves, `build_prompt`
produces a single string that a human (or the model) can read to understand the persona, what
happened recently, and the current legal decision space.

**Acceptance criteria:**
- [ ] **Unit test:** the produced prompt contains the persona's `system_prompt` text.
- [ ] **Unit test:** the produced prompt reflects the current `board` state (e.g. each occupied
  cell's mark appears, distinguishable from empty cells).
- [ ] **Unit test:** the produced prompt lists the `valid_moves`.
- [ ] **Unit test:** the produced prompt includes memory window entries (a recorded move and a
  recorded chat message both appear).
- [ ] `pytest` green and `mypy agent` strict-clean for the whole phase; **no model call** — this is
  pure string assembly.
- [ ] Ties to v02.02 DoD (release gate): a profile loads from YAML; the memory window keeps the
  last *N* events; the prompt builder produces a persona-driven prompt embedding the current board
  and legal moves.
