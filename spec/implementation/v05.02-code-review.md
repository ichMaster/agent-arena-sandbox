## What was checked (and held up)

- **The observer test's event ordering is race-free by construction, not by luck** — traced it
  step by step: the observer connects and reads its own `joined` *before* either `AgentSession`'s
  event-draining task is even created, so it cannot miss the first move's broadcasts the way an
  earlier version of `test_agent_live_game.py` once did (the exact bug the v03.01 review's
  stale-connection fix addressed) — this test structurally can't reintroduce that class of race
  because the ordering is enforced by the code's own shape, not a timing assumption.
- **Bounded waits everywhere a hang is possible** — both `asyncio.wait_for(asyncio.gather(...),
  timeout=10)` calls and the observer's per-`recv()` timeout mean a stuck turn or a silently
  dropped connection fails the test clearly, rather than hanging the suite.
- **The move-sequence assertion is exact, not just "the game finished"** — `x_moves == expected`
  and `o_moves == expected` against the full five-move sequence, from *each* session's own
  independently-recorded memory, which also indirectly re-confirms both sessions received every
  broadcast (not just the ones addressed to them).
- **Zero-model-call is verified two ways, not just claimed** — by construction (no
  `AnthropicHaikuClient` referenced anywhere in the file) and by assertion (`llm_x.calls == 3`,
  `llm_o.calls == 2` — the exact scripted-response count each side's `decide()` loop actually
  consumed, which would only match if no code path fell through to a real client).
- **The observer's socket closing after `game_over` doesn't race the two agent sessions' own
  cleanup** — by the time the observer sees `game_over`, the server has already broadcast it to
  every connection and is about to (or already did) `close_room()` the whole match, so the
  observer closing its own already-effectively-closed connection is inert, not a source of
  interference with `task_x`/`task_o`'s own draining.
