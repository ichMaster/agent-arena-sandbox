## The two findings worth carrying forward

### 1. `finally` alone does not survive cancellation (ARENA-015)

architecture.md §10 warns that a client-initiated drop can surface as async cancellation
rather than `WebSocketDisconnect`, and concludes that cleanup must live in a `finally`
block. **That is necessary but not sufficient**, and the gap is invisible until it is
exercised: once the task is cancelling, the cleanup's *own* `await`s are cancelled too, so
an inline `await release_seat(...)` never reaches its commit and the seat leaks anyway.

Found by running the suite, not by reading: `test_disconnecting_releases_the_seat` failed
with the next client receiving `O` instead of `X`, and the traceback showed a
`CancelledError` raised from inside the connection pool during teardown.

The release now runs as a **shielded task on a fresh session** — fresh because the
connection's own session is being torn down with the connection.

### 2. A test that passed against broken code (ARENA-015)

The first cancellation test raised `CancelledError` from a stubbed `receive_text`. It
passed against the *unfixed* implementation, because throwing that exception is not the
same as the task cancelling — every later `await` still worked. A second attempt cancelled
the task for real and hung the suite. Both were discarded; the mechanism is now covered
directly and the end-to-end behaviour carries the rest.

Worth recording because it is the failure mode this whole project is about: a green test
that proves nothing.

## Detailed notes

- **ARENA-013** — `broadcast` serialises once (asserted by counting `json.dumps`) and
  prunes a socket that raises mid-send, with the test ordering deliberately
  alive-dead-alive: a naive loop stops at the raise, and every socket after it silently
  stops receiving. The contract test also pins that **no `your_turn` event exists**.
- **ARENA-014** — a structural test walks the Repository's AST and fails on any `.commit`.
  The seat race moved from `session.rollback()` to a **savepoint**: under caller-owned
  transactions a session rollback would have discarded the caller's unrelated work.
  Six existing tests broke, all because they relied on the implicit commit; the commit
  moved to the caller and **no assertion was weakened**.
- **ARENA-016** — the §5.4 order is followed exactly and the report records *why* it is
  ordered so: legality before turn would let a player probe free cells on the opponent's
  turn; turn before seat would leak whose turn it is to someone with no seat. A client
  claiming another symbol in the payload is refused, because the symbol comes from the
  token.
- **ARENA-017** — `game_over` strictly after the terminal `state_update`; observers may
  chat (non-authoritative flavour, §6.2). One ARENA-016 test was rewritten because
  `close_room` made its premise unreachable — a stronger guarantee than the refusal it
  asserted.
