## v03.02 — Board & gameplay (Player role)

### ARENA-OPUS-SONNET-028 — `renderBoard` + player cards + turn highlight (read path)

**Description:** render the game from server events (web_ui_spec §4.2–§4.3, §6.1): `joined` stores the
symbol and initialises the player cards; `joined`/`state_update` re-render the board and the
active-turn highlight. No interaction yet (that's ARENA-OPUS-SONNET-029). Touches: `web/app.js`.

**What needs to be done:**
- `renderBoard(board, currentTurn, validMoves)`: for each `#cell-i`, set the mark (`X`/`O`/empty) and
  the class (`x`/`o`/`empty`); toggle `playable` + the `disabled` attribute by
  `isMyTurn = isGameActive && currentTurn === mySymbol && validMoves.includes(i)` (empty cells only).
- `renderPlayers(currentTurn)`: fill `#card-x`/`#card-o` name+role; the human's card labelled
  "You / Human · Player", the opponent by its display name / "Haiku · Agent"; add `.active` to the
  card whose symbol equals `currentTurn` (neither when `currentTurn` is `null`).
- `renderTurnBanner(currentTurn)`: "Your turn…" vs "Waiting for the opponent…" vs a game-over/idle line.
- `routeEvent`: `joined` → store `mySymbol`, `renderPlayers`, `renderBoard`; `state_update` →
  `renderBoard` + `renderPlayers` + banner. Keep `initPlayerCards(mySymbol)` **null-safe** (Observer).

**Dependencies:** None (extends the shipped v03.01 `routeEvent`).

**Expected result:** joining a match renders the current board, the two player cards, and highlights
whose turn it is — all from server events, no optimistic state.

**Acceptance criteria:**
- [ ] Board reflects `board`; empty cells carry `disabled` **unless** it's the human's turn and the move is legal; marked cells are never interactive.
- [ ] The card matching `current_turn` gets `.active`; none when `current_turn` is `null`.
- [ ] **Integration test** (served asset): `app.js` defines `renderBoard`, `renderPlayers`, and gates interactivity on `currentTurn === mySymbol` (and `isGameActive`); the `joined`/`state_update` cases call the renderers. No LLM.
- [ ] mypy unaffected (no Python change). Ties to DoD: the board renders from server events.

### ARENA-OPUS-SONNET-029 — `handleCellClick` → `submit_move` + `handleGameOver` freeze (write path)

**Description:** make the board playable and end the game cleanly (web_ui_spec §6.2–§6.3, §8): a click
on a playable cell sends `submit_move`; `game_over` freezes the board, highlights the winning line,
and updates status + turn banner. Touches: `web/app.js` (+ `styles.css` if a `.win`/frozen tweak is
needed).

**What needs to be done:**
- `handleCellClick(i)`: ignore unless the socket is `OPEN`, `isGameActive`, and `#cell-i` is a
  playable empty cell on the human's turn; else `sendAction('submit_move', { move: i })`. The board is
  **never** optimistically updated — it re-renders from the resulting `state_update`.
- Attach one click listener per cell (or a delegated board listener) at startup.
- `handleGameOver(result)`: `isGameActive = false`, `renderBoard` with everything disabled, derive +
  mark the winning line (`.win` on the 3 cells whose marks all equal `result`; none on a draw),
  `setConnectionStatus('over', result)`, and set a game-over turn banner. Wire `routeEvent`'s
  `game_over` case to it.
- Confirm a new match in the **same tab** fully resets (board cleared, `isGameActive = true`, cards
  reset) via the existing `joinAndConnect` reset — add a `resetPlayState()` if needed.

**Dependencies:** ARENA-OPUS-SONNET-028.

**Expected result:** a human hosts a match, plays a full game against a v02 agent by clicking on their
turn, and the board freezes with the winning line + result at game over; a second match in the same
tab works without reload.

**Acceptance criteria:**
- [ ] Clicking a playable cell sends `{action:"submit_move", payload:{move:i}}`; off-turn / finished / closed-socket / non-empty clicks are ignored; no optimistic board update.
- [ ] `game_over` freezes the board, marks the winning line (none on draw), and shows the result in status + banner.
- [ ] Starting a new match in the same tab resets play state (no permanently-disabled board — the §7 regression).
- [ ] **Integration test** (served asset): `app.js` defines `handleCellClick` + `handleGameOver`, sends `submit_move` guarded by the OPEN/active/turn checks, and the `game_over` case freezes + derives the win line; a reset path exists for a new match. No LLM, no paid call.
- [ ] Ties to DoD: play a full game in the browser; board freezes at game over; new match without reload.
