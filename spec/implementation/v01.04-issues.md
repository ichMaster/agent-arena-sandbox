# v01.04 — GitHub Issues

Issues for phase **v01.04 — WebSocket protocol & move authority** (version **v01 — Game Core &
Server Foundation**), derived from the per-phase Tasks in [roadmap.md](../roadmap.md) (§v01.04) and
the contracts in [architecture.md](../architecture.md) (§5.3 ConnectionManager, §5.4 Move authority
flow, §6.2 WebSocket protocol, §9 Identity/Authority/Security, §10 Concurrency/State). IDs continue
from v01.03 (ARENA-047) → **ARENA-048…051**.

**Reconciliation (Step 0.5):** v01.01–v01.03 are real, released code (tags through v01.03.00).
Two drifts this phase must resolve against the real implementation rather than a literal reading of
roadmap.md:

1. **Seat assignment already happens at REST join (v01.03, ARENA-047), not at WS connect.**
   architecture.md §6.2 documents the `joined` event as carrying `symbol`, and §5.4 step 1 talks
   about "seats are claimed once at WS connect" — but the *real, released* `POST
   /api/v1/lobby/join` already calls `assign_seat` synchronously for non-spectators
   (`server/main.py`, v01.03.00). Since `Repository.assign_symbol` is idempotent (an
   already-seated token just gets its existing symbol back), this isn't a conflict in practice — the
   WS layer only needs to **read** the already-assigned symbol to populate `joined`, never assign
   one itself. This phase adds a genuine read-only `Repository.seat_of(match_id, token) -> str |
   None`, used both for `joined` and for the move-authority flow.
2. **roadmap.md §v01.04's task list says "submit_move → assign seat → reconstruct game → ..."; architecture.md
   §5.4 step 1 is explicit that the move flow *reads* the seat and "never assigns one... assigning
   here would let the act of submitting a move grant a seat to a client who had none."**
   architecture.md is the contract-stability source for this seam (§5.4 is part of the WS
   protocol's authority rules); this file follows §5.4's precise five-step read-only flow, and
   treats roadmap.md's "assign seat" as informal shorthand for "look up the seat," not a literal
   instruction to call `assign_symbol` from `submit_move`.

Adds the real-time layer: `ConnectionManager`, the `/ws/match/{id}` endpoint, and the full
event/action protocol — the point where the server starts enforcing move legality over a live
connection rather than just persisting state.

## v01.04 — WebSocket protocol & move authority

### ARENA-048 — ConnectionManager & the event/action envelopes

**Description:**
`server/websockets.py`: `ConnectionManager` (architecture.md §5.3) — per-match live sockets, a
`broadcast` that serializes once and prunes dead sockets, `send_to`, `close_room`. Also adds the two
`Repository` read accessors the WS layer needs: `get_participant(token) -> Participant | None` and
`seat_of(match_id, token) -> str | None` (read-only — never assigns). Touches: `server/`.

**What needs to be done:**
- `ConnectionManager._connections: dict[str, list[WebSocket]]`, `_owners: dict[WebSocket, str]`
  (socket → participant_id).
- `async def connect(match_id, ws, participant_id) -> None`: `await ws.accept()`, register in both maps.
- `def disconnect(match_id, ws) -> None`: remove the socket from `_connections`/`_owners`.
  (Seat *release* on disconnect — calling `Repository.release_seat` — is wired in ARENA-049's `finally`
  block, which has the `Repository`/session `ConnectionManager` itself doesn't hold.)
- `async def broadcast(match_id, event: dict) -> None`: serialize the envelope once
  (`{"event": name, "payload": {...}}`), send to every socket for `match_id`, catching a send
  failure per-socket and pruning that socket (via `disconnect`) rather than aborting the loop.
- `async def send_to(ws, event: dict) -> None`: single-socket send, same envelope shape.
- `async def close_room(match_id) -> None`: close every socket registered for `match_id`.
- `Repository.get_participant(token) -> Participant | None`.
- `Repository.seat_of(match_id, token) -> str | None`: `get_participant`, then `None` if missing or
  `match_id` mismatch, else `participant.symbol` — a pure read, no write, no idempotent-assign branch.

**Dependencies:** ARENA-042 (released `Repository`)

**Expected result:**
`ConnectionManager` correctly tracks live sockets per match and broadcasts without one dead socket
blocking delivery to the rest; `seat_of` reports a token's current seat without ever mutating it.

**Acceptance criteria:**
- [ ] **Unit test:** `connect`/`disconnect` correctly add/remove a socket from a match's connection list.
- [ ] **Unit test:** `broadcast` reaches every live socket and prunes one that raises mid-send, without failing the whole call.
- [ ] **Unit test:** `seat_of` returns `None` for an unknown token, `None` for a token in a different match, and the persisted symbol for a real seated participant — and never changes `participant.symbol` as a side effect (verified by calling it on a spectator/unseated token and confirming no symbol gets assigned).
- [ ] `mypy server` strict-clean.

### ARENA-049 — The WS endpoint: token to `joined`, cleanup in `finally`

**Description:**
`server/main.py`: `GET /ws/match/{match_id}?token=` — validates the token against the match (via
`Repository.get_participant` + `server.auth.validate_token`), a bad/missing/mismatched token closes
with code `4001` (architecture.md §6.3, §9). A valid token accepts the connection, registers it with
`ConnectionManager`, and sends the `joined` event (`symbol` from `seat_of`, plus `board`,
`current_turn`, `valid_moves` from `reconstruct_game`). The receive loop itself is a stub this
issue (`chat`/`submit_move` land in ARENA-050/051); cleanup — releasing the seat and deregistering
the socket — runs in a `finally` block so a client-initiated drop (which can surface as async
cancellation with a DB session open, not `WebSocketDisconnect`) is still handled (architecture.md
§10). Touches: `server/`.

**What needs to be done:**
- `@app.websocket("/ws/match/{match_id}")`: read `token` from query params.
- Look up the participant (`repo.get_participant(token)`); `None`, or
  `participant.match_id != match_id` → `await ws.close(code=4001)`, return before `accept()`.
- On a valid token: `await connection_manager.connect(match_id, ws, token)`.
- Build and send `joined`: `symbol = await repo.seat_of(match_id, token)`; `game =
  await repo.reconstruct_game(match_id)`; `current_turn = await repo.current_turn(match_id)`;
  `payload = {"symbol": symbol, "board": game.get_state()["board"], "current_turn": current_turn,
  "valid_moves": game.get_valid_moves()}`.
- `try: <receive loop — a pass-through stub this issue> finally: connection_manager.disconnect(match_id, ws); await repo.release_seat(match_id, token)`.

**Dependencies:** ARENA-048, ARENA-047 (released lobby REST — a match/participant must already exist to connect)

**Expected result:**
Connecting with a valid token (from a prior REST join) receives a correct `joined` event; an
invalid token never completes the handshake; disconnecting releases the seat regardless of how the
loop ended.

**Acceptance criteria:**
- [ ] **Contract test:** the `joined` event's shape (`symbol`, `board`, `current_turn`,
  `valid_moves`) matches architecture.md §6.2.
- [ ] **Integration test:** connect with a valid token (join → connect) receives `joined` with the
  correct symbol; a non-spectator's symbol matches what REST join assigned; a spectator's `joined`
  carries `symbol: null`.
- [ ] **Integration test:** connecting with an unknown/foreign-match token closes with code `4001`
  before any event is sent.
- [ ] **Integration test:** disconnecting (closing the client side) releases the seat — verified by
  reconnecting with a *different* token and confirming it can claim the freed symbol.
- [ ] `mypy server` strict-clean.

### ARENA-050 — `chat`, `game_over` & `close_room`

**Description:**
The `chat` client→server action: persist via `Repository.log_chat` and broadcast `chat_message`
(architecture.md §6.2 — "non-authoritative flavor," no legality check beyond the envelope shape).
Also wires `close_room` into the `game_over` path in preparation for ARENA-051 (which is the only
handler that can actually end a game, but the broadcast+close sequencing is shared plumbing landed
here so ARENA-051 only adds the game-ending *trigger*, not new `ConnectionManager` wiring). Touches:
`server/`.

**What needs to be done:**
- Receive-loop dispatch on the incoming envelope's `action`: `"chat"` → `payload.message` →
  `repo.log_chat(match_id, sender=<this token's participant name or symbol>, message)` →
  `connection_manager.broadcast(match_id, {"event": "chat_message", "payload": {"sender": ...,
  "message": ...}})`.
- Malformed envelopes (missing `action`/`payload`, unknown `action`) → `send_to` this socket an
  `error` event with a `detail` string, **connection stays open** (architecture.md §9 "malformed
  JSON → error event, connection kept").
- A `_end_game(match_id, result)` helper: broadcasts `game_over` (`{"result": ...}`) then calls
  `connection_manager.close_room(match_id)` — implemented now, called by ARENA-051.

**Dependencies:** ARENA-049

**Expected result:**
Chat messages sent by one connected client are persisted and reach every connection in the match,
including the sender; a malformed message produces an `error` without dropping the socket.

**Acceptance criteria:**
- [ ] **Contract test:** `chat_message`'s shape (`sender`, `message`) and the client→server `chat`
  action shape (`{message}`) match architecture.md §6.2.
- [ ] **Integration test:** two connected clients — one sends `chat`, both (including the sender)
  receive `chat_message` with the persisted content.
- [ ] **Integration test:** a malformed envelope (bad JSON, missing `action`) yields an `error` event
  to the sender and the socket remains usable for a subsequent valid message.
- [ ] `mypy server` strict-clean.

### ARENA-051 — `submit_move` — the §5.4 authority flow and its refusals

**Description:**
The `submit_move` action, implementing architecture.md §5.4 **exactly** (read-only seat lookup, per
this phase's reconciliation note): `seat_of` → `error` if no seat; `reconstruct_game` +
`current_turn` → `error` if not this symbol's turn; `apply_move` → `error` if illegal; on success,
`log_move`, then `broadcast(state_update)` (`current_turn: null` if the game just ended), and if the
game ended, mark the match `status="finished"` + `result`, `broadcast(game_over)`, `close_room`.
This is the v01 release gate. Touches: `server/`.

**What needs to be done:**
- Receive-loop dispatch: `"submit_move"` → `payload.move`.
- Step 1: `symbol = await repo.seat_of(match_id, token)`; `None` → `send_to` sender an `error`
  (`"no seat"`), do not reconstruct/apply anything.
- Step 2: `game = await repo.reconstruct_game(match_id)`; `turn = await repo.current_turn(match_id)`;
  `symbol != turn` → `error` (`"not your turn"`).
- Step 3: `game.apply_move(symbol, move)` → `False` → `error` (`"invalid move"`); the game object
  from step 2 is discarded either way (never persisted directly — only the move log is truth).
- Step 4 (only on a `True` apply): `await repo.log_move(match_id, symbol, move)`; re-derive
  `is_game_over = game.is_game_over()` (the same in-memory `game` object, now updated by the
  successful `apply_move` — no second reconstruct needed); if truthy, update the `matches` row's
  `status`/`result` (add a small `Repository.finish_match(match_id, result)` helper if none exists).
- Step 5: `broadcast(state_update)`: `{"board": ..., "current_turn": None if is_game_over else
  <next turn from game.get_state()>, "valid_moves": game.get_valid_moves(), "last_move": {"player":
  symbol, "move": move}}`.
- Step 6: if `is_game_over` → `broadcast(game_over, {"result": is_game_over})` then `close_room`
  (via ARENA-050's `_end_game` helper).

**Dependencies:** ARENA-050

**Expected result:**
Two connected clients play a complete, server-validated game to `game_over` (room then closed);
illegal, out-of-turn, and no-seat moves are refused with `error` and never mutate state; the
terminal `state_update` reports `current_turn: null`.

**Acceptance criteria:**
- [ ] **Contract test:** every server→client event (`state_update`, `game_over`, `error`) and the
  `submit_move` action shape match architecture.md §6.2, pinned alongside ARENA-049/050's contract
  tests in one place.
- [ ] **Integration test:** a real WS end-to-end game — two clients connect, alternate legal moves to
  a win, reach `game_over`, and the room closes (further sends fail/are refused).
- [ ] **Integration test:** a full game reaching a **draw** produces `game_over` with `result: "draw"`.
- [ ] **Integration test:** out-of-turn, illegal (occupied/out-of-range), and no-seat (spectator
  attempting `submit_move`) are each refused via `error`, and none of them changes the board.
- [ ] **Integration test:** the winning move's `state_update` carries `current_turn: null`.
- [ ] `pytest` green and `mypy server` strict-clean for the whole phase.
- [ ] Ties to v01.04 DoD (v01 release gate): two raw WS clients connect to one match, alternate
  server-validated legal moves, exchange chat, and reach `game_over` (room then closed); illegal,
  out-of-turn, and no-seat moves are rejected; the terminal `state_update` reports `current_turn:
  null`.
