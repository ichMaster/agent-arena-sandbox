# v01.04 — GitHub Issues

Issues for phase **v01.04 — WebSocket protocol & move authority** (version **v01 — Game Core &
Server Foundation**), derived from [roadmap.md](../roadmap.md) §v01.04 and
[architecture.md](../architecture.md) §5.3 (ConnectionManager), §5.4 (move authority), §6.2 (the WS
contract), §9 (authority), §10 (concurrency & cleanup), §11. IDs continue from ARENA-012 →
**ARENA-013…017**.

**This is the v01 release gate.** It adds the real-time layer and, with it, the rule the whole design
rests on: the **server is the ultimate authority** — every `submit_move` is re-validated server-side
regardless of what the client claims. Two details are easy to get wrong and expensive to get wrong:
`current_turn` must be **`null` on the game-ending move** so no client acts into a closing room, and
cleanup must run in a **`finally`** block because a client-initiated drop can surface as async
cancellation rather than `WebSocketDisconnect`.

This phase also pays off four deferred findings (v01.02 #4, v01.03 #2/#3/#4) that all converge on
transaction ownership and the `joined` event.

## v01.04 — WebSocket protocol & move authority

### ARENA-013 — `ConnectionManager` & the event/action envelopes

**Description:**
`server/websockets.py` — per-match socket registry and the `{event|action, payload}` envelopes
([architecture.md](../architecture.md) §5.3, §6.2). Touches `server/` only; no endpoint yet.

**What needs to be done:**
- `ConnectionManager` with `_connections: dict[str, list[WebSocket]]` and
  `_owners: dict[WebSocket, str]`; `connect(match_id, ws, participant_id)`,
  `disconnect(match_id, ws)`, `broadcast(match_id, event)`, `send_to(ws, event)`,
  `close_room(match_id)`.
- `broadcast` **serializes the payload once**, then sends to each socket, **pruning any socket that
  raises mid-send** — one dead client must never block delivery to the rest.
- Envelope helpers for the five server→client events and two client→server actions of §6.2.
- **Contract test** pinning every event and action shape.

**Dependencies:** None

**Expected result:** sockets can be registered, broadcast to, pruned and closed, with the wire shapes
pinned.

**Acceptance criteria:**
- [ ] `broadcast` serializes **once** for N sockets — asserted by counting, not by inspection.
- [ ] **A socket that raises mid-send is pruned and the remaining sockets still receive the message**
      — the failing socket must not abort the loop.
- [ ] `disconnect` removes the socket **and** drops its owner entry (no leak of `_owners`).
- [ ] `close_room` closes every socket for that match and leaves no entry behind.
- [ ] Broadcasting to an unknown match is a no-op, not a `KeyError`.
- [ ] **Contract test:** the five events (`joined`, `state_update`, `chat_message`, `game_over`,
      `error`) and two actions (`submit_move`, `chat`) are pinned per §6.2 — this test and
      `spec/architecture.md` change together.
- [ ] `mypy games server agent` clean; `pytest` green. No LLM.

### ARENA-014 — Transaction ownership — callers commit, not the Repository

**Description:**
Move the commit boundary out of `Repository` and into its callers, so a unit of work can span more
than one write. Touches `server/repository.py`, `server/main.py` and the v01.02/v01.03 tests that
assume the old behaviour. **This resolves deferred findings v01.02 #4 and v01.03 #2.**

**What needs to be done:**
- Remove the per-method `commit()` from `Repository`; methods `flush()` where they need an id.
- Callers own the transaction: the REST dependency already wraps requests in `session_scope`, and
  the WS handler will wrap each action.
- Update the v01.02/v01.03 tests that relied on implicit commits.

**Dependencies:** None

**Expected result:** a request or action that fails partway leaves **no** partial writes.

**Acceptance criteria:**
- [ ] **A failure after `add_participant` leaves no participant row** — the orphan-row scenario named
      in v01.03 #2, asserted by forcing a failure mid-request.
- [ ] Logging a move and marking the match finished commit **as one unit** — a failure between them
      persists neither.
- [ ] All existing v01.02/v01.03 behaviour still holds (seat rule, replay, lobby) — the suite is the
      proof, and no test may be weakened to accommodate the change.
- [ ] `mypy games server agent` clean; `pytest` green. No LLM.

### ARENA-015 — The WS endpoint: token → `joined`, cleanup in `finally`

**Description:**
`GET /ws/match/{match_id}?token=` in `server/main.py` ([architecture.md](../architecture.md) §6.2,
§10). Validate the token (**bad token → close `4001`**), register the socket, send `joined`, run the
receive loop, and clean up in a **`finally`** block. **Uses `validate_token`, resolving v01.03 #4.**

**What needs to be done:**
- Validate `token` against the match; missing/invalid/foreign → close **4001** before accepting any
  message.
- `connect`, then send `joined` with `symbol` (`null` for an observer), `board`, `current_turn`,
  `valid_moves`.
- Receive loop dispatching on `action`; unknown/malformed → `error`, never a crash.
- **Cleanup in `finally`** — releases the seat and removes the socket regardless of how the loop
  ended.
- `joined` must let a client distinguish **observer** from **no seat available** (v01.03 #3).

**Dependencies:** ARENA-013, ARENA-014

**Expected result:** a client connects with a valid token, receives `joined`, and disconnecting
releases its seat.

**Acceptance criteria:**
- [ ] A missing, malformed, unknown, or **other-match** token closes with **4001**.
- [ ] A valid token receives `joined` carrying `symbol`, `board`, `current_turn`, `valid_moves`.
- [ ] An observer's `joined` carries `symbol: null` and is **distinguishable from a full match**.
- [ ] **Disconnect releases the seat** so a later client can take it.
- [ ] **Cleanup runs even when the drop surfaces as `CancelledError`**, not only
      `WebSocketDisconnect` — the §10 case that `finally` exists for, asserted by cancelling the task.
- [ ] Malformed JSON / an unknown action yields an `error` event and the connection survives.
- [ ] **Integration test** over a real WebSocket. No LLM.
- [ ] `mypy games server agent` clean; `pytest` green.

### ARENA-016 — `submit_move` — the §5.4 authority flow and its refusals

**Description:**
The heart of v01: every move re-validated server-side, in the exact order of §5.4. Touches
`server/websockets.py` / `server/main.py` handlers. **The server is the ultimate authority — client
claims are never trusted.**

**What needs to be done:**
- The §5.4 flow in order: seat → reconstruct → turn check → `apply_move` → persist → broadcast.
- Refusals as `error` events with a `detail`: no seat / observer, not your turn, invalid move.
- Persist the move, and when the game ends set `status="finished"` + `result` **in the same
  transaction** (ARENA-014).
- Broadcast `state_update` with `board`, `current_turn`, `valid_moves`, `last_move` —
  **`current_turn: null` when that move ended the game**.

**Dependencies:** ARENA-015

**Expected result:** two clients alternate legal moves to a finished game; every illegal attempt is
refused without corrupting state.

**Acceptance criteria:**
- [ ] A move from a client with **no seat** (and from an **observer**) is refused with `error`.
- [ ] An **out-of-turn** move is refused — including when the client claims another symbol, since the
      server derives the symbol from the token and never from the message.
- [ ] An **illegal** move (occupied, out of range, wrong type) is refused with `error`.
- [ ] **A refused move writes nothing** — no `moves` row, and the next legal move still succeeds.
- [ ] `state_update` carries **`current_turn: null` on the game-ending move**.
- [ ] The move payload reaches `apply_move` **unexamined** by the transport layer.
- [ ] **Integration test** over real WebSockets: a full game to a win, and to a draw. No LLM.
- [ ] `mypy games server agent` clean; `pytest` green.

### ARENA-017 — `chat`, `game_over` & `close_room`

**Description:**
Complete the protocol: chat persisted and broadcast, `game_over` announced, and the room closed.
Closes the phase DoD and the v01 release gate.

**What needs to be done:**
- `chat` action → `log_chat` → broadcast `chat_message{sender, message}` (non-authoritative flavour).
- On game over: broadcast `game_over{result}` **after** the terminal `state_update`, then
  `close_room`.
- Chat is refused or allowed per role consistently with the seat rule.

**Dependencies:** ARENA-016

**Expected result:** two raw WS clients play a full game with chat, reach `game_over`, and the room
closes.

**Acceptance criteria:**
- [ ] A `chat` action is persisted and broadcast to **every** socket in the match, sender included.
- [ ] `game_over` carries `result` (`X`/`O`/`draw`) and arrives **after** the final `state_update`,
      so no client sees the result before the board that produced it.
- [ ] **`close_room` closes every socket** once the game ends; a later send is refused, not silently
      dropped.
- [ ] An empty or overlong chat message is refused without killing the connection.
- [ ] **Integration test:** two raw WS clients connect → alternate moves → chat → `game_over` → room
      closed. Also a draw. **This is the v01 release gate.** No LLM.
- [ ] `mypy games server agent` clean; `pytest` green.

## v01.04 scope notes

**Total effort:** ~15–22 days across 5 issues (M, M, M, L, M).
**Critical path:** ARENA-013/014 (parallel) → ARENA-015 → ARENA-016 → ARENA-017.
**Phase DoD (roadmap §v01.04):** two raw WS clients connect to one match, alternate server-validated
legal moves, exchange chat, and reach `game_over` (room then closed); illegal, out-of-turn and
no-seat moves are rejected; the terminal `state_update` reports `current_turn: null`. **This is the
v01 release gate.**
**Contracts pinned this phase:** the WebSocket event/action shapes (§6.2), pinned by ARENA-013's
contract test. A change to them updates `spec/architecture.md` in the same commit.

**Reconciliation note (Step 0.5).** Read against the real v01.03 code and its
[code review](v01.03-code-review.md):

- **`Repository.turn_of(game)`** answers the turn from an already-reconstructed game (v01.03 fix #1,
  commit `486b57e`). The broadcast path must use it: it reconstructs once per move and then
  serialises to every socket, so calling `current_turn(match_id)` per socket would reintroduce
  exactly the redundancy that fix removed.
- **`claim_seat` returns `None` for every refusal** — observer, match full, unknown token, lost race
  (v01.02 #2). ARENA-016 step 1 needs no exception handling; `None` is the single no-seat answer.
- **`Repository.current_turn`/`turn_of` raise `NotImplementedError`** for a game with no turn rule
  (v01.02 #1). That is a programming error, not a runtime condition — handlers must **not** catch it
  and turn it into an `error` event.
- **Deferred findings landing here:** v01.02 #4 and v01.03 #2 (transaction ownership) → ARENA-014;
  v01.03 #3 (`joined` must distinguish observer from full) → ARENA-015; v01.03 #4 (`validate_token`
  unused) → ARENA-015.
- `MatchView` already carries exactly what `joined`/`state_update` need — reuse it rather than
  assembling the payload a second way.

**Model note:** no model in this phase. The `LLMClient` seam arrives in v02.01 and is always mocked —
**no paid APIs**, ever.
