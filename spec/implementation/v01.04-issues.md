## v01.04 — WebSocket protocol & move authority

### ARENA-083 — `server/websockets.py` — `ConnectionManager` + event/action envelopes

**Description:**
The connection registry and the wire envelopes, per architecture.md §5.3 and §6.2 (**first pin of
the WS seam** — the doc already specifies the exact shapes; this issue is where they're pinned in
code via a contract test). Touches: `server/websockets.py`, `tests/`.

**What needs to be done:**
- `server/websockets.py`: `class ConnectionManager` with `_connections: dict[str, list[WebSocket]]`
  (`match_id -> sockets`) and `_owners: dict[WebSocket, str]` (`socket -> participant_id`).
- `async def connect(match_id, ws, participant_id) -> None` — accepts the socket, registers it in
  both maps.
- `def disconnect(match_id, ws) -> None` — removes the socket from both maps **and releases its
  seat** (calls `Repository.release_seat` via an injected repo/session — the seat-release side
  effect is part of this method's contract, not left to the caller).
- `async def broadcast(match_id, event) -> None` — serializes the payload **once**, sends to every
  socket in the match, and **prunes** (removes from both maps) any socket that raises mid-send,
  without aborting delivery to the rest.
- `async def send_to(ws, event) -> None`.
- `async def close_room(match_id) -> None` — closes every socket in a finished match.
- Envelope helpers: server→client `{"event": <name>, "payload": {...}}`; client→server
  `{"action": <name>, "payload": {...}}` — pin the five events (`joined`, `state_update`,
  `chat_message`, `game_over`, `error`) and two actions (`submit_move`, `chat`) from
  architecture.md §6.2's tables.

**Dependencies:** ARENA-077

**Expected result:**
`ConnectionManager` correctly tracks live sockets per match, broadcasts without one dead socket
blocking the rest, and the envelope shapes match architecture.md §6.2 exactly.

**Acceptance criteria:**
- [ ] `connect`/`disconnect` correctly maintain both maps; `disconnect` releases the seat.
- [ ] `broadcast` reaches every live socket in a match and **prunes** a socket that raises
      mid-send, still delivering to the others.
- [ ] **Contract test:** the exact server→client event names/payload keys and client→server action
      names/payload keys, pinned here — must change in the same commit as any future protocol
      change.
- [ ] `mypy --strict server` passes.

### ARENA-084 — WS endpoint — token validation, connect, `joined`, receive loop, `finally` cleanup

**Description:**
`GET /ws/match/{match_id}?token=` in `server/main.py`: validates the token, accepts the connection,
sends `joined`, runs the receive loop, and cleans up in a `finally` block — because a
client-initiated drop with a DB session open can surface as async cancellation rather than
`WebSocketDisconnect` (architecture.md §10). Touches: `server/main.py`.

**What needs to be done:**
- `GET /ws/match/{match_id}` accepting `token` as a query param.
- Validate via `validate_token`/`Repository.get_participant`; **invalid/unknown token → close with
  code `4001`** before accepting further messages.
- On valid token: `ConnectionManager.connect(...)`, then send `joined` with `symbol` (from
  `assign_symbol` — `None` for a spectator), `board`, `current_turn`, `valid_moves` (all derived via
  `Repository.reconstruct_game`/`current_turn`).
- The receive loop: read `{action, payload}` JSON; malformed JSON → `error` event, **connection
  kept** (not closed).
- **Cleanup in a `finally` block**: `ConnectionManager.disconnect(...)` runs regardless of whether
  the loop exited via `WebSocketDisconnect` or any other exception/cancellation.
- Action dispatch is a stub in this issue (routes to handlers added in ARENA-085/086); an unknown
  action name → `error` event.

**Dependencies:** ARENA-083, ARENA-081

**Expected result:**
A raw WS client with a valid token connects, immediately receives `joined` with correct initial
state; a bad token gets closed `4001`; a dropped connection always releases its seat.

**Acceptance criteria:**
- [ ] Bad/unknown token → WS close code `4001`, no `joined` sent.
- [ ] Valid token → `joined` event with correct `symbol`/`board`/`current_turn`/`valid_moves`.
- [ ] Malformed JSON on the socket → `error` event, connection stays open.
- [ ] Disconnect (client-initiated close) runs cleanup via `finally` and releases the seat.
- [ ] `mypy --strict server` passes.

### ARENA-085 — `chat` action handler — persist + broadcast `chat_message`

**Description:**
Wire the `chat` action: persist via `Repository.log_chat`, then broadcast `chat_message` to
everyone in the room (architecture.md §6.2 — non-authoritative flavor, never affects move legality).
Touches: `server/main.py`.

**What needs to be done:**
- `{action: "chat", payload: {message}}` → `Repository.log_chat(match_id, sender, message)` (sender
  resolved from the connection's participant) → `ConnectionManager.broadcast(match_id,
  {"event": "chat_message", "payload": {"sender": ..., "message": ...}})`.
- Both players and observers **receive** chat; only seated participants may **send** it in the MVP
  (an observer attempting to chat is out of this phase's scope per game_specification.md §3.3 — note
  it, don't block it defensively here unless trivial).

**Dependencies:** ARENA-084

**Expected result:**
A chat message sent by one connection is persisted and broadcast to every connection in the match.

**Acceptance criteria:**
- [ ] `chat` action persists a `chat_messages` row and broadcasts `chat_message` to all sockets in
      the room, including the sender.
- [ ] `mypy --strict server` passes.

### ARENA-086 — `submit_move` handler — the full move authority flow, and the end-to-end test suite

**Description:**
Wire `submit_move` through the exact §5.4 authority flow, and close out the v01 release gate with
the end-to-end WS test suite. Touches: `server/main.py`, `tests/`.

**What needs to be done:**
- `{action: "submit_move", payload: {move}}` →
  1. `symbol = repo.seat_of(...)` (via `get_participant`) — `None` → `error` ("no seat").
  2. `reconstruct_game`; `symbol != current_turn` → `error` ("not your turn").
  3. `game.apply_move(symbol, move)` → `False` → `error` ("invalid move").
  4. persist `log_move`; if `is_game_over()` now truthy, mark the match finished.
  5. `broadcast(state_update)` with `current_turn: null` if the game just ended.
  6. if ended → `broadcast(game_over)` then `close_room`.
- **`current_turn` in `state_update` is `null` on the game-ending move** — no client should treat it
  as an invitation to act into a closing room.

**Dependencies:** ARENA-084, ARENA-085

**Expected result:**
Two raw WS clients connect to one match, alternate server-validated legal moves, exchange chat, and
reach `game_over` with the room closed; illegal/out-of-turn/no-seat moves are rejected via `error`.

**Acceptance criteria:**
- [ ] **Integration test:** a real WS end-to-end game — connect both clients, alternate legal moves
      to a win, exchange chat mid-game, reach `game_over`, confirm the room is closed afterward.
- [ ] A second end-to-end game reaching a **draw** (both `game_over.result == "draw"` and terminal
      `current_turn: null`).
- [ ] Out-of-turn move → `error`, game state unchanged.
- [ ] Illegal move (occupied/out-of-range) → `error`, game state unchanged.
- [ ] A no-seat connection (spectator) submitting a move → `error`, never mutates state.
- [ ] Terminal `state_update` reports `current_turn: null` on the winning move.
- [ ] `mypy --strict server` passes; full suite green. **This is the v01 release gate — the DoD
      above must hold end to end.**
