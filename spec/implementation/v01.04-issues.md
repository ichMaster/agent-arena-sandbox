(`current_turn == your symbol`), and `current_turn` is **`null` on the game-ending move**. It builds
on the v01.03 lobby (tokens, seats). No model is involved.

## v01.04 — WebSocket protocol & move authority

### ARENA-OPUS-SONNET-012 — `ConnectionManager`, WS envelopes & the event/action protocol

**Description:**
`server/websockets.py` — the whole WS protocol layer as a **pure, DB-free** unit: the
`ConnectionManager` (per-match sockets + owner map), the `{event|action, payload}` envelopes, and
the pure builders for the five server→client events. This is the gate that **pins the §6.2 wire
seam**. Touches: `server/websockets.py`, `tests/`.

**What needs to be done:**
- `ConnectionManager` (§5.3): `_connections: dict[str, list[WebSocket]]`, `_owners: dict[WebSocket, str]`; `async connect(match_id, ws, participant_id)` (accept + register), `disconnect(match_id, ws) -> str | None` (remove socket + owner, return the participant_id so the endpoint can release the seat), `async broadcast(match_id, event)` (**serialize once**, send to each, prune a socket that raises mid-send so delivery continues), `async send_to(ws, event)`, `async close_room(match_id)` (close every socket in a finished match).
- Envelope + event builders (§6.2), pure functions returning `{"event": ..., "payload": {...}}`: `joined{symbol, board, current_turn, valid_moves}`, `state_update{board, current_turn, valid_moves, last_move}`, `chat_message{sender, message}`, `game_over{result}`, `error{detail}`; plus parsing an inbound `{action, payload}`.
- Keep it DB-free — data comes in as arguments (the endpoint/handlers gather it).

**Dependencies:** None (v01.04 depends on v01.03, already released).

**Expected result:**
A pure socket registry + serialize-once/prune broadcast, and pinned builders for every server→client event and the client→server action envelope.

**Acceptance criteria:**
- [ ] `ConnectionManager` registers/removes sockets and owners; `broadcast` serializes once and still delivers to healthy sockets when one raises (pruning the dead one); `close_room` closes all; `send_to` sends to one.
- [ ] **Contract test:** every server→client event shape (`joined`/`state_update`/`chat_message`/`game_over`/`error`) and the client→server `{action, payload}` envelope are pinned (§6.2). *(Protocol implemented as documented — no architecture change.)*
- [ ] **Unit test:** ConnectionManager behavior with fake WebSocket doubles (connect/disconnect/broadcast-prune/close_room) — no DB, no LLM, no paid call.
- [ ] mypy (strict) clean on `server/websockets.py`.
- [ ] Ties to DoD: the socket hub + wire shapes the endpoint and handlers use.

### ARENA-OPUS-SONNET-013 — WS endpoint — connect, token auth, `joined` & `finally` cleanup

**Description:**
`server/main.py` — `GET /ws/match/{match_id}?token=`: validate the token (bad → close `4001`),
`connect`, claim/report the seat, send the `joined` event, run the receive-loop dispatch skeleton,
and **clean up in a `finally`** (disconnect + release the seat, §10). Touches: `server/main.py`,
`tests/`.

**What needs to be done:**
- The WS route: `validate_token(repo, match_id, token)` → `None` closes with code **`4001`**; else `ConnectionManager.connect`.
- Claim/report the seat: `match.assign_symbol(session_maker, match_id, token)` (idempotent; `None` for a spectator) → send `joined{symbol, board, current_turn, valid_moves}` (state derived from `reconstruct_game`/`current_turn`).
- Receive loop that reads `{action, payload}` and dispatches (handlers land in 014/015); a small helper builds the current state payload for `joined`/`state_update`.
- **`finally` block:** `disconnect` the socket and `release_seat` for its owner — runs regardless of how the loop ended (§10).

**Dependencies:** ARENA-OPUS-SONNET-012

**Expected result:**
A valid token connects and receives `joined` with its symbol and the live board; a bad token is closed with `4001`; leaving the socket releases the seat.

**Acceptance criteria:**
- [ ] `GET /ws/match/{id}?token=` validates the token; a missing/invalid token closes with **`4001`**; a valid one connects and receives a single `joined` with `symbol` (X/O/`null` observer), `board`, `current_turn`, `valid_moves`.
- [ ] Cleanup runs in a **`finally`** block: the socket is removed and the seat released.
- [ ] **Integration test** (`TestClient.websocket_connect`, throwaway DB): valid token → `joined` with the expected symbol; bad token → close `4001`; disconnect releases the seat (a later connection can reclaim it). No LLM, no paid call.
- [ ] mypy (strict) clean on the endpoint code.
- [ ] Ties to DoD: the connection lifecycle two clients use to join one match.

### ARENA-OPUS-SONNET-014 — `chat` action → `chat_message` broadcast

**Description:**
The `chat` handler on the WS receive loop: persist the message (`log_chat`) and broadcast a
`chat_message` to everyone in the room (§3.5, §6.2). Chat is non-authoritative flavor. Touches:
`server/main.py`, `tests/`.

**What needs to be done:**
- Handle inbound `{action: "chat", payload: {message}}`: `Repository.log_chat(match_id, sender, message)`, then `ConnectionManager.broadcast(match_id, chat_message{sender, message})`.
- Sender label is the connection's symbol/name (whatever the join recorded); chat never affects game state.

**Dependencies:** ARENA-OPUS-SONNET-013

**Expected result:**
A chat action from one connection is persisted and delivered as a `chat_message` to every socket in the match.

**Acceptance criteria:**
- [ ] A `chat` action persists the message and broadcasts a `chat_message{sender, message}` to all connections in the room.
- [ ] **Integration test** (two `TestClient` WS connections, throwaway DB): one sends `chat`, both receive the `chat_message`; the message is persisted. No LLM, no paid call.
- [ ] mypy (strict) clean.
- [ ] Ties to DoD: two clients exchange chat during a match.

### ARENA-OPUS-SONNET-015 — `submit_move` authority flow + `game_over` / `close_room`

**Description:**
The heart of the phase — the §5.4 server-side move authority on the `submit_move` action, plus the
game-over path. Every move is re-validated server-side; illegal / out-of-turn / no-seat moves are
rejected with an `error`. Touches: `server/main.py`, `server/repository.py` (a `finish_match`
helper), `tests/`.

**What needs to be done:**
- `submit_move` per §5.4: (1) `assign_symbol` → `None` → `error` ("no seat"/observer); (2) `reconstruct_game` + `current_turn`, `symbol != current_turn` → `error` ("not your turn"); (3) `apply_move(symbol, move)` `False` → `error` ("invalid move"); (4) `log_move`, and if `is_game_over()` is now truthy update the match row (`status="finished"`, `result`) via a new `Repository.finish_match`; (5) `broadcast(state_update)` with **`current_turn: null` if the game just ended** and `last_move`; (6) if ended → `broadcast(game_over{result})` then `close_room`.
- Reject out-of-turn / illegal / no-seat moves with an `error` event **to the offending client**, without corrupting state.

**Dependencies:** ARENA-OPUS-SONNET-013

**Expected result:**
Two clients alternate server-validated legal moves to a win or a draw; the terminal `state_update` reports `current_turn: null`, then `game_over` is broadcast and the room closed; illegal/out-of-turn/no-seat moves are rejected.

**Acceptance criteria:**
- [ ] The §5.4 flow is enforced server-side: no-seat/observer, out-of-turn, and illegal moves each yield an `error` and do not change state; a legal move persists and broadcasts a `state_update` with `last_move`.
- [ ] On the game-ending move the `state_update` carries **`current_turn: null`**, then `game_over{result}` is broadcast and the room is closed (`close_room`); the match row is `finished` with the `result`.
- [ ] **Integration test** (two WS connections, throwaway DB): a full game to a **win** and to a **draw**; out-of-turn / illegal / no-seat rejections; `current_turn: null` on the winning move; room closed after `game_over`. No LLM, no paid call.
- [ ] mypy (strict) clean on the handler + `Repository.finish_match`.
- [ ] Ties to DoD: two raw WS clients play a full server-validated game to `game_over`; illegal/out-of-turn/no-seat rejected; terminal `current_turn: null`.

> **⟳ Reconciled (2026-07-21, discovered during ARENA-OPUS-SONNET-013 execution):** this note
> originally also deferred "reconnect-reclaim" and "the cancellation-vs-`WebSocketDisconnect` path"
> to v05.01 — but ARENA-OPUS-SONNET-013's own acceptance criteria require "disconnect releases the
> seat (a later connection can reclaim it)" as a passing integration test **now**. Empirically, a
> `TestClient` websocket-context exit surfaces as **task cancellation**, not a clean
> `WebSocketDisconnect` — and an un-shielded `finally: await release_seat(...)` gets interrupted by
> that same cancellation mid-commit, leaking the seat (reproduced deterministically 5/5). §10 already
> states cleanup must be reliable "regardless of how the loop ended," which a cancellable `finally`
> does not satisfy — so this is core to *this* issue's own §10 scope, not new work. **Fix:** wrap the
> release in `asyncio.shield(...)`. What genuinely stays v05.01 scope is the *dedicated, broader*
> resilience test suite (malformed JSON, the full disconnect/reconnect integration sweep) — not this
> basic shielding, which ARENA-OPUS-SONNET-013 needed to pass its own stated criteria.
