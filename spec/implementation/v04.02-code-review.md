# Code Review & Fix Recommendations — v04.02 (arena orchestration script, v04 release gate)

**Date:** 2026-07-21 · **Reviewer:** Claude Sonnet 5, via `/ship-solution`
**Scope:** `scripts/run_arena.sh` and its static tests.
**Method:** manual adversarial read (shell semantics: quoting, `set -euo pipefail` interaction with
command substitution and backgrounded processes, trap/signal behavior, injection surface); concrete
failure scenario per finding.

## Recommendation summary

*No findings.* The script is defensively written: every variable expansion that can contain a value
(match id, profile paths) is double-quoted, `set -euo pipefail` makes a failed `curl`/JSON-parse abort
immediately rather than proceeding with an empty match id, and the wait-for-agent-1 loop has an
explicit liveness check (not just a log-content poll) so a crashed agent 1 fails fast instead of
looping the full 10s timeout.

## Notes considered and set aside (not findings)

- **`cleanup()` can run twice on Ctrl-C** (once for the `INT` trap, once more for the `EXIT` trap that
  fires as the script naturally ends afterward). Not a bug: both the `kill -0` guard and `rm -f` are
  idempotent, so a second invocation is a no-op, not a double-kill/double-delete error. This is the
  standard, intentionally-idempotent belt-and-suspenders trap pattern, not an oversight.
- **Agent 2 has no join-liveness check of its own** (only agent 1's join is awaited/verified before
  launch). Considered and left as scope: the point of `tail -f` is that a human is watching both logs
  live, so an agent-2 failure (a bad profile, a startup crash) surfaces immediately in the tailed
  output — the acceptance criteria (and the DoD) only require agent 1 → agent 2 *ordering* for
  deterministic seats, not a symmetric liveness contract for both.
- **A malicious/compromised server could return a crafted `match_id`.** Not exploitable here: the
  script only ever uses it as a quoted argument to `agent/agent.py`, never in `eval` or an unquoted
  shell context; and it's the local-first dev server this repo itself runs (architecture.md §12), not
  an untrusted third party.

## What's solid
`MATCH_ID` and both profile paths are always `"$quoted"` at every use site — no word-splitting/glob
surface. `set -euo pipefail` combined with using command substitution in an *assignment*
(`MATCH_JSON="$(curl -sf …)"`, `MATCH_ID="$(… | "$PYTHON" -c …)"`) means a failed `curl` or invalid
JSON aborts the script immediately rather than limping forward with an empty match id — verified by
reading bash's documented `set -e`-in-assignment semantics, not assumed. The `PYTHON` fallback
(`.venv/bin/python` → `python3`) and the repo-root `cd` match the reconciled issue's shipped-CLI
assumptions exactly (no `--symbol` flag exists; ordering is the only lever). Zero paid calls in the
test suite — the script's real Haiku calls only happen in an actual demo run, never under test.

## Architecture impact
None — a new operator script over already-shipped, already-pinned surfaces (the lobby REST, the agent
CLI); no seam, event, or contract changed.
