## Findings

### 1. 🟡 LOW — Trailing slash in `SERVER_URL` breaks the health check

**File:** `scripts/run_arena.sh:32,39` (`SERVER_URL`, the health-check `curl`)

**Failure scenario:** `SERVER_URL` is used as `"${SERVER_URL}/api/v1/health"` with no
normalization. A URL copied from a browser address bar often carries a trailing slash (e.g.
`http://127.0.0.1:8000/`); with one, the health check requests
`http://127.0.0.1:8000//api/v1/health` (a double slash), which does not match the real route and
the check reports "server not reachable" even though the server is running fine. For the one
script whose entire job is a good first impression of the release-gate demo, a URL-formatting
habit as ordinary as a trailing slash producing a wrong, discouraging error is a real (if minor)
rough edge.

**Why LOW, not MEDIUM/HIGH:** only triggers when a user overrides `SERVER_URL` with a trailing
slash (the documented default has none); the failure mode is a clear, recoverable error message,
not silent corruption or a security concern.

**Proposed fix:** strip a trailing slash from `SERVER_URL` once, right after reading it
(`SERVER_URL="${SERVER_URL%/}"`), so every URL built from it downstream is well-formed regardless
of how the user supplied it.
