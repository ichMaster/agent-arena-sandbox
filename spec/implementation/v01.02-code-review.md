## Findings

### 1. 🟠 MEDIUM — `current_turn` answers `None` for any game that is not TicTacToe

**Anchor:** [server/repository.py](../../server/repository.py) — `current_turn`

```python
game = await self.reconstruct_game(match_id)
return game.current_player if isinstance(game, TicTacToe) else None
```

**Failure scenario.** `reconstruct_game` is typed to return a `GameInterface` — the seam whose entire
purpose is that *"new games are new modules"* (§4.1). `current_player` is not part of that seam; it is
a `TicTacToe` convenience. So the `isinstance` narrowing is doing real work, and its `else` branch
returns `None`.

`None` from `current_turn` already means something specific and load-bearing: **the game is over**
(§6.2). So the moment a second game module is added, every match of that game reports "nobody is to
move" from the first turn. In v01.04 that becomes a `state_update` with `current_turn: null`, which
is precisely the signal telling clients *not to act* — so the game would appear frozen at move one,
with no error anywhere, in the server, the agent, or the UI.

The bug is not reachable today (TicTacToe is the only implementation). It is worth fixing now because
the failure is **silent and remote**: it surfaces two seams away from its cause, as "the new game
doesn't work", long after this code was last read.

**Proposed fix.** Keep the narrowing — turn order genuinely is game-specific — but make the unknown
case **loud instead of wrong**: raise rather than return the sentinel that means something else. A
game that reaches here without a turn rule is a programming error at the one place that must be
updated, not a match that has quietly ended.

**Not a seam change.** Promoting `current_player` onto `GameInterface` is the fuller fix and would be
the right call when a second game actually arrives — but it changes a pinned contract (§4.1 declares
exactly four methods) and would need `architecture.md` and the contract test moved with it. That is
larger than "fix now", so it is finding #3's deferred home rather than something to slip in here.

### 2. 🟠 MEDIUM — the seat race is named in the design but not handled in the code

**Anchor:** [server/repository.py](../../server/repository.py) — `assign_symbol`

**Failure scenario.** `assign_symbol` reads the taken symbols, then writes:

```python
taken = await self._taken_symbols(match_id)
...
participant.symbol = symbol
await self._session.commit()
```

Two connections joining the same empty match interleave between the read and the commit: both see
`taken == set()`, both pick `X`, and the second `commit()` raises `IntegrityError` from
`UNIQUE(match_id, symbol)`.

The constraint does its job — no double seat is ever persisted, which is why it exists. But the
Repository lets the exception escape. §5.2 describes the constraint as the thing that *"guards
against a race assigning the same symbol twice"*, and the code's own comment calls it "the backstop"
— yet nothing catches it, so the loser of the race gets an unhandled exception rather than the
`None` that every other no-seat path returns. In v01.03 that is a 500 on `POST /lobby/join`; in
v01.04 it kills a WebSocket connection during `connect`.

Two clients joining a fresh match simultaneously is the *normal* case for the agent-vs-agent demo —
`scripts/run_arena.sh` launches two agents at once, and §12 already notes the ordering hazard there.

**Proposed fix.** Catch `IntegrityError` around the seat write, roll back, re-read the participant,
and return whatever seat it actually holds — or `None` if the match filled while we were losing the
race. That makes the constraint behave as the design says it does: the backstop that turns a race
into a correct answer rather than an error.

### 3. 🟡 LOW — `reconstruct_game` ignores `matches.game_type`

**Anchor:** [server/repository.py](../../server/repository.py) — `reconstruct_game`

The column is written on `create_match` and then never read; replay always builds a `TicTacToe`.
Together with finding #1, adding a game means editing two places that currently name TicTacToe
implicitly.

Not fixed now because a game registry with only one game in it is speculative structure, and §14
puts more games out of MVP scope. Recorded so that whoever adds the second game finds both sites.

**Home:** out of MVP scope (§14). The natural fix — a small `game_type → GameInterface` factory, plus
promoting the turn rule onto the seam — belongs with that work.

### 4. 🟡 LOW — every Repository method commits

**Anchor:** [server/repository.py](../../server/repository.py) — throughout

`create_match`, `add_participant`, `log_move`, `log_chat`, `assign_symbol` and `release_seat` each
end in `await self._session.commit()`. Convenient here, but it means no caller can group two writes
into one transaction.

v01.04's move-authority flow (§5.4) wants exactly that: persist the move **and** mark the match
finished with its result as one unit. As written, a crash between the two leaves a won game recorded
as still active — recoverable, since replay derives the result from the moves anyway, but the
`matches.status`/`result` columns would disagree with the log.

**Home:** v01.04, which is the first caller that needs the grouping. `session_scope()` (finding #5)
is already the seam for it.

### 5. 🟡 LOW — `session_scope()` is unused

**Anchor:** [server/database.py](../../server/database.py) — `session_scope`

Written, tested only indirectly, and called by nothing — the first real caller is v01.03's request
handling. Harmless, but it is unexercised code shipping ahead of its use.

**Home:** v01.03. If that phase does not adopt it, it should be deleted rather than left.

## What's solid

- **The PRAGMA is verified, not assumed.** `foreign_keys` is asserted to read back as `1`, *and* to
  stay on across repeated connections — the per-connection semantics are the trap, and the test
  covers it. The three FK-rejection tests then double as a live check that it is still in force.
- **The seat constraint is tested from three sides**, only one of which is obvious: duplicate symbol
  within a match rejected, same symbol in another match allowed, many `NULL` symbols coexisting. Had
  the third been wrong, a second spectator could never have been inserted — a bug that would have
  surfaced as "observing is broken" in v03.03.
- **The identity rule is pinned through the signature.** `assign_symbol(match_id, token)` takes no
  name, so keying a seat by display name is not expressible without changing the seam and its
  contract test together. That is a stronger guarantee than a test asserting behaviour.
- **Durability is proven with a second engine over the same file**, for both an in-progress and a
  finished match — the only construction that can tell durable state from a live object. The fixtures
  use a temp file rather than `:memory:` specifically to make this expressible.
- **Replay is ordered explicitly** (`order_by(Move.id)`), not left to incidental row order.
- **A corrupt move row degrades one move, not the replay**, because `apply_move` never raises — the
  v01.01 seam rule paying off in a caller that was written two phases later.
- **The reconciliation worked as intended.** `current_turn` needed no parity arithmetic and no
  terminal special case, because v01.01's review fix had already put the `None`-once-over rule in one
  place.
