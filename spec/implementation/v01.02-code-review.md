## Findings

### 1. 🟠 MEDIUM — `current_turn()` can disagree with `reconstruct_game()`'s own state

**File:** `server/repository.py` (`Repository.current_turn`, `Repository.log_move`)

**Failure scenario:** `log_move` performs **no validation** — it is a raw insert of whatever
`(match_id, symbol, move)` the caller passes. `reconstruct_game()` replays each stored move through
`TicTacToe.apply_move`, which silently **skips** (returns `False`, does not raise, does not advance
internal state for) any move that fails legality — exactly as `GameInterface` §4.1 requires. But
`current_turn()` computed its parity from `len(await self._ordered_moves(match_id))` — the **raw
row count** — not from how many of those moves the replayed game actually accepted. Demonstrated:

```
log_move("m1", "X", 0)    # legal
log_move("m1", "O", 99)   # illegal -- out of range, but log_move stores it anyway
reconstruct_game("m1")  -> board has one X at cell 0; TicTacToe's own internal state says it's O's turn
current_turn("m1")      -> "X"   (2 raw rows, 2 % 2 == 0)   <-- WRONG, contradicts the game it just replayed
```

Today this isn't reachable through the intended call path — v01.04's move-authority flow (§5.4)
only calls `log_move` *after* `apply_move` already returned `True` — but `Repository` is the last
line before persistence and `log_move` has no defense of its own. A future caller, or a bug in the
not-yet-built v01.04 handler, could log an unvalidated move and silently corrupt whose-turn state
with no error raised anywhere. Given `CLAUDE.md`'s non-negotiable that authority checks are never
trusted implicitly, `current_turn` re-deriving its answer from a *different* source of truth than
`reconstruct_game` (raw rows vs. replayed board) is a real gap, not a hypothetical one.

**Proposed fix:** derive `current_turn`'s move count from the **reconstructed game's own board**
(`game.get_state()["board"]`, counting non-`None` cells) instead of a second, independent query
against the raw `moves` table. This makes the two methods structurally unable to disagree — there
is only one source of truth (the replayed game), not two.

## Fixes applied

### Fix for Finding 1

**Change:** `Repository.current_turn()` now counts filled cells on the board returned by
`reconstruct_game()` instead of re-querying `moves` independently.

**Regression test:** `tests/test_reconstruct_game.py::test_current_turn_matches_reconstructed_board_even_with_an_invalid_logged_move`
— logs one legal move followed by one move `log_move` accepts but `apply_move` rejects on replay,
and asserts `current_turn()` agrees with the replayed game's own state rather than the raw row
count.

**Verification:** full suite green (47/47 after the new test), `mypy --strict games server tests`
clean.

**Architecture impact:** none — `Repository.current_turn`'s public signature and return contract
(`"X" | "O" | None`) are unchanged; only its internal derivation changed. No update to
`spec/architecture.md` needed.
