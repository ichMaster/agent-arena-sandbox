## Findings

### #1 🟠 Observer chat not server-refused (MEDIUM) — fixed
**Scenario:** a forced WS `chat` frame from a seatless (`spectator:true`) connection is currently
**accepted** by `_handle_action` — it's logged and broadcast labeled `sender="observer"`. The shipped
Web UI never sends this (chat input is disabled for an Observer, `setChatEnabled(mySymbol !== null)`),
but any other WS client (a script, curl, a modified page) can post chat into a match it's only
supposed to watch — the client-side suppression is the *only* guard, which is exactly the failure mode
web_ui_spec §5 calls out for `submit_move` ("the UI must not depend on that as its only guard") and,
by the same logic, should hold for chat too, per game_spec §3.3's explicit "in the MVP, only players
post chat; observers watch … read-only." This was flagged (not silently fixed) during this version's
`reconcile-issues` pass, since the issues file's own citation for "observers cannot chat" turned out to
be stale (no such v01.04 fix exists).
**Fix applied (`cf1f759`):** `_handle_action`'s `chat` branch now refuses a seatless connection with
`error_event("observers cannot chat")` (mirroring the existing `"no seat"` refusal shape for
`submit_move`) and returns without logging or broadcasting. **Regression test:**
`tests/test_ws_chat.py::test_observer_chat_is_refused` — a spectator's `chat` frame gets back
`{"event": "error", "payload": {"detail": "observers cannot chat"}}` and the `chat_messages` table
stays empty. **Verification:** 203 passed (202 → 203), `mypy --strict` clean (19 source files).

## What's solid
`renderChat`/`renderSystem` build DOM nodes and set `.textContent` only — no `innerHTML` anywhere in
the new code, so chat content can't inject markup. `chat_message.sender` is derived server-side from
the connection's actual assigned symbol (`_handle_action`'s existing `sender = symbol if symbol is not
None else "observer"`), never trusted from the client payload — no spoofing. The chat form never
renders optimistically (only the server's echo renders a bubble), consistent with the board's
no-optimistic-update discipline from v03.02. `renderPlayers`'s Observer branch is a pure presentation
change with no server dependency, and correctly avoids `null.toLowerCase()` (the `sym` iterated is
always the literal `'X'`/`'O'`, never `mySymbol`).

## Architecture impact
**Behavioral, not a wire-shape change:** the `chat` action's server-side authorization now matches
`submit_move`'s pattern (seatless → `error`, not silently accepted) — no new event/action, no schema
change, so `spec/architecture.md` §6.2's action table is unaffected (it already documents `chat` as
requiring a seat implicitly via "players... chat"; this fix makes the server enforce what the doc
already implied). No contract test update needed beyond the new regression test above.
