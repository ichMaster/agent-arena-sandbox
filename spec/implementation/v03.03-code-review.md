## Finding 1 — a genuine spec disagreement, not a bug

roadmap §v03.03 describes the observer view as *"chat visible, no posting"*. The server
built in v01.04 (ARENA-017) **permits** observer chat, on the reasoning recorded there:
chat is non-authoritative flavour under §6.2, and an arena whose audience cannot react is
missing the point. The UI currently leaves the chat input enabled for everyone, so it
follows the server.

Both positions are defensible and the code is self-consistent — but the roadmap and the
implementation say different things, and that is worth surfacing rather than silently
picking one. It needs a product decision, not a patch: suppressing posting client-side
while the server still accepts it would be the worst of both, since a spectator could
still post with a raw socket.

**Deferred to v05.03** with both options recorded. This is the only spec-vs-code
disagreement found in the whole run.

## What is solid
- **Chat is inserted as text, never HTML** — asserted by forbidding `innerHTML` anywhere
  in `app.js`. Chat is attacker-controlled and reaches every socket in the room.
- **Observe is a distinct action** and Host/Join are asserted non-spectator.
- **The gate runs against the real server**: the observer holds no seat, sees the board and
  chat live, and a forced `submit_move` is refused server-side — the client being
  read-only is a courtesy, the refusal is the guarantee.

## Fixes applied
None — the one finding needs a decision, not code.
