## What was checked

- **Every README command against real code:** venv setup (`python3 -m venv .venv`,
  `pip install -e ".[dev]"`), `uvicorn server.main:app`, the three run modes' exact commands
  (`agent/agent.py`'s real `argparse` flags: `--match-id`, `--profile`, `--server-url`,
  `--player-name`; `scripts/run_arena.sh`'s real `SERVER_URL` env var and positional profile-path
  args), `pytest` / `mypy games server agent`. All match.
- **REST/WS surface documented vs. real:** `POST /api/v1/lobby/join`, `POST /api/v1/lobby/match`,
  `GET /api/v1/health`, `GET /ws/match/{match_id}?token=` (`server/main.py:72,77,84,97`), and the
  five server->client events (`joined`, `state_update`, `chat_message`, `game_over`, `error`) plus
  the two client->server actions (`submit_move`, `chat`) (`server/main.py:128-200`,
  `server/websockets.py:29-51`). All match, byte-for-byte on the names.
- **Secrets claim:** README states `ANTHROPIC_API_KEY` lives only in `.env`, is gitignored, and is
  never sent to/logged by server or UI. Confirmed: `.env`/`.envrc` are in `.gitignore`; only
  `agent/` reads the key; `server/` and `web/` have no reference to it.
- **`arena.db` gitignored claim:** confirmed via `*.db` in `.gitignore`.
- **`tests/test_ui_shell.py`'s two new regexes** (`test_styles_css_matches_every_prototype_design_token`,
  `test_every_dom_id_app_js_looks_up_exists_in_index_html`): checked for false-negative risk --
  every `getElementById(...)` call in `web/app.js` uses a plain string literal (no template
  interpolation), so the id-existence regex has no blind spot; the CSS custom-property regex
  (`--[a-z0-9-]+:`) matched a non-empty set on both files, so the `assert prototype_tokens` sanity
  check is doing real work, not passing vacuously.
- **`tests/test_readme.py`:** each assertion is a plain substring check against README's own text
  (no regex, no dynamic path construction) -- correctly scoped as a content-drift guard, not a
  behavioral test (the file's own docstring says as much).
