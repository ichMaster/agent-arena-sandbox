## Findings

### #1 🔴 `uvicorn` missing from declared dependencies (HIGH) — the DoD's literal first step fails
**Scenario:** a newcomer follows the README exactly: clones the repo, `python3 -m venv .venv`,
`pip install -e ".[dev]"`, then `uvicorn server.main:app` — the *first* run command in the whole
document, the one every one of the three modes depends on. `pyproject.toml`'s `dependencies` list has
`fastapi>=0.110` but **no `uvicorn`** entry, and plain `fastapi` does not pull it in transitively (it's
a separate ASGI server, not a fastapi dependency in any version). On a truly clean checkout this
command fails with `command not found` / `ModuleNotFoundError`. It only *appears* to work in this
session because `.venv` already has `uvicorn` installed from earlier ad-hoc work this run — exactly
the kind of drift a real "clean checkout" DoD check exists to catch, and exactly what a review must
verify against the manifest, not the live environment.
**Fix applied (`cf8b306`):** added `uvicorn>=0.30` to `pyproject.toml`'s `[project.dependencies]`.
**Regression test:** `tests/test_readme.py::test_uvicorn_is_a_declared_dependency` parses
`pyproject.toml` (via `tomllib`) and asserts an entry starting with `uvicorn` is present in
`[project].dependencies` — so this can't silently drift back out. **Verification:** 226 passed
(225 → 226), `mypy --strict` clean (19 source files).
