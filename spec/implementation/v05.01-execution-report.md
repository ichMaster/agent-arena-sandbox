## Highlights

- **Reconciliation found a real, in-scope gap**, not just a verification task: this version's own DoD
  ("a malformed message is rejected without killing the socket") was **not actually implemented** —
  sending non-JSON text over the WS raised an uncaught `json.JSONDecodeError` that crashed the
  connection. Verified empirically before writing the fix.
- **Fix:** `_ws_connection`'s receive loop now parses JSON manually (`receive_text` + `json.loads`),
  catching decode errors and non-dict payloads to send the existing `error_event("malformed message")`
  and `continue` — no new wire shape, reuses the shipped `error` event.
- **Tests:** `tests/test_reconnect.py` — same-token reconnect reclaims its seat after a drop; the
  two-seat invariant holds with no leak across a drop → reconnect → third-participant-joins sequence;
  malformed JSON (both bad syntax and valid-but-non-object JSON) yields a graceful error and leaves
  the connection usable afterward.
- **Also confirmed already-shipped** (no new code needed): seat release + shielded `finally` cleanup,
  broadcast pruning a dead socket, bad-token `4001` close, and the `choose_move` model-error fallback —
  all landed in v01.04/v02.03, not a later HARDEN patch (the issues file's original "v02.03.01 HARDEN"
  citations were stale; no such tag exists on this branch).

## DoD (roadmap §v05.01)

> A player disconnecting mid-game frees their seat for a reconnect; a malformed message is rejected
> without killing the socket; a dead socket doesn't block broadcasts; the server never leaks a seat on
> any disconnect path.

**Met — now genuinely, not just by inherited assumption.** Every clause is covered by a passing,
deterministic test: reconnect-reclaim (`test_reconnect.py`), malformed-message resilience (this
issue's fix + tests), dead-socket broadcast pruning (`test_ws_protocol.py`, pre-existing), and no seat
leak (`test_drop_then_reconnect_leaves_both_seats_usable`).
