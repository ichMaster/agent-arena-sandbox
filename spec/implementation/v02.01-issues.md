# v02.01 — GitHub Issues

Issues for phase **v02.01 — `LLMClient` seam & the Anthropic Haiku client** (version **v02 — Agent
Client (Haiku)**), derived from [roadmap.md](../roadmap.md) §v02.01 and
[architecture.md](../architecture.md) (§4.2 the `LLMClient` seam, §7.1–§7.3 agent architecture and
structured output, §9 secrets, §11 testing). IDs continue from ARENA-017 → **ARENA-018…021**.

This phase opens the second of the three stable seams: **`LLMClient`**, the only way the agent talks
to a model vendor. Anthropic Haiku is the sole implementation, but the seam is vendor-agnostic by
design — `agent/agent.py` never imports a concrete client, and swapping vendors is a config change,
not a code change. Structured output is forced **at the client**, so the caller never parses raw
text.

**The LLM is mocked in every test, forever.** No test, validation run, or CI job may spend model
quota. The `ANTHROPIC_API_KEY` lives only in the agent process and is never sent to or logged by the
server or UI (§9).

## v02.01 — `LLMClient` seam & the Anthropic Haiku client

### ARENA-018 — `AgentResponse` — the structured turn reply

**Description:**
`agent/schemas.py` — the Pydantic model the agent returns **once per turn**
([architecture.md](../architecture.md) §7.3). Touches `agent/` only; imports nothing from `server/`.

**What needs to be done:**
- `class AgentResponse(BaseModel)`: `move: int`, `comment: str`.
- `move` is the opaque payload the server re-validates (§4.1) — it is **not** trusted here.
- `comment` is the taunt, broadcast as chat; bound its length so a model cannot emit unbounded text.
- Contract test pinning the two fields per §7.3.

**Dependencies:** None

**Expected result:** one validated object per turn; the caller never parses raw text.

**Acceptance criteria:**
- [ ] Both fields present and required; a response missing either fails validation.
- [ ] A non-integer `move` fails validation rather than being coerced silently.
- [ ] An overlong `comment` is rejected — the model's output is untrusted input.
- [ ] **Contract test:** the `AgentResponse` shape is pinned per §7.3.
- [ ] **Unit test:** validation cases. **No model call.**
- [ ] `mypy games server agent` clean; `pytest` green.

### ARENA-019 — `LLMClient` — the vendor seam

**Description:**
`agent/llm.py` — the abstract base class that is **the only way the agent talks to a model**
([architecture.md](../architecture.md) §4.2). Generic over a `BaseModel` schema. **This is a seam
issue**: it carries its `spec/architecture.md` pin and its contract test in the same commit.

**What needs to be done:**
- `T = TypeVar("T", bound=BaseModel)`; `class LLMClient(ABC)` with
  `async def generate_structured_response(self, prompt: str, schema: type[T]) -> T`.
- Document the two seam rules: structured output is **forced at the client**, and the caller never
  parses raw text; and the seam is **vendor-agnostic** — a second vendor is a new subclass, not a
  branch inside this one.
- Contract test pinning the method name, signature and return relationship.

**Dependencies:** ARENA-018

**Expected result:** a typed seam an agent can depend on without knowing any vendor.

**Acceptance criteria:**
- [ ] `LLMClient` cannot be instantiated; a subclass missing the method cannot either.
- [ ] The return type is tied to the `schema` argument, so a caller gets back the type it asked for
      (verified under `mypy --strict`, not just at runtime).
- [ ] **Contract test:** the seam is pinned per §4.2 — method name, parameters, and genericity.
- [ ] **Unit test:** an in-test stub subclass implements it and returns a validated model. **No model
      call.**
- [ ] `mypy games server agent` clean; `pytest` green.

### ARENA-020 — `AnthropicHaikuClient` — forced structured output

**Description:**
The **only** concrete `LLMClient`, over the official `anthropic` SDK
([architecture.md](../architecture.md) §4.2, §7.3). Touches `agent/` and `pyproject.toml`.

**What needs to be done:**
- `AnthropicHaikuClient(LLMClient)` using `AsyncAnthropic`, calling `messages.parse(...)` with
  `output_format=schema` so the SDK validates the reply into the schema — **structured output is
  forced at the client**, and no raw-text parsing exists anywhere in the agent.
- **A single model-id constant.** Use `claude-haiku-4-5` — confirmed against the live Anthropic model
  list rather than guessed, as the roadmap requires. Do not append a date suffix.
- `temperature` and `max_tokens` configurable; sensible defaults for a one-move reply.
- Declare `anthropic` as a runtime dependency.
- Map SDK failures to a clear error the agent can retry against.

**Dependencies:** ARENA-019

**Expected result:** a client that returns a validated `AgentResponse` from a mocked SDK, with no
raw-text parsing anywhere.

**Acceptance criteria:**
- [ ] Returns a validated `AgentResponse` from a **mocked** Anthropic client — **the SDK is patched;
      no paid call is made.**
- [ ] The model id is a **single constant** equal to `claude-haiku-4-5`, asserted by a test so a
      future edit cannot silently change the model or reintroduce a date suffix.
- [ ] Malformed model output surfaces as a **validation error**, not a crash or a silently wrong
      move.
- [ ] `temperature` and `max_tokens` are passed through to the SDK (asserted on the mock's call).
- [ ] **No raw-text parsing** — asserted structurally, so nobody can reintroduce `json.loads` on a
      model reply.
- [ ] **Unit test:** the above, all mocked. **Zero paid calls.**
- [ ] `mypy games server agent` clean; `pytest` green.

### ARENA-021 — `create_llm_client` dispatch & fail-fast key handling

**Description:**
Config-driven vendor selection plus startup key validation
([architecture.md](../architecture.md) §4.2, §9). Touches `agent/` only. Closes the phase DoD.

**What needs to be done:**
- `create_llm_client(model_type: str, api_key: str, temperature: float) -> LLMClient` — dispatch
  keyed off `AgentProfile.model_type` (v02.02).
- An unknown `model_type` fails with a clear, listing error rather than a default that silently picks
  a vendor.
- **Fail-fast key handling:** a missing/blank `ANTHROPIC_API_KEY` aborts startup with a clear
  message. The key lives **only** in the agent process.
- The key must never appear in an exception message, `repr`, or log line.

**Dependencies:** ARENA-020

**Expected result:** `create_llm_client("haiku", …)` returns a working client; a missing key aborts
before any network call.

**Acceptance criteria:**
- [ ] `create_llm_client("haiku", …)` returns an `AnthropicHaikuClient`.
- [ ] An unknown `model_type` raises an error **naming the supported values** — never a silent
      default.
- [ ] **A missing or blank key aborts with a clear message**, before any client is constructed.
- [ ] **The key never appears in an error message, `repr`, or log** — asserted, since §9 makes this
      non-negotiable and a leaked key in a traceback is the likeliest way it escapes.
- [ ] **`agent/` imports nothing from `server/`** — asserted structurally; the agent is a true
      external client (§2).
- [ ] **Unit test:** dispatch and key handling. **No model call.**
- [ ] `mypy games server agent` clean; `pytest` green.

## v02.01 scope notes

**Total effort:** ~7–11 days across 4 issues (S, M, M, S).
**Critical path:** ARENA-018 → ARENA-019 → ARENA-020 → ARENA-021.
**Phase DoD (roadmap §v02.01):** `create_llm_client("haiku", …)` returns a client whose
`generate_structured_response` yields a validated `AgentResponse`; the agent code references only the
seam; a missing API key aborts startup with a clear message.
**Contracts pinned this phase:** `LLMClient` (§4.2) and `AgentResponse` (§7.3).

**Model note — the one thing this phase must not guess.** The roadmap explicitly says to *"confirm
[the model id] against the live model list rather than hardcoding a guess."* The id is
**`claude-haiku-4-5`**, confirmed against the current Anthropic model catalogue: active, 200K
context, and — importantly for this phase — it **supports structured outputs**, which is what makes
`messages.parse(output_format=…)` the right mechanism rather than prompt-and-parse. No date suffix:
`claude-haiku-4-5-20251001` is the full id, but the alias is what belongs in code.

**Reconciliation note (Step 0.5).** No agent code exists yet — this is the first `agent/` module
beyond the package marker created in ARENA-001. Read against the real v01 code:

- **`games/` is importable and pure** — the agent may use it for local move validation in v02.03, and
  importing it breaks no boundary. `server/` remains off-limits.
- The server re-validates every move regardless (§5.4, and `handle_submit_move` reads the seat from
  the token), so a hallucinated move from the model is refused server-side even if the agent's own
  validation were wrong. That is why `AgentResponse.move` is `int` and not further constrained here:
  the authority is the server's, not the schema's.
- **`current_turn` is `null` on the game-ending move**, so the agent's event loop (v02.03) can use it
  to know when to stop acting rather than needing a separate signal.

**No paid APIs — ever.** Every test in this phase and every phase after it mocks the `LLMClient` or
the Anthropic SDK. A test that would spend quota is a bug, not a trade-off.
