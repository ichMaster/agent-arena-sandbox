# v02.01 — GitHub Issues

Issues for phase **v02.01 — `LLMClient` seam & the Anthropic Haiku client** (version **v02 —
Agent Client (Haiku)**), derived from the per-phase Tasks in [roadmap.md](../roadmap.md)
(§v02.01) and the contracts in [architecture.md](../architecture.md) (§4.2 `LLMClient`, §7.3

This file is scoped to a single phase; IDs continue from the previous phase
(ARENA-086 → **ARENA-087…089**).

This phase opens version v02 and establishes the **second of the three stable seams**:
`LLMClient` — the only way the agent talks to a model vendor, kept vendor-agnostic so Haiku is
the first implementation, not the only one the seam can ever support. Depends on v01.01 only
(the schema-type conventions the agent's Pydantic models follow) — nothing else in v01 is
needed, since the agent talks to the server purely over HTTP/WS, not by importing it.

## v02.01 — `LLMClient` seam & the Anthropic Haiku client

### ARENA-087 — `agent/schemas.py` — `AgentResponse`, agent package skeleton

**Description:**
Stand up the `agent/` package and its structured-output schema, per architecture.md §7.3:
`AgentResponse{move: int, comment: str}` — the single response an agent gives per turn, later
validated against `valid_moves` by the caller (not this schema's job). Touches: `agent/__init__.py`,
`agent/schemas.py`, `pyproject.toml`.

**What needs to be done:**
- `agent/__init__.py` (empty).
- `agent/schemas.py`: `class AgentResponse(BaseModel): move: int; comment: str`.
- `[tool.setuptools] packages` gains `"agent"`.
- No LLM/vendor code here — this issue is the response shape only.

**Dependencies:** ARENA-071

**Expected result:**
`AgentResponse` validates a `{"move": int, "comment": str}` payload and rejects a malformed one.

**Acceptance criteria:**
- [ ] `AgentResponse.model_validate({"move": 4, "comment": "taking the center"})` succeeds.
- [ ] A non-int `move` or missing field fails validation (Pydantic's own `ValidationError`).
- [ ] `mypy --strict agent` passes.

### ARENA-088 — `agent/llm.py` — the `LLMClient` abstract seam + `create_llm_client` dispatch

**Description:**
Define the **`LLMClient`** abstract seam per architecture.md §4.2 — the only way `agent/agent.py`
(landing in v02.03) will ever talk to a model — and `create_llm_client`, the config-driven
dispatch that keeps agent logic free of any concrete vendor SDK. This is the **first pin** of the
seam; the doc already specifies it exactly, so only the contract test is new here, not an
`architecture.md` edit. Touches: `agent/llm.py`, `tests/`.

**What needs to be done:**
- `agent/llm.py`: `T = TypeVar("T", bound=BaseModel)`; `class LLMClient(ABC): @abstractmethod
  async def generate_structured_response(self, prompt: str, schema: type[T]) -> T: ...`.
- `def create_llm_client(model_type: str, api_key: str, temperature: float) -> LLMClient:` —
  dispatches on `model_type` (`"haiku"` → `AnthropicHaikuClient`, landing in ARENA-089; an
  unknown `model_type` raises a clear `ValueError`).
- No concrete client here — `AnthropicHaikuClient` lands in ARENA-089. `create_llm_client`'s
  `"haiku"` branch can be written now even though its target class doesn't exist yet, as long as
  the import is structured so this issue's own tests don't need it (import inside the dispatch
  function, or accept this issue temporarily stubs the "haiku" branch and ARENA-089 completes it
  — the implementer's call, documented in the commit).

**Dependencies:** ARENA-087

**Expected result:**
`LLMClient` cannot be instantiated directly; `create_llm_client` dispatches correctly and raises
clearly on an unknown `model_type`.

**Acceptance criteria:**
- [ ] `LLMClient` is abstract (cannot be instantiated).
- [ ] **Contract test:** `generate_structured_response`'s signature (`prompt: str, schema:
      type[T]`) is pinned here — must change in the same commit as any future seam change.
- [ ] `create_llm_client` with an unrecognized `model_type` raises `ValueError` with a clear
      message.
- [ ] `mypy --strict agent` passes.

### ARENA-089 — `agent/llm.py` — `AnthropicHaikuClient`, fail-fast API key handling

**Description:**
The only concrete `LLMClient` implementation for the MVP: `AnthropicHaikuClient`, backed by the
Anthropic SDK, forcing structured output (tool-use / JSON schema) rather than parsing raw text.
`ANTHROPIC_API_KEY` is required at startup with a clear failure if missing — the secret lives only
in this process (architecture.md §9). Touches: `agent/llm.py`, `pyproject.toml`.

**What needs to be done:**
- Add the `anthropic` SDK as a runtime dependency.
- `class AnthropicHaikuClient(LLMClient)`: constructed with an API key + temperature; the model
  id is a single named constant near the top of the module (e.g. `HAIKU_MODEL_ID =
  "claude-haiku-4-5"` — confirm against the live model list rather than hardcoding a guess; leave
  a comment noting where to check if this ever needs updating).
- `generate_structured_response(prompt, schema)`: calls the Anthropic SDK with tool-use (or
  equivalent structured-output forcing) keyed to `schema`'s JSON schema, parses the tool-call
  arguments into `schema`, and returns it. **Never** returns unparsed text; a malformed/unparsable
  response surfaces as a `pydantic.ValidationError` (or is deliberately caught and re-raised as
  one), not swallowed.
- `create_llm_client("haiku", api_key, temperature)` returns a working `AnthropicHaikuClient`
  (completing ARENA-088's dispatch).
- Fail-fast: if `api_key` is falsy, raise a clear, actionable exception before any network call —
  never at the point of the first API call deep in a match.

**Dependencies:** ARENA-088

**Expected result:**
`create_llm_client("haiku", key, temp).generate_structured_response(prompt, AgentResponse)`
returns a validated `AgentResponse` when the (mocked) SDK responds correctly, and raises a
validation error when it doesn't.

**Acceptance criteria:**
- [ ] `create_llm_client("haiku", …)` returns an `AnthropicHaikuClient` whose
      `generate_structured_response` yields a validated instance of the passed schema, against a
      **mocked** Anthropic SDK client (the unit test makes no network call and costs nothing).
- [ ] Malformed/unparsable structured output from the (mocked) SDK surfaces as a validation
      error, not a silent `None` or a raw-text fallback.
- [ ] A missing/empty API key aborts client construction immediately with a clear message — no
      SDK call attempted.
- [ ] `mypy --strict agent` passes; full suite green.
