## v02.01 — `LLMClient` seam & the Anthropic Haiku client

### ARENA-052 — `AgentResponse` — the structured turn reply

**Description:**
`agent/schemas.py`: `AgentResponse` — the one structured reply the agent gets from the model each
turn, per architecture.md §7.3. Touches: `agent/`.

**What needs to be done:**
- `class AgentResponse(BaseModel): move: int; comment: str` exactly per §7.3 — `move` stays opaque
  to this layer (validated against `valid_moves` client-side in v02.03, then server-side always);
  `comment` is the taunt/banter, broadcast as chat once v02.03 wires the event loop.

**Dependencies:** None

**Expected result:**
A Pydantic model that validates a `{move, comment}` payload and rejects a malformed one.

**Acceptance criteria:**
- [ ] **Unit test:** valid `{move: int, comment: str}` parses; a missing field or wrong type raises `ValidationError`.
- [ ] **Contract test:** field names/types (`move: int`, `comment: str`) match architecture.md §7.3.
- [ ] `mypy agent` strict-clean.

### ARENA-053 — `LLMClient` seam & `create_llm_client` dispatch

**Description:**
`agent/llm.py`: the abstract **`LLMClient`** seam (architecture.md §4.2) — generic over a
`BaseModel` schema, one method `generate_structured_response(prompt, schema) -> schema` — plus
`create_llm_client(model_type, api_key, temperature) -> LLMClient`, the config-driven dispatch that
keeps `agent/agent.py` free of any vendor SDK import. Also lands the fail-fast `ANTHROPIC_API_KEY`
check (roadmap §v02.01) here, since it's the natural point where a vendor client would otherwise be
constructed with a missing secret. Touches: `agent/`.

**What needs to be done:**
- `T = TypeVar("T", bound=BaseModel)`; `class LLMClient(ABC): async def
  generate_structured_response(self, prompt: str, schema: type[T]) -> T: ...` — abstract, per §4.2
  exactly.
- `create_llm_client(model_type: str, api_key: str, temperature: float) -> LLMClient`: for
  `model_type == "haiku"`, requires `api_key` truthy — raise a clear, actionable `RuntimeError`
  (e.g. `"ANTHROPIC_API_KEY is required to run a live agent"`) if empty/`None`, **before**
  constructing anything; unknown `model_type` raises `ValueError`. The concrete Haiku client class
  itself is ARENA-054 — this issue defines the dispatch function's contract and error paths; it can
  reference the class by name/forward-declare and ARENA-054 completes the wiring in the same file.

**Dependencies:** ARENA-052

**Expected result:**
`create_llm_client("haiku", api_key="", temperature=0.7)` fails fast with a clear message before any
network/SDK object is created; `LLMClient` is a proper `ABC` that cannot be instantiated directly.

**Acceptance criteria:**
- [ ] **Unit test:** `create_llm_client("haiku", api_key="", ...)` raises with a clear, actionable message (no key configured never silently proceeds).
- [ ] **Unit test:** `create_llm_client("bogus-vendor", ...)` raises `ValueError`.
- [ ] **Contract test:** `LLMClient.generate_structured_response`'s signature (generic over `T`, `prompt: str`, `schema: type[T]`, returns `T`) matches architecture.md §4.2.
- [ ] `mypy agent` strict-clean.

### ARENA-054 — `AnthropicHaikuClient` — forced structured output

**Description:**
Complete `agent/llm.py` with `AnthropicHaikuClient(LLMClient)` — the only vendor implementation —
using the Anthropic SDK's tool-use mechanism to force structured output matching the requested
Pydantic schema, never leaving the caller to parse raw text (architecture.md §4.2, §7.3). Wires it
into `create_llm_client`'s `"haiku"` branch. The model id is a single named constant,
`claude-haiku-4-5-20251001` (Anthropic's current Haiku 4.5 release — not a placeholder). This closes
the v02.01 DoD. Touches: `agent/`.

**What needs to be done:**
- `_HAIKU_MODEL_ID = "claude-haiku-4-5-20251001"` — one named constant, imported nowhere else as a
  guess.
- `AnthropicHaikuClient(LLMClient)`: holds an `anthropic.AsyncAnthropic(api_key=...)` client and
  `temperature`; `generate_structured_response(prompt, schema)` calls the SDK with a single
  synthetic tool whose input schema is `schema.model_json_schema()`, forces `tool_choice` to that
  tool, and parses the tool-call arguments back into `schema(**args)` — the caller never touches raw
  text.
- `create_llm_client("haiku", api_key, temperature)` returns `AnthropicHaikuClient(api_key,
  temperature)` after the ARENA-053 key check passes.
- Malformed/unparseable model output (a tool-call whose arguments don't validate against `schema`)
  surfaces as a `pydantic.ValidationError`, not a silent `None` or a raw-text fallback.

**Dependencies:** ARENA-053

**Expected result:**
`create_llm_client("haiku", api_key=..., temperature=0.7).generate_structured_response(prompt,
AgentResponse)` returns a validated `AgentResponse` when the (mocked, in tests) SDK returns a
well-formed tool call, and raises a validation error when it doesn't.

**Acceptance criteria:**
- [ ] **Unit test:** with the Anthropic SDK client **mocked** (patched, no network/cost), a
  well-formed tool-call response is parsed into a validated `AgentResponse`.
- [ ] **Unit test:** a malformed tool-call response (missing/wrong-typed field) surfaces as a
  `ValidationError`, not a silent failure.
- [ ] **Unit test:** `create_llm_client("haiku", api_key="valid", ...)` returns an
  `AnthropicHaikuClient` instance (end-to-end dispatch, still with the SDK mocked).
- [ ] `pytest` green and `mypy agent` strict-clean for the whole phase; **no live API call** in the
  default suite.
- [ ] Ties to v02.01 DoD (release gate): `create_llm_client("haiku", …)` returns a client whose
  `generate_structured_response` yields a validated `AgentResponse`; the agent code references only
  the seam; a missing API key aborts startup with a clear message.
