AgentArena -- Release Notes
===========================

Version 03.02.00 (2026-08-03)
---------------------------
Roadmap phase v03.02 -- Board & gameplay (Player role).

- Cells are enabled only when current_turn matches our symbol AND the server
  called that cell legal; the client never invents legality.
- Clicks are guarded against off-turn, finished-game and closed-socket.
- game_over freezes the board and shows the result.
- Player cards show both seats with the active one highlighted, and starting a
  new match in the same tab clears board, banner and chat.

Tests: 443 passing. mypy --strict clean.

Version 03.01.00 (2026-08-03)
---------------------------
Roadmap phase v03.01 -- Static UI shell & connection.

- web/ mounted at /ui with no build step, and Cache-Control: no-store on /ui/*

Tests: 428 passing. mypy --strict clean.

Version 02.03.00 (2026-08-03)
---------------------------
Roadmap phase v02.03 -- Agent event loop & decision play. THE v02 GATE.

- decide_move: ask the model, validate against valid_moves, retry, then play a
  random legal move. The fallback is the point -- a model that keeps naming
  occupied cells would otherwise stall the match forever.
- AgentSession: join over REST, connect over WS, and act only when current_turn
  equals its own symbol. The turn is derived from state, never a separate event,
  which is also what stops the agent acting on the terminal update.
- CLI: --match-id / --profile / --server-url / --player-name, line-buffered
  stdout so a redirected log flushes as the game plays, and a direct-run shim.
- Code review fix: only genuine model failures count as a failed turn; a bug in
  our own code propagates instead of being retried away.

The LLM is mocked in every test -- no paid call is made anywhere.

Tests: 391 passing. mypy --strict clean.

Version 02.02.00 (2026-08-03)
---------------------------
Roadmap phase v02.02 -- Profile, persona, memory & prompt.

- AgentProfile: the Agent Designer's YAML surface, validated at load. model_type
  is checked against what create_llm_client accepts and temperature against its
  range, so a typo fails at startup rather than mid-match.
- MemoryWindow: the last N moves and chat messages, oldest evicted first.

- build_prompt: persona + memory + the pushed board and legal moves, composed

- profiles/aggressive.yml: the first sample persona, loaded by a test.

Version 02.01.00 (2026-08-03)
---------------------------
Roadmap phase v02.01 -- LLMClient seam & the Anthropic Haiku client.

- AgentResponse: one structured reply per turn (move + taunt), bounded. move is
  deliberately unconstrained -- the server is the legality authority, and a
  second weaker one in the agent would invite trusting it.
- LLMClient: the vendor seam, generic over a schema. Structured output is forced
  at the client, so the caller never parses raw text; a second vendor is a new
  subclass, not a branch.
- AnthropicHaikuClient: the only implementation, using messages.parse with
  output_format so the SDK validates the reply into the schema. The model id is
  a single constant, claude-haiku-4-5, confirmed against the live model list.
- create_llm_client: config-driven selection; an unknown model_type names the
  supported values rather than silently defaulting, and a missing key aborts
  before any client is built. The key never appears in a repr or an error.

The LLM is mocked in every test -- no paid call is made anywhere.

Tests: 344 passing. mypy --strict clean.

Version 01.04.00 (2026-08-03)
---------------------------
Roadmap phase v01.04 -- WebSocket protocol & move authority. THE v01 GATE.

- ConnectionManager: per-match sockets, broadcast that serialises once for the
  room and prunes a socket failing mid-send, and close_room. The five server
  events and two client actions of architecture.md 6.2 are pinned by a contract
  test -- including that no your_turn event exists, since the turn is derived.
- Transaction ownership moved to the callers: Repository methods flush, never
  commit, so a request that fails partway leaves nothing behind and a move can
  be written together with the match result.
- The WS endpoint: bad token closes 4001, joined reports the seat, and cleanup
  survives the cancellation a client-initiated drop actually produces -- it runs
  detached on its own session, because a cancelled task cannot await.
- submit_move runs the 5.4 authority flow. The symbol comes from the token, never
  from the message, and the flow READS the seat rather than assigning one.
- chat, game_over and close_room: the result is announced only after the board
  that produced it, and the terminal state_update carries current_turn: null.

Code review fixes: the move flow no longer grants seats, and a deferred seat
release can no longer outrun a reconnect and wipe the seat it just claimed.

Tests: 310 passing. mypy --strict clean.

Version 01.03.00 (2026-08-03)
---------------------------
Roadmap phase v01.03 -- Match, seats & lobby REST.

- Opaque join tokens (server/auth.py): the token IS the participant id and
  carries no player-supplied text, so a display name cannot be recovered from
  an identity handed to clients. validate_token answers None rather than
  raising, so a bad token becomes a 4001 close at WS connect.
- Lobby schemas (server/schemas.py): spectator defaults to False, and unknown
  fields are refused rather than ignored -- a typo'd "spectatr" would otherwise
  have seated someone who asked to observe.
- FastAPI app (server/main.py): a lifespan context calling init_models,
  GET /api/v1/health, POST /api/v1/lobby/match and POST /api/v1/lobby/join,
  which 404s on an unknown match. is_spectator is written onto the participants
  row at join, before any seat exists, so an observer can never be handed one.
- server/match.py: thin seat and turn helpers over the Repository, with no
  long-lived match object and no registry -- enforced by a test that parses the
  module and fails on any module-level container.
- Code review fix: a match view now replays the move log once per call rather
  than twice, on the path v01.04 walks for every connected socket on every move.

Tests: 220 passing. mypy --strict clean.

Version 01.02.00 (2026-08-03)
---------------------------
Roadmap phase v01.02 -- Persistence layer (SQLite).

- Async SQLAlchemy engine over sqlite+aiosqlite with a config-driven URL, an
  async_sessionmaker(expire_on_commit=False), and a connect-time
  PRAGMA foreign_keys=ON -- SQLite disables foreign keys per connection, so
  without it every constraint would be decorative.
- Four tables (matches, participants, moves, chat_messages) with
  UNIQUE(match_id, symbol), making "at most one X and one O" a database
  guarantee rather than an application convention.
- Repository: the single seam for all database access, implementing the
  seat rule of architecture.md 5.2 in order -- observers refused permanently,
  idempotent reconnect, match-full, then the first free symbol. Seats are keyed
  by token, never by display name.
- Move and chat logs, and reconstruct_game: live state is recovered by replaying
  the move log through a fresh TicTacToe, so no serialize step is added to
  GameInterface and the board survives a restart, not just a reconnect.
- current_turn is derived and is None once the game is over, satisfying the
  architecture.md 6.2 rule by construction.
- Code review fixes: a game with no turn rule now raises instead of reporting
  "game over"; the seat race returns "no seat" instead of an IntegrityError.

Tests: 160 passing. mypy --strict clean.

Version 01.01.00 (2026-08-03)
---------------------------
Roadmap phase v01.01 -- Project skeleton & the game engine.

- Project skeleton: pyproject.toml with an explicit setuptools package list
  (games, server, agent), strict mypy, and pytest scoped to tests/.
- GameInterface: the abstract game plug-in seam (get_state, get_valid_moves,
  apply_move, is_game_over), pinned by a contract test (architecture.md 4.1).
  The move payload is opaque to transport; apply_move is the sole legality
  authority and never raises on bad input.
- TicTacToe engine: 9-cell board, X first, current_player derived from move
  parity. apply_move rejects unknown players, non-int moves (bool included,
  since bool subclasses int), out-of-range indices and occupied cells.
- Terminal detection: the eight winning lines, draw, and is_game_over. A
  completed line is checked before fullness, so a board that fills on a
  winning move reports the winner rather than a draw.
- Code review fix: current_player is None once the game is over, so callers
  satisfy the architecture.md 6.2 rule (current_turn is null on the
  game-ending move) by construction.

Tests: 100 passing. mypy --strict clean.
